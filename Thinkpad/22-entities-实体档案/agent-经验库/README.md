### 规则 2:强反问 + 细化(被动 → 主动)

用户给的粗需求,必**主动拆解成 3-5 个子问题**用 `vscode_askQuestions` 追问:

1. 改哪个文件 / 模块?(具体路径)
2. 是新增 / 修改 / 删除 / Bug 修复?
3. 有没有具体复现步骤 / 截图 / 报错堆栈?
4. 是否涉及跨模块联动?
5. 验收标准是什么?(跑通什么命令 / 看到什么效果)

**反模式**:问"你需要什么?"——太开放,用户答不上来。
**正模式**:问"是改 A、B 还是 C?"——给具体选项,降低回答成本。

**禁止**未填完清单就动手。

### 规则 3:查资料 + 验证双步骤

| 步骤           | 工具                                    | 必做 |
| -------------- | --------------------------------------- | ---- |
| 查 API 用法    | `Context7` MCP / `firecrawl-scrape` MCP | ✅   |
| 查项目内用法   | `grep_search` / `read_file`             | ✅   |
| 查项目决策     | 读 wiki(规则 1)                         | ✅   |
| **跑验证**     | typecheck / lint / build                | ✅   |
| **跑业务验证** | 浏览器 MCP / 命令行测试                 | ✅   |

**反模式**:查完 API 文档就信,直接写代码——文档可能过时。
**正模式**:查到用法 → 写最小验证 → 跑通 → 才用到项目里。

## 🚦 经验等级与升降级

| 等级      | 标识 | 含义                                    |
| --------- | ---- | --------------------------------------- |
| 🟢 已验证 | ✅   | 复用计数 ≥ 3 次未出问题                 |
| 🟡 待验证 | 🟡   | 写入未满 3 次复用                       |
| 🔴 已废弃 | ❌   | 已被推翻或用户显式纠正,保留作为反面教材 |

### 自动升降级规则

| 状态变化   | 触发条件                           | 操作                                             |
| ---------- | ---------------------------------- | ------------------------------------------------ |
| 🟡 → 🟢    | 复用计数 ≥ 3                       | agent 自动改 `**状态**: 🟢 已验证`               |
| 🟢 → 🟡    | 出现 1 次该经验没起作用            | agent 自动降级回 🟡 + 写一句"为什么这次没起作用" |
| 🟢/🟡 → 🔴 | 用户显式说"这条经验错了"或自行推翻 | 标记 🔴,但**不删**,留作反面教材                  |

### 复用计数规则

| 计数           | 触发                                   |
| -------------- | -------------------------------------- |
| 写入时         | 默认 `**复用计数**: 0`                 |
| 每次子任务完成 | agent 被纠正时引用了某条经验,该经验 +1 |
| 计数 ≥ 3       | 自动升级 🟢                            |
