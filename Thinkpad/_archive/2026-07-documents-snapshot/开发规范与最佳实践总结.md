# 开发规范与最佳实践总结

> 基于项目核心记忆整理的完整开发规范指南

## 一、需求分析与设计

### 1.1 需求分析流程

**全面分析框架**：
1. **前后端协同分析**
   - 前端：页面组件、交互流程、用户体验
   - 后端：API 设计、领域模型、业务逻辑

2. **影响范围评估**
   - 关联功能影响（上下游依赖）
   - 数据影响（表结构、数据迁移）
   - 用户影响（权限、使用习惯）
   - 性能影响（查询量、并发场景）

3. **延伸场景预判**
   - 未来功能扩展方向
   - 兼容性需求预留
   - 可配置化可能性

4. **边界情况处理**
   - 异常场景（数据异常、网络异常）
   - 并发场景（重复提交、资源竞争）
   - 数据一致性（事务、锁机制）

5. **技术债务预防**
   - 代码复用设计
   - 扩展性架构预留
   - 配置化方案设计

### 1.2 DDD 领域建模

**模块划分原则**：
- **课程域** (wk-module-course): Course-CourseFile-CourseLearn
- **考试域** (wk-module-exam): Exam-Paper-ExamRecord
- **题库域** (yf-module-repo): Repo-Question-Chapter
- **计划域** (yf-module-plan): Training-Plan-Execution
- **用户域** (yf-module-system): User-Role-Department

**限界上下文**：
- 各域之间通过领域事件解耦
- 依赖注入面向接口编程
- 禁止跨域直接调用数据库

## 二、后端开发规范

### 2.1 DDD 分层架构

```
Controller 层 → Application 层 → Domain 层 → Repository 层 → Infrastructure 层
```

**各层职责**：

1. **Controller 层**
   - 只负责 HTTP 请求处理
   - 参数接收与校验
   - DTO 转 Command
   - 调用 Application 层
   - VO 转换返回

2. **Application 层**
   - 流程编排与协调
   - 参数校验（必须）
   - 调用 Domain 层
   - 事务控制 (@Transactional)
   - 发布领域事件

3. **Domain 层**
   - 核心业务逻辑
   - 领域行为与状态管理
   - 业务规则校验
   - 保持纯净（无技术依赖）

4. **Repository 层**
   - Domain ↔ Entity 转换
   - 数据访问接口定义
   - 使用 MyBatis Plus

5. **Infrastructure 层**
   - 基础设施实现
   - 第三方服务集成
   - 数据库实现

### 2.2 对象转换规范

**DTO → Command → Domain → Entity → VO**

```java
// Controller 层：DTO 转 Command
TrainingRoleAddDto dto → toTrainingRoleCommand() → TrainingRoleCommand

// Application 层：Command 转 Domain
TrainingRoleCommand → TrainingRole.create() → TrainingRole

// Domain 层：Domain 转 VO
TrainingRole → TrainingRoleInfoVo.toTrainingRoleInfoVo() → TrainingRoleInfoVo
```

**禁止事项**：
- ❌ 禁止直接返回 Entity/Domain 对象给前端
- ❌ 禁止在 Controller 写业务逻辑
- ❌ 禁止 Domain 层直接操作数据库

### 2.3 API 设计规范

**路径命名**：
```java
@RequestMapping("/api/wk/training/role/management")
```

**方法命名规范**：
- `pageXXX` - 分页查询
- `saveXXX` - 保存（新增/更新）
- `addXXX` - 新增
- `editXXX` - 编辑
- `removeXXX` - 删除
- `infoXXX` - 查询详情

**前后端路径一致**：
```java
// 后端
@RequestMapping("/api/wk/training/role/management")

// 前端
const BASE_URL = '/api/wk/training/role/management'
```

### 2.4 事务控制规范

**注解使用**：
```java
@Transactional(rollbackFor = Exception.class)
```

**最佳实践**：
- ✅ 加在 Application 层实现类上
- ✅ Exception 级别回滚
- ✅ 不捕获运行时异常
- ✅ 批量操作注意事务大小
- ✅ 领域事件在事务提交后发布

### 2.5 日志记录规范

**日志注入**：
```java
@LogInject(title = "保存角色", logType = LogType.TRAINING)
```

**日志类型**：
- `LogType.TRAINING` - 培训相关
- `LogType.EXAM` - 考试相关
- `LogType.SYSTEM` - 系统相关

**记录内容**：
- 操作人、操作时间、操作内容
- IP 地址
- 敏感信息脱敏（密码/手机号/身份证）

### 2.6 权限控制规范

**权限注解**：
```java
@RequiresAuthentication  // 需要登录
@RequiresPermissions("module:action")  // 需要权限
```

**权限粒度**：
1. **菜单权限** - 路由级别控制
2. **按钮权限** - 前端 `v-permission`
3. **接口权限** - 后端 `@RequiresPermissions`
4. **数据权限** - 部门/创建人/角色隔离

**权限标识格式**：`module:action`（如 `ai:sparring:list`）

### 2.7 分页查询规范

**PageQueryDto**：
```java
{
  current: 1,      // 当前页
  size: 10,        // 每页大小
  params: {}       // 查询参数
}
```

**PageResult 返回**：
```java
{
  records: [],     // 数据列表
  total: 100,      // 总数
  size: 10,        // 每页大小
  current: 1       // 当前页
}
```

**MyBatis Plus 分页**：
```java
Page<T> page = new Page<>(current, size);
```

### 2.8 批量操作规范

**前端**：
- 选中多行数据
- 确认对话框
- 批量删除/启用/禁用

**后端**：
```java
// 接收 List<Long> ids
public void batchRemove(List<Long> ids) {
    // 循环调用单个操作
    // 或批量 SQL
}
```

**注意事项**：
- ✅ 事务控制，部分失败全部回滚
- ✅ 返回成功/失败数量统计
- ✅ 大批量考虑分批处理

### 2.9 文件上传规范

**单文件上传**：
```java
@PostMapping("/upload")
public Result<String> upload(@RequestParam("file") MultipartFile file)
```

**大文件上传**：
- 分片上传（chunkSize = 5MB）
- 断点续传
- 生成 UUID 文件名
- 保存 OSS/本地
- 返回 URL

**校验要求**：
- 文件大小限制
- 文件类型校验

### 2.10 枚举类型使用

**Domain 层定义**：
```java
public enum State {
    NOT_PUBLISHED(0),
    PUBLISHED(1);
    
    private final int value;
    
    public int getValue() { return value; }
    public static State getByValue(int value) { ... }
}
```

**使用规范**：
- 前端传递数字（0/1）
- 后端转换为枚举
- Optional 包装避免 null

### 2.11 错误处理规范

**统一响应格式**：
```java
{
  code: 200,       // 成功码
  msg: "success",  // 消息
  data: {}         // 数据
}
```

**业务异常**：
```java
throw new ServiceException(错误码，错误消息);
```

**统一异常处理**：
```java
@RestControllerAdvice
public class GlobalExceptionHandler {
    @ExceptionHandler(ServiceException.class)
    public Result<?> handleServiceException(ServiceException e) { ... }
}
```

### 2.12 时间格式规范

**后端**：
```java
@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")
private LocalDateTime createTime;
```

**前端**：
```javascript
import dayjs from 'dayjs'
dayjs(date).format('YYYY-MM-DD HH:mm:ss')
```

**统一使用 ISO 格式或带时区的 yyyy-MM-dd HH:mm:ss**

## 四、数据库设计规范

### 4.1 表命名规范

**规则**：
- 下划线 + 小写：`training_role`
- 禁止驼峰：❌ `trainingRole`

### 4.2 必备字段

```sql
id BIGINT PRIMARY KEY,           -- 主键
-- 业务字段
create_by BIGINT,                -- 创建人
create_time DATETIME,            -- 创建时间
update_by BIGINT,                -- 更新人
update_time DATETIME,            -- 更新时间
deleted TINYINT DEFAULT 0        -- 逻辑删除
```

### 4.3 索引规范

**建索引原则**：
- 高频查询字段
- 外键字段
- 排序字段
- 单表 ≤ 5 个索引

**避免**：
- 低选择性字段（性别、状态）
- 函数索引（会导致索引失效）

### 4.4 MyBatis Plus 使用

**注解**：
```java
@TableName("training_role")
@TableId(type = IdType.AUTO)
@TableLogic
```

**查询**：
```java
LambdaQueryWrapper<TrainingRole> wrapper = new LambdaQueryWrapper<>();
wrapper.eq(TrainingRole::getState, 1);
```

**禁止字符串拼接 SQL**

```java

wrapper.eq(TrainingRole::getName, name);
```

## 六、性能优化规范

### 6.1 查询优化

**必须分页**：
- ❌ 禁止一次性查询所有数据
- ✅ 使用分页查询

**避免 N+1 问题**：
```java
// ❌ 错误：循环查询
for (Role role : roles) {
    User user = userService.getById(role.getCreateBy());
}

// ✅ 正确：批量查询
List<Long> userIds = roles.stream().map(Role::getCreateBy).collect(Collectors.toList());
List<User> users = userService.listByIds(userIds);
Map<Long, User> userMap = users.stream().collect(Collectors.toMap(User::getId, u -> u));
```

### 6.2 缓存使用

**后端缓存**：
```java
@Cacheable(value = "dict", key = "#code")
@CacheEvict(value = "dict", key = "#code")
```

**前端缓存**：
- localStorage 缓存字典数据
- localStorage 缓存用户信息
- sessionStorage 缓存临时数据

### 6.3 数据库优化

**查询优化**：
- ❌ 避免 `SELECT *`
- ❌ 避免函数索引
- ✅ 使用 `EXPLAIN` 分析 SQL

**大数据量处理**：
- 考虑游标分页
- 滚动加载
- 异步处理

## 七、常见问题解决方案

### 7.1 时间格式不一致

**解决方案**：
- 后端统一 `@JsonFormat`
- 前端统一 `dayjs` 处理

### 7.2 大文件上传

**解决方案**：
- 分片上传（chunkSize = 5MB）
- 断点续传
- 秒传（文件 hash 校验）

### 7.3 接口响应慢

**排查步骤**：
1. 检查 N+1 问题
2. 添加索引优化
3. 使用缓存
4. 异步处理
5. 分页查询

### 7.4 数据一致性

**解决方案**：
- `@Transactional` 事务
- 乐观锁 version 字段
- 分布式锁（Redis）
- MQ 最终一致性

### 7.5 并发场景

**考试并发**：
- 数据库乐观锁
- Redis 分布式锁
- MQ 削峰填谷
