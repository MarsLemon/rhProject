# 教训：哑巴功能（静默 return / skip / log only）= 隐藏最深的事故

## 一句话

**所有"打了 log.warn 但不抛异常"的 return / continue / catch-all，都是高优先级 bug，必须改为显式 throw 或修实现。**静默失败的代码比报错的代码危险 10 倍，因为前者线上跑半天都没人发现。

## 哑巴功能四大典型反模式

### 1. `if (X) { log.warn("尚未实现"); return; }`

```java
// ❌ 反模式
public void manualQuery(String nodeType) {
    switch (nodeType) {
        case "course": doCourse(); break;
        case "exam":   doExam();   break;
        case "survey": log.warn("survey 尚未实现"); return;  // ← 静默
        case "battle": log.warn("battle 尚未实现"); return;  // ← 静默
    }
}
```

后果：含"问卷/竞赛"的计划 → 报名数据永不写入 → 完成校验凑不齐 → 计划永远完不成，UI 无任何提示。

### 2. `if (refId == null) continue;`

```java
// ❌ 反模式
for (PlanNode item : batchList) {
    if (StringUtils.isBlank(item.getRefId())) continue;  // ← 静默丢节点
    this.save(item);
}
```

后果：异步加载未完成 → 保存 → 部分节点悄无声息消失，UI 显示已保存但实际丢数据。

### 3. `catch (Exception e) { console.error(e); }`

```java
// ❌ 反模式
try {
    apiCall();
} catch (Exception e) {
    console.error(e);  // ← 吞掉所有错误,UI 不显示
}
```

后果：上游接口调用失败但 UI 继续跑，管理员以为成功，实际数据未落库。

### 4. `if (override instanceof Map) { cast } else { /* 跳过 */ }`

```java
// ❌ 反模式(更隐蔽)
Map<String, Object> map = (Map<String, Object>) resolver.resolve(...);  // 上游返 null → ClassCastException
```

后果：ClassCastException 打断整条接口链路，前端白屏但后端没明显报警。

## 正模式

### ✅ 1. 显式 throw，让上层知道

```java
case "survey": throw new UnsupportedOperationException("survey nodeType 暂不支持,请联系 PM 确认产品范围");
```

### ✅ 2. 拒绝保存含未实现节点的整批数据

```java
if (StringUtils.isBlank(item.getRefId())) {
    throw new ServiceException("节点" + i + " 关联资源为空: sort=" + item.getSort() + ", title=" + item.getTitle());
}
```

### ✅ 3. 异常要传到 UI 层

```java
try {
    return apiCall();
} catch (Exception e) {
    throw new ServiceException("操作失败: " + e.getMessage(), e);  // 全局异常处理器会推到 UI
}
```

### ✅ 4. cast 前必须 `instanceof` 守护

```java
Object result = resolver.resolve(...);
if (result == null) return;
if (!(result instanceof Map)) {
    throw new ServiceException("解析结果类型异常: " + result.getClass());
}
Map<String, Object> map = (Map<String, Object>) result;
```

## 必须做的自检清单

- [ ] `grep -n "log.warn\|return null\|return;\|continue;\|catch.*Exception"` 全仓扫描可疑点
- [ ] 任何 `// TODO` / `// 暂未实现` / `// 后续补充` 注释附近的代码必须 throw 或注释清楚风险
- [ ] 静默 catch 必须有"吞掉原因"的明确文档说明，且必须影响后续可观察行为

## 红线

**禁止**：`catch (Exception e) { log.error(e); }` 无 rethrow（除非有明确文档说明为何吞）

**禁止**：`log.warn(...) + return` 当作"暂未实现"的占位逻辑（应直接 throw）

**禁止**：`for` 循环里 `if (X) continue;` 不带日志（漏数据无法追查）

**强制**：所有"功能存在但实际不工作"的代码路径必须 throw 或在 UI 层显式提示
