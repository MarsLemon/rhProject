# 一键延期与一键补考 — 实施计划

## 需求摘要

在学习任务学员记录概览页（`/admin/plan/stat/process`）新增"一键延期"按钮（仅在 Plan.endTime 过期后显示），管理员勾选未完成人员后可：
1. 设置延期截止时间（仅作用于勾选人员，前端显示延长天数）
2. 可选开启补考，按考试维度配置追加次数，后端自动筛选未通过人员
3. 完成后发送通知，完成状态区分"延期完成"
4. 表格支持二级表头（项目数/完成项目 各拆 总/学/考）、独立状态筛选Tab、考试分数合并列

### 4.2 实现 PlanExtensionServiceImpl
- **文件**: `yf-module-plan/.../user/service/impl/PlanExtensionServiceImpl.java`（新建）
- `@Transactional(rollbackFor = Exception.class)`

**previewExtend() 逻辑：**
1. 查询 Plan 下所有 nodeType='exam' 的 PlanNode
2. 对每个考试节点，批量查询 ExamRecord WHERE exam_id IN (...) AND user_id IN (userIds) AND passed=false
3. 组装返回（一条SQL联合查询，避免N+1）

**batchExtend() 逻辑：**
1. 校验：now > Plan.endTime，newDeadline > Plan.endTime
2. **延期部分**（批量UPDATE）：
   - `UPDATE el_plan_user SET deadline=newDeadline, extend_count=extend_count+1 WHERE plan_id=? AND user_id IN (?) AND state=0`
3. **补考部分**（enableMakeup=true时）：
   - 对每个 makeupExams 中 addCount>0 的考试：
     a. `UPDATE el_exam SET end_time=newDeadline WHERE id=? AND end_time < newDeadline`
     b. `UPDATE el_plan_node SET end_time=newDeadline WHERE plan_id=? AND ref_id=? AND node_type='exam'`
     c. 批量查询/创建 ExamRecord，设置 `chance_override = tryCount + addCount`
     d. 重新调度 ExamOverdueJob（先deleteJob再addCronJob）
4. **通知**：通过 JobService 立即触发 PlanExtendNotifyJob 发送站内消息

## 第九部分：风险与缓解

| 风险 | 缓解措施 |
|------|----------|
| **Exam.endTime全局扩展影响非延期学员** | PlanPreServiceImpl.preCheck() 先校验学员级 deadline，非延期学员仍被 Plan.endTime 拦截 |
| **ExamOverdueJob竞态** | 延期时先 deleteJob 再 addCronJob，使用固定 jobName 格式 `exam:overdue:{examId}` |
| **大批量用户性能** | 批量 UPDATE...WHERE IN 替代循环；userIds>500时分批处理（每批200） |
| **多次延期状态混乱** | state=2 统一表示"延期完成"，extend_count 记录次数；checkFinished 兼容 state=0 和 state=2 |
| **补考Paper与正考混淆** | is_makeup 字段明确区分；现有成绩查询加 is_makeup=0 条件（默认值0向后兼容） |
| **关联子查询性能劣化** | 短期可接受（分页10-20条/页）；长期改为 LEFT JOIN...GROUP BY 或预计算 |
| **Vue 2语法限制** | 禁止 ?. ?? ES2020+；代码审查时重点检查 |
| **并发延期操作** | extendAndMakeup 方法加分布式锁 `@RedisLock(key="'plan:extend:'+#reqDTO.planId")` |

## 第十部分：被拒绝的方案

| 方案 | 拒绝原因 |
|------|----------|
| 修改 Exam.chance 全局值来追加补考次数 | 影响所有引用该考试的用户（包括非本培训项目的），副作用太大 |
| 为每次补考创建新的 ExamRecord | 破坏现有 ExamRecord 的"一人一考一记录"汇总设计，影响统计逻辑 |
| 频繁创建/取消 ExamOverdueJob | 不如直接更新 Exam.endTime + 重新调度，更简洁可靠 |
| 延期时同时延长 Plan.endTime | 已完成用户可能被"解冻"重新进入，业务风险大 |
| 补考截止时间独立设置 | 增加管理员操作复杂度，统一跟随延期时间更简单 |
| 完成状态显示延期次数（如"第2次延期完成"） | 状态列保持简洁，次数在 extend_count 字段中记录即可 |
