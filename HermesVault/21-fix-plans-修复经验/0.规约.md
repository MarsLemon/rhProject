# fix-plans 规约

> **2026-06-18 重新定位**：从 `E:\rhProject\fix-plans\` 迁入 `HermesVault\fix-plans\`，定位从"修复计划目录"升级为"**修复经验库**"。

## 为什么重新定位

旧定位（`E:\rhProject\fix-plans\`）已经**事实上是经验库**了——每份 fix-plan 都有 `Context / 修复任务清单 / 验证方法 / 关联风险 / 不在本计划范围`，沉淀的是"**问题 → 修复 → 学到什么**"的完整循环。但：

1. **没进 Obsidian 规约**——没有 frontmatter，dataview 查不到
2. **散在 `E:\rhProject\` 根目录**——和 IDE 配置、build 脚本混在一起，工作空间乱
3. **没有"经验"维度**——只有"问题 + 修复"，没显式记录"这次教会了我什么"

新定位 = **问题 → 计划 → 修复 → 沉淀** 四步循环，**每条都是"修过的事 + 学到的事"**。


## 命名规范

沿用 `E:\rhProject\fix-plans\README.md` 既有规范（**不破坏**）：

```
<YYYYMMDD>-<来源>-<主题>.md
```

- `<来源>`：`code-review` / `manual-test` / `prod-incident` / `tech-debt` / `refactor` / `spike`
- `<主题>`：3-5 个词的英文 / 拼音简述

## 必填 Frontmatter

每份 fix-plan **必须**带 frontmatter（按 HermesVault SCHEMA 规约）：

```yaml
---
title: <一句话标题>
created: YYYY-MM-DD
updated: YYYY-MM-DD
type: fix-plan                          # 新增 type（见 SCHEMA.md）
severity: blocker | high | medium | low # 严重度（替代原 emoji）
status: open | in-progress | fixed | wontfix | archived
tags: [fix-plan, <来源>, <模块>]        # <模块> = ui / backend / db / infra
learned: <一句话踩坑教训>                # 新增字段（最值钱的部分）
fixed_in: <commit hash 或 PR 链接>       # status=fixed 时填
sources:                                # 引用的原始材料（repowiki / 业务文档）
  - <路径>
confidence: high | medium | low
---
```

**`learned` 是这次重新定位的核心**——它强制每条 fix-plan 写一句"这次教会了我什么"，半年后翻回来才有价值。

## 文件正文模板

**沿用** `E:\rhProject\fix-plans\README.md` 既有模板（**不破坏**）：

```markdown

## Context（背景与问题）

（具体 bug / 设计缺陷描述 + 根因）

## 触发条件

（用户/调用方 输入 → 错误输出）

## 修复任务清单

### Task 1：<任务名>

**文件**：<绝对路径>:<行号>
<具体改法，必要时附代码片段>

## 关键修改文件路径

| 文件 | 修改 |
|------|------|
| ... | ... |

## 验证方法

### 步骤 1：<环境准备>
### 步骤 2：<操作>
### 步骤 3：<预期结果>

## 关联风险

（这次修复可能引入的次生问题）

## 不在本计划范围

（明确划清边界，避免范围蔓延）

## Learned（2026-06-18 新增）

> **这次教会了我什么**（一句话，重点写"为什么会犯"+"以后怎么避"）。
> 必填。即使写"无"，也要写"无明显教训，但 X 让我意识到 Y"。
```

## 何时新建页面

- ✅ code-review 跑出来的新 bug / 设计缺陷
- ✅ 手动测试发现的问题
- ✅ 生产事故
- ✅ 跨域改动留下的技术债
- ❌ 一次性的小问题（直接 commit message 写清楚就行）
- ❌ 还没想清楚怎么修的（先写 TODO，进了 issue tracker，再来 fix-plan）

## 何时归档到 `_archive/`

- `status: wontfix` 且超过 30 天未重启 → 归档
- 内容被完全替代（修了新方案）→ 归档
- 跟现在的方向完全不一致（过时的技术栈 / 换赛道）→ 归档
