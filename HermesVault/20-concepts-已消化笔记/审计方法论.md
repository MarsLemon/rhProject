# 审计 / 检查类任务方法论

> 2026-06-15 第 16 轮审计踩的坑,沉淀成 3 条铁律。
> 适用:任何"扫一堆文件,核状态"的活儿(权限审计 / 链接检查 / 配置漂移检测等)。

## 3 条铁律

### 1. **用物理文件系统 os.walk,不靠 git**

- **错路**:`git log` / `git ls-files` / `git diff` —— **会漏**
  - git 看不到**未追踪文件**(主人新建的)
  - git 看不到**stash / worktree / 第三方 clone**
  - git 看不到**文件被改名/移动但没 commit** 时的中间态
- **正路**:`os.walk` 扫真实目录,直接读文件内容
- **小坑**:跨平台用 `pathlib.Path` 而不是字符串拼路径

### 2. **"啥 abcd"=拒绝盲选,选项要给 context**

- 主人说"啥 abcd 啊"——意思是:别让我在没上下文的选项里蒙圈
- **错路**:列 A/B/C/D 一句话就完事
- **正路**:每选项带 1-2 句**为什么有这个选项 / 选它会怎样**,让主人有依据

### 3. **每条结论带字节数等证据**

- 审计/检查类回答,光说"有问题"不够
- **必带**:文件路径 + 字节数 + 行号 + 1 句说明
- **例子**:
  - ❌ "有个文件太大了"
  - ✅ "`scripts/old.py` 23 KB / 612 行,内部 `os.walk` 跟 `git` 重复,建议拆"

## 配套习惯

- 扫文件前先 `find . -name "*.md" -not -path "./.git/*"` 之类 **列文件清单**,再针对每个跑检查
- 大的扫描**用 `delegate_task` 并行**,别主线程死磕
- 报告分"**严重 / 中等 / 提示**"三档,不堆在一起

## 验证清单

- [ ] 改用 os.walk 后,跟 git 出的文件清单对比,os.walk 应该**多出来**那些 untracked/stash
- [ ] 任何"主人说选个"的问题,选项都带 context
- [ ] 任何审计报告都有 文件路径 + 字节数 + 行号
