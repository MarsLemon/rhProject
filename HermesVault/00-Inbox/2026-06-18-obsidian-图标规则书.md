# Obsidian 图标规则书

> 适用对象:本 Vault(`E:\rhProject\.obsidian-vault\`)目录树 + 笔记文件
> 配套插件:「为文件夹/文件指定图标」(Obsidian 1.12+ 原生功能)
> 维护:文件改动前先查本规则,新增目录/笔记先按本规则配色再写入

---

## 1. 规则层级(3 层,从上到下优先级递增)

| # | 层级 | 作用域 | 适用场景 |
|---|---|---|---|
| L1 | **目录默认色** | 整个文件夹及未单独配色的子项 | 10 个一级目录(见 §2) |
| L2 | **子目录 / 子笔记覆盖** | 目录内某个具体子文件夹或笔记 | concepts 下的 调研/新友盘/... |
| L3 | **文件级特例** | 单个具体文件 | 40-_meta-归档索引/SCHEMA、23-Tools-工具用法/README 等 |

**匹配顺序**:L3 > L2 > L1(更具体的覆盖更通用的)

---

## 2. L1 目录默认色(10 个一级目录)

按**业务域**分色,亮/暗二选一保证**左栏文件树在深色背景下对比清晰**。

| # | 目录 | 业务域 | 配色规则 | 备注 |
|---|---|---|---|---|
| 1 | `_meta` | 元数据 / 索引 | 亮色背景 + 黑字 | 唯一带下划线的目录,**所有"规则/索引"性质的元笔记都进这** |
| 2 | `comparisons` | 横向对比 | 亮色背景 + 黑字 | 跟 _meta 同色,都是"参考性"内容 |
| 3 | `concepts` | 概念定义 | 亮色背景 + 黑字 | 同上 |
| 4 | `entities` | 实体(人/项目/系统) | 亮色背景 + 黑字 | 同上 |
| 5 | `fix-plans` | 修复/迁移计划 | **亮色** | 跟"行动"相关,留亮色醒目 |
| 6 | `queries` | 查询 / Dataview 模板 | 暗色背景 + 白字 | 跟 raw 同暗色,都是"工具/原料" |
| 7 | `raw` | 原始摘抄/原料 | 暗色背景 + 白字 | **不加工**的原料,跟成品区分 |
| 8 | `Tags` | 标签页(自动聚合) | 暗色背景 + 白字 | 系统性,跟 raw 同色 |
| 9 | `Tools` | 工具/插件说明 | 暗色背景 + 白字 | 跟 31-queries-查询归档/raw 同色,都是"工具" |
| 10 | `log` | 日记 / 周报 / 流水 | **亮色** | 时间序列,亮色醒目 |

**色板**:亮色 = `#F4D8CD / #E8C896 / #D5E8B9 / #B5D3E7` 暖色系(粉/橙/绿/蓝);暗色 = `#2A2D3E / #3A4055 / #4A5066` 冷色系(深蓝灰)

## 3. L2 子目录 / 子笔记覆盖规则

### 3.1 何时覆盖

- 父目录的默认色不能体现子目录业务含义时
- 子目录有**专属视觉锚点**的需求(比如想跟"日常"区分"项目")

### 3.2 配色原则

- **同业务域 = 沿用父目录色**,只在 L1 默认色基础上调 1 档明度
- **跨业务域 = 用色板里其他颜色**,但**不与 L1 重复**(避免左栏混淆)
- **亮/暗反转判断**:如果子目录放的是"成品/对外内容"→ 保持亮色;如果是"内部草料/工具原料"→ 转暗色

### 3.3 当前约定(以 `20-concepts-已消化笔记/` 为例,看截图)

| 子目录 | 业务 | 配色 | 理由 |
|---|---|---|---|
| `20-concepts-已消化笔记/调研` | 调研笔记成品 | 亮色(沿用父) | 成品 |
| `20-concepts-已消化笔记/新友盘` | 单项目 | 亮色(沿用父) | 成品 |
| `20-concepts-已消化笔记/hermes-skill-system` | 单系统 | 亮色(沿用父) | 成品 |
| `20-concepts-已消化笔记/llm-wiki` | 单系统 | 亮色(沿用父) | 成品 |

**注**:截图里 4 个子笔记都是亮色,**符合"concepts 全域亮色"规则**。

## 4. L3 文件级特例(只能用图标,不能改配色)

| 规则 | 说明 |
|---|---|
| 配色锁定 L1/L2 | 文件级 **不**单独配背景色,只配图标 + 标签色 |
| 适用对象 | 根目录的 `log.md` `index.md` `README.md` `SCHEMA.md` `0_装Obsidian+打开这个Vault.md` |
| 配色 vs 图标 | 图标 = `lucide-*` 库的 SVG(优先)或 emoji(降级) |

**配色保留给目录**,文件级只换图标 — 这是为了左栏视觉不爆。

## 5. 命名 / 命名空间约定(避免图标覆盖错乱)

| 目录            | 颜色规则 | 图标建议                      | 禁用          |
| ------------- | ---- | ------------------------- | ----------- |
| `_meta`       | 亮色   | `lucide-settings` 或 `📐`  | 不用鲜艳色       |
| `comparisons` | 亮色   | `lucide-scale` 或 `⚖️`     | 不用双向箭头      |
| `concepts`    | 亮色   | `lucide-lightbulb` 或 `💡` | 不用书本        |
| `entities`    | 亮色   | `lucide-box` 或 `📦`       | 不用人物        |
| `fix-plans`   | 亮色   | `lucide-wrench` 或 `🔧`    | 不用扳手 + 文档组合 |
| `queries`     | 暗色   | `lucide-search` 或 `🔍`    | 不用代码块       |
| `raw`         | 暗色   | `lucide-file-text` 或 `📄` | 不用数据库       |
| `Tags`        | 暗色   | `lucide-tag` 或 `🏷️`      | 不用井号        |
| `Tools`       | 暗色   | `lucide-tool` 或 `🛠️`     | 不用齿轮        |
| `log`         | 亮色   | `lucide-calendar` 或 `📅`  | 不用时钟        |

---

## 6. 禁止(避免视觉噪音)

- **同一目录内 2 个子目录用同一颜色** — 失去区分意义
- **用纯红色 / 纯绿色 / 纯黄色当背景** — 太刺眼,违反暗色主题
- **文件级改背景色** — 左栏文件树会爆
- **图标用 emoji 跟 lucide 混搭** — 视觉不一致
- **新增目录时 L1 默认色不够** — 回到 §2 的色板扩,不要现造颜色

---

## 7. 维护流程(改前必查)

1. 改任何目录/笔记前,先看本规则书
2. 新增目录 → 在 §2 加一行,**先选色板已有颜色**
3. 现有目录改名 / 业务域变更 → 同步更新 §2 + §5
4. 视觉太杂时,先按本规则回滚,再考虑改 §2 色板
