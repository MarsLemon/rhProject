# oss-console 完善方案

## Context

`e:\rhProject\oss-console` 是本地自用的 OSS 文件浏览工具：列出当前 prefix 下的对象、复制 key、预览、按 key 批量删除、签名 URL。

对照主项目（`wk-train-center-service` / `wk-train-center-ui` / `wk-train-center-ui-v3` / `wk-PPTist-ui`）的真实用法，oss-console 存在以下问题：

1. **缺文件上传**：主项目前端 `ossUpload` 是核心能力，oss-console 完全没做
2. **私有桶无法预览**：`buildPublicUrl` 不区分 public/private，私有桶 `publicUrl` 直连必然 403
3. **批量删除低效**：当前 `for...await client.delete(key)` 串行，主项目用 `deleteMulti({ quiet: true })` 单次 1000 个
4. **类型重复**：`OssFileRow` / `ListResult` 在 `server/oss-client.ts` 与 `src/api.ts` 各定义一遍
5. **错误处理漏**：`App.vue` 的 `ElMessageBox.confirm` 没有 try/catch，用户取消会冒泡
6. **配置字段缺**：`OssEnvConfig` 缺 `security`（公开/私有区分），主项目 OssConfig 的 `arn` / `url` 占位字段也没保留
7. **README 误导**：写"参考 wk-PPTist-ui/src/utils/alioss.ts"，但 alioss.ts 依赖主项目 file-service 后端的 STS 端点，与本工具的"本机自用"定位不一致

**用户已确认边界**（不要扩展）：
- 范围 = 完善现有工具（不重做、不接主项目 DB）
- 必备功能 = 文件上传（单/批量）
- 配置来源 = 继续 `.env` 本地
- 鉴权 = 本机自用，不加

## 关键设计决策

### 1. 共享类型放 `shared/`

`e:\rhProject\oss-console\shared\types.ts`，平级于 `server/` 和 `src/`。`tsconfig.json` 已 `include: ["src/**/*.ts", "server/**/*.ts"]`，在 worktree 根加 `shared/**/*.ts` 即可。引用：

- `server/*.ts` → `import type { ... } from '../shared/types.js'`（注意 `.js` 后缀，ESM 规范）
- `src/*.ts` → `import type { ... } from '../../shared/types'`

### 2. 上传走 `multipart/form-data` + `multer`

**选 A 的理由**：
- Element Plus `<el-upload drag multiple>` 默认 form-data，前端零成本
- multer 1.4 lts 是 Node 生态唯一广泛使用的 multipart 解析器
- 后端内存模式 `multer.memoryStorage()` → `Buffer` → `client.put(name, buffer)`，500MB 以内对 4-8GB 内存的本机工具完全够用
- 上传进度天然得到：`<el-upload :on-progress>` + XHR `xhr.upload.onprogress`

**否决其他方案**：
- ❌ `application/octet-stream`：浏览器要 `fetch(file, { body: file.stream() })`，`Content-Length` 不准
- ❌ 前端浏览器直传 OSS：需桶 CORS + 暴露 AK，违背"本机自用最小依赖"
- ❌ base64：33% 膨胀，单文件上限低

### 3. 公开/私有桶通过 `security` 字段区分

```typescript
// server/oss-config.ts
export function buildPublicUrl(
  bucket: string, region: string,
  override: string | undefined,
  security: 'public' | 'private'
): string {
  if (security === 'private') return ''   // 私有桶直连必然 403
  const trimmed = override?.trim()
  if (trimmed) return trimmed.endsWith('/') ? trimmed : `${trimmed}/`
  return `https://${bucket}.${region}.aliyuncs.com/`
}
```

前端 `OssFileRow.publicUrl` 私有桶时为 `''`，预览按钮走 `/api/objects/sign?key=...` 拿签名 URL。

### 4. deleteMulti 按 1000 分批

```typescript
// server/oss-client.ts
const DELETE_BATCH = 1000
export async function deleteObjects(client: OSS, keys: string[]) {
  const deleted: string[] = []
  const failed: { key: string; error: string }[] = []
  for (let i = 0; i < keys.length; i += DELETE_BATCH) {
    const batch = keys.slice(i, i + DELETE_BATCH)
    try {
      const result = await client.deleteMulti(batch, { quiet: true })
      deleted.push(...batch)
      // 兜底：SDK 老版本在 quiet 模式下仍可能返回 deleted 数组
      if (result?.deleted && Array.isArray(result.deleted)) {
        const okSet = new Set(result.deleted.map((d: { Key?: string }) => d.Key).filter(Boolean) as string[])
        deleted.splice(deleted.length - batch.length, batch.length, ...batch.filter((k) => okSet.has(k)))
        for (const k of batch.filter((k) => !okSet.has(k))) failed.push({ key: k, error: 'not in response' })
      }
    } catch (e) {
      const msg = e instanceof Error ? e.message : String(e)
      for (const k of batch) failed.push({ key: k, error: msg })
    }
  }
  return { deleted, failed }
}
```

### 5. key 安全

`server/key-safety.ts` 的 `safeJoinKey(prefix, filename)`：

- 取 `filename.split(/[\\/]/).pop()` 作为 basename（防 `../` 越界）
- 拒绝 basename 为 `.` / `..` / 空
- 拒绝含控制字符 `\u0000-\u001f\u007f`
- normalize prefix：以 `/` 结尾、不出现 `//`、不出现 `../`、去除反斜杠
- 拒绝长度 > 1024

应用点：
- `uploadObjects` 拿 `file.originalname` 后必过 `safeJoinKey`，失败进 `failed`（不 500）
- `/api/objects/delete` 路由层过 `keys[]`，避免空串或越界 key 传给 SDK

### 6. 上传白名单（可被 .env 关闭）

```typescript
const ALLOWED_EXT = new Set([
  'pdf', 'doc', 'docx', 'ppt', 'pptx', 'xls', 'xlsx', 'txt', 'md', 'csv',
  'jpg', 'jpeg', 'png', 'gif', 'webp', 'svg', 'bmp',
  'mp4', 'mp3', 'wav', 'mov', 'avi', 'mkv', 'm4a',
  'zip', 'rar', '7z', 'tar', 'gz'
])
```

非白名单扩展名进 `failed`，主流程不中断。

### 7. 前端上传走 XHR 不用 fetch

`fetch` 的上传进度是消费进度不是发送进度，要走 `ReadableStream` 拆 chunk 才能拿到。XHR `xhr.upload.onprogress` 是浏览器原生支持的最佳路径：

```typescript
// src/api.ts
export function uploadFiles(files: File[], prefix: string, onProgress?: (p: number) => void) {
  return new Promise<UploadResult>((resolve, reject) => {
    const form = new FormData()
    files.forEach((f) => form.append('files', f, f.name))
    const xhr = new XMLHttpRequest()
    xhr.open('POST', `/api/objects/upload?prefix=${encodeURIComponent(prefix)}`)
    xhr.upload.onprogress = (e) => {
      if (e.lengthComputable && onProgress) onProgress(Math.round((e.loaded / e.total) * 100))
    }
    xhr.onload = () => {
      try {
        const body = JSON.parse(xhr.responseText)
        if (xhr.status >= 200 && xhr.status < 300) resolve(body)
        else reject(new Error(body.error ?? xhr.statusText))
      } catch { reject(new Error(xhr.statusText || 'parse error')) }
    }
    xhr.onerror = () => reject(new Error('network error'))
    xhr.send(form)
  })
}
```

## 关键代码片段

### `server/upload.ts`

```typescript
import multer from 'multer'
import OSS from 'ali-oss'
import { safeJoinKey } from './key-safety.js'
import type { UploadResult, UploadSuccessItem, UploadFailureItem } from '../shared/types.js'
import type { OssEnvConfig } from './oss-config.js'

const ALLOWED_EXT = new Set([
  'pdf', 'doc', 'docx', 'ppt', 'pptx', 'xls', 'xlsx', 'txt', 'md', 'csv',
  'jpg', 'jpeg', 'png', 'gif', 'webp', 'svg', 'bmp',
  'mp4', 'mp3', 'wav', 'mov', 'avi', 'mkv', 'm4a',
  'zip', 'rar', '7z', 'tar', 'gz'
])

export function createUploadMiddleware(maxFileSize: number, maxFiles = 50) {
  return multer({
    storage: multer.memoryStorage(),
    limits: { fileSize: maxFileSize, files: maxFiles }
  }).array('files', maxFiles)
}

export async function uploadObjects(
  client: OSS, config: OssEnvConfig,
  files: Express.Multer.File[], rawPrefix: string
): Promise<UploadResult> {
  const prefix = (rawPrefix || config.defaultPrefix || '').trim()
  const uploaded: UploadSuccessItem[] = []
  const failed: UploadFailureItem[] = []

  for (const file of files) {
    const key = safeJoinKey(prefix, file.originalname)
    if (!key) { failed.push({ name: file.originalname, error: 'invalid key' }); continue }
    const ext = (file.originalname.split('.').pop() || '').toLowerCase()
    if (ext && !ALLOWED_EXT.has(ext)) { failed.push({ name: file.originalname, error: `extension .${ext} not allowed` }); continue }
    try {
      const res = await client.put(key, file.buffer, { headers: { 'Cache-Control': 'max-age=31536000' } })
      uploaded.push({
        key, name: file.originalname, size: file.size,
        etag: res.res?.headers?.etag,
        publicUrl: config.security === 'private' ? '' : config.publicUrl + key
      })
    } catch (e) {
      failed.push({ name: file.originalname, error: e instanceof Error ? e.message : String(e) })
    }
  }
  return { uploaded, failed, prefix }
}
```

### `server/index.ts` 新增路由

```typescript
import { createUploadMiddleware, uploadObjects } from './upload.js'

const uploadMw = createUploadMiddleware(config.maxFileSize, 50)

app.post('/api/objects/upload', (req, res) => {
  uploadMw(req, res, async (err) => {
    if (err) {
      const msg = err instanceof multer.MulterError ? `${err.field}: ${err.message}` : err.message
      res.status(400).json({ error: msg }); return
    }
    try {
      const files = (req.files as Express.Multer.File[] | undefined) ?? []
      if (files.length === 0) { res.status(400).json({ error: 'no files in form-data (field: files)' }); return }
      const prefix = String(req.query.prefix ?? '')
      const result = await uploadObjects(client, config, files, prefix)
      res.json(result)
    } catch (e) {
      res.status(500).json({ error: e instanceof Error ? e.message : String(e) })
    }
  })
})
```

## 边界条件（容易被忽视）

1. **同名 key 覆盖语义**：`client.put(name, buffer)` 默认直接覆盖（OSS 标准，versioning 关闭时）。本机自用工具的"覆盖"是用户可预期的。可选：上传前 `listV2` 检查 `prefix + filename` 已存在时弹 `ElMessageBox.confirm` 让用户确认。**本次先做最简（直接覆盖）**，留待后续按需加。
2. **签名 URL 过期**：`client.signatureUrl(key, { expires })` 阿里 SDK 默认 1800s。`/api/objects/sign?expires=` 限定 `[60, 86400]`，防误传极大值。
3. **中文 key**：`ali-oss` 6.22 内部 UTF-8 处理正确。`toFileRow` 取 `key.split('/').pop()` 得到正确 basename。**测试要补一条中文 key 用例**。
4. **桶 versioning** 开启时 `deleteMulti` 产生 delete marker 不真删。本机自用工具默认没开，不处理。
5. **multer `req.files` 类型**：`@types/multer` 1.4 下是 `Multer.File[] | undefined`，要 `as Express.Multer.File[]` 强转。`tsconfig.json` 已 `strict: true`。
6. **OSS 单次 deleteMulti 上限 1000**：超出要分批（已实现）。

## 不做的事（明确边界）

| 不做 | 原因 |
|------|------|
| 接主项目 DB / `cfg_prop` 表 | 用户明确"不接主项目 DB" |
| STS / 临时凭证 | 本机自用、AK/SK 已足够；STS 需配 RAM Role，复杂度爆炸 |
| 前端浏览器直传 OSS | 需 CORS + 暴露 AK，与"本机自用最小依赖"冲突 |
| `multipartUpload` 分片上传 | 浏览器分片只对绕过服务器直传有意义；本工具中转，500MB 内存 Buffer 单 `put` 足够 |
| 桶 versioning 处理 | 本机自用默认不开，不主动加复杂度 |
| 视频转码 / 缩略图 | 主项目 `OssServiceImpl` 才有，本工具不重做 |
| 多桶切换 / 按前缀删除 / 全局搜索 | 用户未勾选；明确不做 |
