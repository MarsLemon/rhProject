## 二、与文档的偏差 ⚠

### 偏差 1:文档"协议加 state 字段全链路透传"措辞过满

- 文档第三章"协议加 state 字段全链路透传"
- 实际:**仅批量路径(`TrainCenterUserSyncInfoCommand`)** 透传 `state`
- **单条路径**(`TrainCenterUserSyncCommand`,用于加角色实时同步) **无 `state` 字段**;`RepositoryImpl.doSyncUser`(对应 `/api/open/wk/sync-user`)也不带 `state`
- 影响:无 — 加角色时用户肯定是启用态,逻辑合理
- 建议:文档补一句"state 仅在批量同步链路透传;单条加角色路径不含此字段"

### 偏差 2:文档"`UserService` 卸掉同步方法"措辞不准

- 文档说"`UserService` / `UserServiceImpl` **卸掉**同步方法,回归用户自身职责"
- 实际:`a0bac1f2` 只卸了**批量**方法(`userSyncAllInfo`/`userSyncChangedInfo`/`userSyncInfo`/`syncUsersToTrainCenter`)
- **`UserServiceImpl.addUserRole` 内的 `trainCenterUserSyncService.syncUser()` 单条同步调用没卸** — 仍依赖 train-center HTTP
- 影响:**见下方 bug 3**(事务内调用 + 无容错)
- 建议:文档改为"卸掉批量同步方法;加角色触发的单条同步仍走老入口"

### 偏差 3:文档"加学习中心角色时实时单人同步"路径有 bug

- 文档说"加学习中心角色时实时单人同步(`RoleServiceImpl.batchAddRoleUser` / `addUserRole`)"
- `batchAddRoleUser` 已加 try-catch 容错 ✅
- `addUserRole` 在 [`UserServiceImpl.java:533-561`](file:///E:/rhProject/wk-user/wk-user-api/src/main/java/com/wk/user_new/service/user/impl/UserServiceImpl.java#L533) 用 `@Transactional` 包裹,**且 `trainCenterUserSyncService.syncUser()` 在事务内** — 若 train-center 不可达,事务回滚,**用户加角色也被回滚**
- `RepositoryImpl` 注释说"单人同步处于事务内,必须快速失败" — 但快速失败的后果是回滚业务,不是单点失败
- **建议**:`addUserRole` 里把 `syncUser` 调用挪出事务 / 加 try-catch + 异步化(参考 `batchAddRoleUser` 异步池模式)

## 三、发现的 bug 🔴

### bug 1:`selectValidTenures` LEFT JOIN 与 WHERE 条件不符 [P2]

- 文件:[TrainCenterEmployeeDeptSyncMapper.xml:5-21](file:///E:/rhProject/wk-user/wk-user-api/src/main/resources/com/wk/user_new/mapper/TrainCenterEmployeeDeptSyncMapper.xml#L5)
- 现象:写的是 `LEFT JOIN wk_employee_department`,但 WHERE 里 `wed.office_type != 20` / `wed.state = 1` / `wed.office_begin_date <= now()` 会把 wed 为 NULL 的行**全部过滤掉**,实际行为等价于 INNER JOIN
- 影响:无功能影响(业务上"没任职=不参与同步"是对的),但 LEFT JOIN 误导维护者
- 修复:把 `LEFT JOIN` 改为 `INNER JOIN`,或加 `OR wed.id IS NULL` 显式表达"无任职"语义

### bug 2:`appendDisabledUserCommands` 可能误把刚被新增/启用的账号冻掉 [P3]

- 文件:[AppServiceImpl.java:293](file:///E:/rhProject/wk-user/wk-user-api/src/main/java/com/wk/user_new/service/traincenter/TrainCenterUserSyncAppServiceImpl.java#L293)
- 场景:`syncChanged(25h)` 跑了之后,train-center 临时挂了;25h 后重跑增量 — `listDisabledUserCodes` 仍返回**历史上停用的全部账号**,不只是 25h 内停用的
- 后果:第 25h 这次重跑会把**全部历史停用账号**再次发冻结指令(虽然 train 侧是 no-op,网络开销大)
- 修复:增量场景下也按 `update_time >= since` 过滤停用账号(同 `findChangedUserCodes` 的窗口一致)
- **或**:`appendDisabledUserCommands` 加个 `since` 参数,在 `syncChanged` 传进来,`syncAll` 仍传全量

### bug 3:`addUserRole` 单条同步在事务内,无容错 [P1]

- 文件:[UserServiceImpl.java:533-561](file:///E:/rhProject/wk-user/wk-user-api/src/main/java/com/wk/user_new/service/user/impl/UserServiceImpl.java#L533)
- 现象:见偏差 3
- 风险:train-center 不可达 → 业务回滚;前端报"加角色失败"但实际角色没加成(用户困惑)
- 修复:**加 try-catch,失败只 log 不抛**;或将 `syncUser` 挪到事务外 / 异步化

### bug 4:`querySyncInfo` 没过滤 merchant,但 `syncAll`/`syncChanged` 排除 [P3,行为正确但易混]

- 文件:[AppServiceImpl.java:84-97](file:///E:/rhProject/wk-user/wk-user-api/src/main/java/com/wk/user_new/service/traincenter/TrainCenterUserSyncAppServiceImpl.java#L84)
- 现象:`querySyncInfo(userCode)` 对 merchant 也返回 BO(只读)
- 接口注释已注明此行为 ✅
- 风险:若后续有人误用 `querySyncInfo` 的结果做批量,会把企业用户拉进去
- 建议:无修复,但建议在 controller 路径上加 @ApiOperation 备注,文档第三章"加学习中心角色时实时单人同步"明确说"企业用户走 `querySyncInfo` 不入批量"

### bug 5:`findChangedUserCodes` 第 2 个 UNION 不带 `state=1` 过滤 [P3,实际无副作用但有歧义]

- 文件:[UserMapper.xml:200-203](file:///E:/rhProject/wk-user/wk-user-api/src/main/resources/com/wk/user_new/mapper/UserMapper.xml#L200)
- 现象:`SELECT wa.user_code FROM wk_account wa WHERE wa.update_time >= #{since}` — 不关联 `wk_user`,不过滤 `state`
- 实际:`syncChanged` 后续通过 `userRepository.allUser()` 过滤启用账号,最终走 `appendDisabledUserCommands` 路径
- 风险:无功能影响,但 SQL 行为依赖下游过滤,**耦合隐式**
- 修复:第二个 UNION 改写为 `SELECT u.user_code FROM wk_user u JOIN wk_account wa ON u.user_code = wa.user_code WHERE u.state = 1 AND wa.update_time >= #{since}`

### 6.2 单一职责(SRP) ⚠

#### 6.2.1 `TrainCenterUserSyncAppServiceImpl` 类 321 行,做了 4 件事

### 6.4 命名 / 包结构 ⚠

#### 6.4.1 包名 `service.traincenter` 而不是 `service.train_center`
- 文件:包路径

### 6.5 异常与错误处理 ⚠

#### 6.5.1 `appendDisabledUserCommands` catch 后只 log warn(P2)
- 文件:[AppServiceImpl.java:316-318](file:///E:/rhProject/wk-user/wk-user-api/src/main/java/com/wk/user_new/service/traincenter/TrainCenterUserSyncAppServiceImpl.java#L316)
- 现象:`catch (Exception e) { log.warn(...) }` — 吞了所有异常
- 问题:数据库挂了 / MyBatis 抛 DataAccessException,被悄悄吞掉,主流程继续推,接收端拿到残缺数据
- 建议:**至少**对 `DataAccessException` 上抛,其他异常(如序列化)可降级

#### 6.5.2 `buildSyncCommand` 整个 try-catch 太宽(P2)
- 文件:[AppServiceImpl.java:275-279](file:///E:/rhProject/wk-user/wk-user-api/src/main/java/com/wk/user_new/service/traincenter/TrainCenterUserSyncAppServiceImpl.java#L275)
- 现象:`catch (Exception e)` — NPE/ClassCast/IllegalState 全吞
- 问题:空指针 bug 也被悄悄吞,排障极难
- 建议:细分为 `catch (NullPointerException e) { log.error("字段缺失", e); return null; }` + `catch (Exception e) { log.error("未知", e); return null; }`,或只 catch `IllegalArgumentException` + `NullPointerException`

#### 6.5.3 `querySyncInfo` 对 merchant 调 `getMerchantMemberByCode` 没判 null(P3)
- 文件:[AppServiceImpl.java:95-96](file:///E:/rhProject/wk-user/wk-user-api/src/main/java/com/wk/user_new/service/traincenter/TrainCenterUserSyncAppServiceImpl.java#L95)

- 建议:加 null 判断或 try-catch(查询方法统一从仓储层抛 DataNotExist 异常)

## 七、DDD/OOP 总结

| 维度 | 评价 |
|---|---|
| 分层 | ✅ 整体清晰,AppService 抽离成功 |
| 单一职责 | ⚠ `TrainCenterUserSyncService` 命名误导 + AppServiceImpl 偏胖 |
| 开闭原则 | ⚠ `appendDisabledUserCommands` 隐式耦合;`EmployeeDeptSyncBatchQuery` 名实不符 |
| 接口隔离 | ⚠ `TrainCenterUserSyncService` 同时管单条/批量,语义重叠 |
| 依赖倒置 | ⚠ RepositoryImpl 自己 new RestTemplate,不能注入 |
| 包结构 | ✅ `service.traincenter.*` 边界清晰,`dao/model` 隔离好 |
| 命名一致性 | ⚠ `service.traincenter`(无下划线)vs `TrainCenter`(驼峰)需要新人对一次 |
| 异常处理 | ⚠ catch 太宽,吞异常 |
| 不可变 / 集合 | ✅ 用 `LinkedHashMap` 保留顺序是好习惯 |
| Lombok | ⚠ BO 用 `@Data` 过度 |
| 测试 | ⚠ 私有方法没独立测,`verify` 不全 |

**核心建议 3 条**

1. **拆 `TrainCenterUserSyncService`** — 一个接口管两个完全不同的用例,违反 ISP。改 `TrainCenterUserRoleSyncService`(单条) + 让 `AppService` 直接调 `Repository.syncUserAll`(批量)
2. **`EmployeeDeptSyncBatchQuery` 改名 `EmployeeDeptSyncAssembler`** — 名实一致;同时把 `appendDisabledUserCommands` 跟它合并成一个 `UserSyncCommandAssembler`,AppServiceImpl 瘦到 100 行内
3. **RepositoryImpl 抽 RestTemplate 到 Spring Bean** — 复用项目通用配置 + 利于单测 mock

这些都不影响上线(P0 仍是 P1 的 `addUserRole` 事务回滚),但发版前修一遍能少埋几个 6 个月后的坑。
