## 1. 现状与基础

### 1.1 当前公式

```
行金额 = Σ(职级费率 × 人数) × 单件标准工时 × 数量
最终报价 = Max(合计保底价, 明细合计) × 影响系数
影响系数 = Max(紧急系数, 地点系数, 时间系数)   // 2026-09-18 取最大值
```

### 1.2 因子划分

| 类别 | 包含 | 作用 |
|------|------|------|
| **基础因子** | 职级费率 / 标准工时 / 数量 / 计件基准 | 推标准价 |
| **影响因子** | 紧急系数 / 地点系数 / 时间系数 | 调节最终价 |

### 1.3 业务事实

- **客户档案已存在**(船东/船管公司、联系人、历史记录)
- **默认一船一单**(业务方确认)
- **客户侧只看最终价**(D17)

## 2. 成本大表分析

### 2.1 6 种计价逻辑概览

成本大表是公司销售内部定价的成熟体系,**支持 6 种定价法 + 多级审批**。

| # | 方法 | 业务语义 |
|---|------|---------|
| 1 | 成本加成 | 成本 + 计划毛利率 |
| 2 | 市场导向 | 看竞品行情 + 毛利率 |
| 3 | 边际成本(船套) | 大批量同型船分摊成本 |
| 4 | 效用 | 按客户使用价值 |
| 5 | 自定义 | 名称 + 金额(兜底) |
| 6 | 其他费用/佣金 | 名称 + 金额(附加项) |

### 2.2 客户定价场景对照

| # | 成本大表方法 | 客户定价适用性 | 判定 |
|---|-------------|---------------|------|
| 1 | 成本加成 | ❌ 不适用 | D17 已定客户侧不暴露成本 |
| 2 | 市场导向 | ❌ 不适用 | 客户定价是参考报价,不是竞品对比 |
| 3 | 边际成本(船套) | ❌ 不适用 | 客户询价是单船单次,无"船套"概念 |
| 4 | 效用 | ❌ 不适用 | 维保是劳务型,非按用量计费商品 |
| 5 | 自定义 | ✅ 已沿用 | 客户定价已有"自定义"附加项 |
| 6 | 其他费用/佣金 | ✅ 已沿用 | 客户定价已有"代理佣金"附加项 |

### 2.3 4 种不适用方法的详细分析

#### #1 成本加成 — 不适用

- **成本大表用法**:成本 + 计划毛利率
- **客户定价场景**:客户侧不看成本构成(D17)
- **结论**:加成无意义,客户报价是劳务汇总,不暴露成本

#### #2 市场导向 — 不适用

- **成本大表用法**:看竞品行情定价
- **客户定价场景**:是 B2C 询价参考,不是 B2B 竞品对比
- **结论**:无竞品对比场景,无市场参考机制

#### #3 边际成本(船套) — 不适用

- **成本大表用法**:大批量同型船分摊成本
- **客户定价场景**:默认一船一单(§1.3),无"船套"概念
- **结论**:批量场景业务边界模糊,场景不匹配

#### #4 效用 — 不适用

- **成本大表用法**:按客户使用价值定价
- **客户定价场景**:维保是劳务型服务,非"按用量计费"商品
- **结论**:无"使用价值"概念,无法套用

### 2.4 2 种可沿用方法

| 方法 | 沿用方式 |
|------|---------|
| 自定义(#5) | 客户定价已有"自定义"附加项,沿用 |
| 其他费用/佣金(#6) | 客户定价已有"代理佣金"附加项,沿用 |

## 3. 成本大表深层逻辑借鉴

虽然 6 种方法不直接适用,但其**底层设计思想**值得深挖借鉴。

### 3.1 4 个可借鉴的底层逻辑

| 借鉴点 | 业务本质 | 是否借鉴 | 备注 |
|--------|---------|---------|------|
| **Strategy Pattern(策略模式)** | 加新方法不动现有数据 | ✅ **P0 已定** | 调研报告 §5.1 |
| **多对多关联** | 询价单↔客户/系数 N:N 关联 | ✅ 浅借鉴 | 审计可追溯 |
| **快照冻结 + 生效期** | 历史询价不受调价影响 | ✅ **已实现** | R-23 |
| **跨币种 + 汇率快照** | 国外客户询价锁定 | ✅ **P1 已定** | 调研报告 §5.2 |

### 3.2 借鉴方式详解

#### 借鉴 A:Strategy Pattern(策略模式)

**业务本质**:把"定价方法"从写死公式升级为可切换方法,加新方法不动老方法。

```
未来客户定价可支持的定价方法:
├─ 标准工时定价     ← 当前(保留)
├─ 紧急加价         ← P0 升级(§4.2)
├─ VIP 客户价       ← P1 新增(§4.3)
├─ 远程诊断定价     ← P1 新增(§4.4)
├─ 询价包干价       ← P1 新增(§4.5)
└─ [未来扩展]
```

#### 借鉴 B:多对多关联(部分借鉴)

**业务本质**:所有定价相关实体走 N:N 关联表,审计可追溯。

```
询价单 (inquiry)
├─ N:N 客户档案 (inquiry_customer)        ← VIP 折扣按客户等级
├─ N:N 影响系数快照 (inquiry_coefficient) ← 影响系数追溯
├─ 1:N 服务项 (inquiry_item)              ← 明细行
└─ 1:N 定价方法快照 (inquiry_pricing_method) ← 加价金额追溯
```

#### 借鉴 C:快照冻结 + 生效期(已借鉴)

- 询价单提交冻结(R-23)
- 职级费率卡带生效期
- 调费率/调系数不影响历史询价单

#### 借鉴 D:跨币种 + 汇率快照(P1)

- 询价单加币种 + 汇率字段
- 提交时按当时汇率锁定
- 销售邮件双币种展示

### 3.3 决策点(2 项)

| # | 决策 | 推荐 |
|---|------|------|
| C1 | 多对多关联深度 | **浅(只关联客户+系数)** |
| C2 | 跨币种 | **启用(P1)** |

### 4.2 P0 紧急加价升级 ⭐

#### 1. 一句话(含推荐理由)

**客户要得急,加价;要得不急,原价。从乘数升级为独立定价法 — 业务可解释,成本可测算,数据可沉淀。**

#### 2. 公式

```
加价金额 = 标准价 × (加价率 - 1)
最终报价 = 标准价 + 加价金额
影响系数 K = Max(地点系数, 时间系数)   // 紧急维度退出合成
```

#### 3. 决策点(6 项)

| # | 决策 | 推荐 |
|---|------|------|
| U1 | 加价率配置方 | **运营配** |
| U2 | 字典档位 | **5 档(含特急/灾难)** |
| U3 | 与影响系数关系 | **完全解耦** |
| U4 | 加价金额可见性 | **销售邮件可见** |
| U5 | 加价说明路径 | **邮件 + 后台双通道** |
| U6 | 影响系数 Max 调整 | **改为两维(地点+时间)** |

#### 4. 加价率与融合方式

**加价率建议**:

| 紧急程度 | 加价率 | 备注 |
|----------|--------|------|
| 不紧急 | 100% | 默认 |
| 紧急 | 120%(+20%) | 加班成本 |
| 非常紧急 | 150%(+50%) | 外协 + 加班 |
| 特急 | 协议价 | 单谈 |
| 灾难级 | 协议价 | 单谈 |

**升级理由矩阵**:

| # | 理由 | 升级后效果 |
|---|------|----------|
| 1 | 业务可见 | 销售邮件明示加价金额 |
| 2 | 成本可测算 | 加价率=真实成本(加班/外协/违约/物流) |
| 3 | 解耦地点/时间 | 紧急独立,不影响其他维度 |
| 4 | 多档扩展 | 2 档 → 5 档 |
| 5 | 数据沉淀 | 加价金额独立字段,统计"加价贡献率" |
| 6 | 业务可拍板 | 加价率=绝对加价幅度,易决策 |
| 7 | 可解释 | 销售说清"加价 $20 万 = 加班 + 外协 + 物流" |
| 8 | 维度清晰 | 紧急/地点/时间 不再互相挤压 |

**融合方式**:

- 与基础因子:正交(基础因子推标准价,加价因子推加价额,两路独立)
- 与影响因子:**退出 Max 合成**,影响系数从三件套变两件套(地点+时间)
- 与报价公式:`最终报价 = 标准价 + 加价金额`,加价行独立展示
- 与询价单:新增 `urgency_level_id` + `urgency_premium_amount` + `urgency_premium_rate` + `urgency_premium_explanation` 字段,均进快照
- 与 D17:**紧急维度退出影响系数 Max 合成**(关键变化)

### 4.3 P1 VIP 客户价 ⭐

#### 1. 一句话(含推荐理由)

**同产品,不同客户不同价。按客户等级折扣 — 锁单关键手段,客户档案已就位可直接做。**

#### 2. 公式

```
VIP 报价 = 标准价 × VIP 折扣率
```

#### 3. 决策点(5 项)

| # | 决策 | 推荐 |
|---|------|------|
| V1 | 等级体系 | **5 级(含战略)** |
| V2 | 评定方 | **系统自动 + 运营复核** |
| V3 | 复评周期 | **一年** |
| V4 | 战略客户是否参与 | **不参与(协议价)** |
| V5 | 等级快照口径 | **询价时点**(同影响系数) |

#### 4. 等级体系与融合方式

**等级体系**:

| 等级 | 折扣率 | 评定标准 | 备注 |
|------|--------|---------|------|
| 普通 | 100% | 默认 | 无等级走标准价 |
| 银卡 | 95% | 年度询价 ≥ 3 次 或 累计 ≥ 50 万 | 自动 |
| 金卡 | 90% | 年度询价 ≥ 5 次 或 累计 ≥ 200 万 | 自动 |
| 钻石 | 85% | 战略合作 | 运营手工 |
| 战略 | 协议价 | 不参与折扣 | 协议价单谈 |

**融合方式**:

- 与基础因子:正交(基础因子推标准价,VIP 折扣按客户等级作用于标准价)
- 与影响因子:正交(紧急/地点/时间仍走 Max,VIP 折扣作用于基础价)
- 与报价公式:`VIP 报价 = 标准价 × VIP 折扣率`,折扣独立展示
- 与询价单:新增 `customer_id` + `customer_level` + `vip_discount_rate` 字段,均进快照
- 与客户档案:**客户档案已存在**,只需新增等级字段(工作量从"大改造"降级到"中等改造")
- 与一船一单:N:N 关系(同一客户多艘船 → 多个询价单,每单独立应用 VIP 折扣)

### 4.4 P1 远程诊断定价 ⭐

#### 1. 一句话(含推荐理由)

**视频/电话指导,不出场 — 覆盖长尾小客户,纯人力低成本,边际成本接近零。**

#### 2. 公式

```
远程诊断报价 = 远程费率 × 咨询时长
```

无差旅/物流/住宿成本,**只算人力时间**。

#### 3. 决策点(2 项)

| # | 决策 | 推荐 |
|---|------|------|
| B1 | 是否做远程诊断 | **做(P1)** |
| — | 远程费率如何配? | **运营配 + 时长上限封顶** |

#### 4. 远程费率与融合方式

**远程费率建议**:

| 咨询类型 | 费率(假设) | 备注 |
|----------|-----------|------|
| 视频诊断 | $80/h | 主力场景 |
| 电话咨询 | $50/h | 轻量场景 |
| 邮件书面 | $30/封 | 异步场景 |

**时长封顶**:单次询价 ≤ 4 小时,超出转现场服务(防止远程被无限占用)。

**融合方式**:

- 与基础因子:**替代**(远程诊断不走"职级费率 × 标准工时",直接按时长计费)
- 与影响因子:正交(地点系数可能仍适用,因偏远地区远程服务也加价;时间系数不适用,远程是即时)
- 与报价公式:`远程诊断报价 = 远程费率 × 时长`,独立定价
- 与询价单:新增 `pricing_method = remote_diagnosis` + `remote_hours` + `remote_rate` 字段
- 与客户侧:D17 持续(只看最终价)
- 与销售邮件:明示"远程诊断费 $X(视频诊断 Y 小时)"
- 与业务边界:沉淀远程案例库,后续可做 AI 自助咨询

### 4.5 P1 询价包干价(区间报价) ⭐

#### 1. 一句话(含推荐理由)

**系统给"8-12 万"区间报价,期内有效 — 客户决策快,销售沟通轮次减半。**

#### 2. 公式

```
区间下限 = 标准价 × 0.95   // 5% 折让
区间上限 = 标准价 × 1.10   // 10% 浮动
客户拿区间,销售在区间内落定
```

#### 3. 决策点(2 项)

| # | 决策 | 推荐 |
|---|------|------|
| B2 | 是否做询价包干价 | **做(P1)** |
| — | 区间宽度如何配? | **下限 95% / 上限 110%(建议起点)** |

#### 4. 区间配置与融合方式

**区间配置建议**:

| 标准价档位 | 区间宽度 | 备注 |
|-----------|---------|------|
| < 10 万 | [95%, 110%] | 小单,窄区间 |
| 10-50 万 | [95%, 115%] | 中单,中等区间 |
| 50-100 万 | [95%, 120%] | 大单,宽区间 |
| > 100 万 | [协议, 协议] | 超大单,不走区间 |

**融合方式**:

- 与基础因子:正交(基础因子推标准价,区间按标准价上下浮动)
- 与影响因子:正交(紧急/地点/时间仍走 Max,包干价的"标准价"含系数后值)
- 与报价公式:`区间 = [标准价 × 下限, 标准价 × 上限]`,独立展示
- 与询价单:新增 `pricing_method = package_price` + `price_range_min` + `price_range_max` + `final_locked_price` 字段
- 与销售流程:**新增** 销售落价环节(从区间内选一个值定)
- 与客户侧:客户看到区间(如"8-12 万"),销售邮件落定具体值
- 与有效期:期内有效(如 7 天),逾期重算区间(汇率/费率变动时刷新)

| Strategy Pattern(策略模式) | 加新定价方法不动现有公式,像插卡一样往"方法架"上挂 |
| 紧急加价 | 客户要求加急,在标准价基础上加收(独立定价法) |
| 加价率 | 紧急程度的百分比,如 120%(+20%) |
| 加价的钱花在哪 | 加班费 + 外协费 + 违约成本 + 物流加急 |
| VIP 客户价 | 按客户等级给予不同折扣 |
| 客户等级 | 普通/银卡/金卡/钻石/战略 5 级 |
| 客户档案 | 客户主数据(已存在):等级、联系信息、历史记录 |
| 一船一单 | 默认业务模型:一艘船对应一个询价单 |
| 远程诊断定价 | 视频/电话指导,不出场 |
| 询价包干价 | 系统给"8-12 万"区间报价,期内有效 |
| 续约折扣 | 一次性签 N 年维保,年单价递减 |
| 基础因子 | 职级费率/标准工时/数量,推标准价 |
| 影响因子 | 紧急/地点/时间系数,调节最终价(紧急升级独立) |
| 影响系数 K | `Max(地点, 时间)`(紧急退出) |
