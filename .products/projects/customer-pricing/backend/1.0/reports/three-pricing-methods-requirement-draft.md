## 1. 背景与目标

### 1.1 为什么需要这 3 种

客户定价当前是**单一公式**:

```
行金额 = Σ(职级费率 × 人数) × 单件标准工时 × 数量
最终报价 = Max(明细合计, 合计保底价) × 影响系数
```

这意味着所有客户、所有场景的报价规则都一样。但实际业务中,**不同客户类型、不同采购规模、不同紧急程度**,理应有不同的报价规则。

借鉴成本大表的"6 种定价法"框架,我们建议在客户定价增加 3 种**业务场景特有的**定价方法(成本大表的 6 种不全部适用)。

### 1.2 报告范围

**做**:3 种定价法的业务需求规格,含现状分析、需求规格、关键依赖、待拍板事项。

**不做**:不写实现细节(代码、数据表),不写定价公式的数学推导(那是开发的事)。

### 1.3 与借鉴报告的关系

本文是[《客户定价参考成本大表计价逻辑 — 调研报告》](customer-pricing-cost-accounting-reference-report.md) §5.1 的**业务展开**:

- 调研报告 §5.1 提出"借鉴可插拔定价方法"作为 P0 借鉴项
- 本文给出 P0 借鉴项的**业务侧需求草稿**

## 2. 现状盘点:客户定价的"基本盘"

### 2.1 当前计价公式(已实现)

```
行金额 = Σ(职级费率 × 人数) × 单件标准工时 × 数量
合计保底价 = Σ(每项人员配置综合费率 × 最低计费工时)
最终报价 = Max(合计保底价, 明细合计) × 影响系数
影响系数 = Max(紧急系数, 地点系数, 时间系数)
```

### 2.2 已有订单级字段(影响系数三件套)

| 字段               | 当前实现                             | 业务作用         |
| ------------------ | ------------------------------------ | ---------------- |
| **是否紧急** | 不紧急/紧急(可扩展字典)+ 紧急系数    | 反映加急成本     |
| **服务地点** | 大地区 > 国家 > 地点(三级)+ 地点系数 | 反映偏远成本     |
| **服务时间** | 具体日期(派生距询价天数)+ 时间系数   | 反映临近排期成本 |

> **关键发现**:这 3 个字段**本质就是"加价/乘数"机制**,只是当前以"乘在最终报价上"的形式实现。

### 2.3 没有的能力(关键缺口)

| 缺口                                 | 影响                          |
| ------------------------------------ | ----------------------------- |
| ❌**无客户档案**(客户是匿名的) | VIP 客户价无法实现            |
| ❌**无客户等级字段**           | 客户分级定价无法实现          |
| ❌**无批量概念**(船舶单台)     | 批量优惠需重新定义            |
| ❌**无"加价"独立概念**         | 紧急系数只是乘数,不是显式加价 |

### 2.4 与成本大表的对应关系

| 维度         | 成本大表                       | 客户定价 | 借鉴判定                       |
| ------------ | ------------------------------ | -------- | ------------------------------ |
| 多种定价方法 | 6 种                           | 1 种     | **新增 3 种**            |
| 客户分级     | 无                             | 无       | **新增**                 |
| 批量折扣     | 边际成本(船套)                 | 无       | **新增**(需重新定义场景) |
| 紧急加价     | 通过"边际成本"+ "船套回本"表达 | 紧急系数 | **升级为独立定价法**     |

## 3. 定价法 ①:批量优惠

### 3.1 一句话定义

**买得越多/越集中,单价越便宜。**

### 3.2 业务场景

主人明确要求:**两者都考虑**(船队批量 + 单船多项目合并)。

#### 场景 A:船队批量(多艘船同型号)

**业务场景**:

- 某船东公司有 5 艘同型号主机(都是 6S60MC-C)
- 同时需要维保
- 一起询价 → 给予批量折扣

**业务要点**:

- 折扣仅适用于**同型号**(不同型号折扣率不同或不给)
- 折扣随船数增加而加大(阶梯式)

#### 场景 B:单船多项目合并

**业务场景**:

- 同一艘船同时调多个维保类型
- 例:同时做 5年保养 + 健康检查 + 故障排查
- 合并询价 → 给予打包价

**业务要点**:

- 折扣按**项目数**或**总金额**给
- 与"套餐"区别:套餐是预打包推荐,合并是客户临时组合

### 3.3 阶梯式折扣建议(待业务方拍板)

| 船套数 / 项目数 | 折扣率(船队批量) | 折扣率(项目合并) |
| --------------- | ---------------- | ---------------- |
| 1               | 100%             | 100%             |
| 2~5             | 98%              | 95%              |
| 6~10            | 95%              | 90%              |
| 11~20           | 92%              | 85%              |
| 20 以上         | 90%(协议)        | 80%(协议)        |

> **说明**:折扣率为示例,**需业务方按行业惯例拍板**。

### 3.4 怎么算

**总报价计算**(场景 A 船队批量):

```
总报价 = Σ(每艘船的报价 × 该档位折扣率)

例:5 艘同型号,每艘标准价 100 万
   1 ~ 5 艘档位:折扣率 98%
   总报价 = 5 × 100 万 × 98% = 490 万
```

**总报价计算**(场景 B 项目合并):

```
总报价 = Σ(各项目报价) × 合并折扣率

例:同船 3 个项目,合计 100 万
   3 个项目档位:折扣率 90%
   总报价 = 100 万 × 90% = 90 万
```

### 3.5 适用边界

| 适合                   | 不适合                   |
| ---------------------- | ------------------------ |
| 同型号多艘船           | 不同型号混买(折扣率不同) |
| 同船多项目             | 单一项目(无批量可言)     |
| 客户主动询问"批量优惠" | 客户不知情时单方面给折扣 |

### 3.6 关键依赖

| 依赖                | 是否已有 | 说明                                   |
| ------------------- | -------- | -------------------------------------- |
| 询价单关联船名/船舶 | ✅ 已有  | 询价单可填船名(选填)                   |
| 同型号识别          | ✅ 已有  | 询价单可识别型号                       |
| 多船合并询价流程    | ❌ 缺失  | 需新增"合并询价"流程或允许多询价单关联 |
| 折扣率配置          | ❌ 缺失  | 需后台加"批量折扣率配置"页             |
| 折扣率计算逻辑      | ❌ 缺失  | 需新增"批量优惠定价法"                 |

### 3.7 待业务方拍板

| # | 决策点                              | 选项                                                                     | 建议                            |
| - | ----------------------------------- | ------------------------------------------------------------------------ | ------------------------------- |
| 1 | 是否同时支持"船队批量"和"项目合并"? | A. 两者都做 / B. 只做船队 / C. 只做项目合并                              | **A. 两者都做**(主人确认) |
| 2 | 折扣率谁配?                         | A. 运营配 / B. 业务方配 / C. 系统默认值                                  | **A. 运营配**(灵活)       |
| 3 | 折扣率按什么定?                     | A. 数量阶梯 / B. 总金额阶梯 / C. 两者结合                                | **A. 数量阶梯**(简单)     |
| 4 | "多船合并询价"如何实现?             | A. 一个询价单支持多艘船 / B. 多个询价单关联 / C. 不支持,只支持"项目合并" | **C**(避免大改流程)       |

## 4. 定价法 ②:VIP 客户价

### 4.1 一句话定义

**同一产品,对不同等级的客户报不同价。**

### 4.2 业务场景

```
普通客户问:"这个多少钱?"
销售:"标准价 100 万。"

金卡客户问:"这个多少钱?"
销售:"金卡价 90 万,给您 9 折。"

战略客户问:"这个多少钱?"
销售:"按协议价(单谈)。"
```

### 4.3 关键发现:客户档案缺失

**当前系统没有"客户档案"主数据**。

调研确认:

- 客户是匿名的(船东 / 船管公司)
- 询价单只有"船名"字段(选填),不存客户实体
- 没有客户等级、客户类型、客户标签字段

**这意味着**:

- VIP 客户价**不能简单加一个字段**就实现
- 需要**从零建"客户档案"主数据**,这是个大改造

### 4.4 客户档案应包含什么(建议)

```
客户档案(Customer):
├─ 客户编号(系统生成)
├─ 客户名称(船东/船管公司全称)
├─ 联系人 / 联系方式
├─ 客户等级(字典:普通/银卡/金卡/钻石/战略)
├─ 评定日期(等级评定时间)
├─ 保级日期(下次复评时间)
├─ 历史询价记录(关联)
├─ 历史订单记录(关联)
└─ 备注
```

### 4.5 等级与折扣建议(待业务方拍板)

| 等级               | 折扣率 | 评定标准(建议)                         |
| ------------------ | ------ | -------------------------------------- |
| **普通客户** | 100%   | 默认                                   |
| **银卡**     | 95%    | 年度询价 ≥ 3 次 或 累计金额 ≥ 50 万  |
| **金卡**     | 90%    | 年度询价 ≥ 5 次 或 累计金额 ≥ 200 万 |
| **钻石 VIP** | 85%    | 战略合作客户(单独评定)                 |
| **战略客户** | 协议价 | 不参与折扣,按协议单独定价              |

### 4.6 怎么算

**直接打折**:

```
VIP 报价 = 标准价 × VIP 折扣率

例:标准价 100 万
   普通:100 × 100% = 100 万
   银卡:100 × 95%  = 95 万
   金卡:100 × 90%  = 90 万
   钻石:100 × 85%  = 85 万
   战略:协议价(另算)
```

### 4.7 适用边界

| 适合                 | 不适合                     |
| -------------------- | -------------------------- |
| 长期合作的客户       | 一次性匿名客户             |
| 客户有明确等级       | 新客户(无等级)             |
| 同产品不同客户不同价 | 同一客户同一产品只能一个价 |

### 4.8 关键依赖(重要)

| 依赖                     | 是否已有         | 说明                 |
| ------------------------ | ---------------- | -------------------- |
| **客户档案主数据** | ❌**缺失** | **前置改造**   |
| 客户等级字典             | ❌ 缺失          | 需新建               |
| 等级评定规则             | ❌ 缺失          | 需业务方拍板         |
| 询价单关联客户           | ❌ 缺失          | 询价单要能选客户档案 |
| 折扣率配置               | ❌ 缺失          | 需后台加配置         |
| VIP 定价法               | ❌ 缺失          | 需新增               |

### 4.9 待业务方拍板

| # | 决策点                | 选项                                        | 建议                             |
| - | --------------------- | ------------------------------------------- | -------------------------------- |
| 1 | 是否做客户档案?       | A. 做 / B. 暂缓                             | **A. 做**(VIP 必需)        |
| 2 | 等级体系如何定?       | A. 4 级 / B. 5 级(含战略)/ C. 自定义        | **B. 5 级**(灵活)          |
| 3 | 等级谁评定?           | A. 运营 / B. 销售副总 / C. 系统自动(按规则) | **C. 系统自动 + 运营复核** |
| 4 | 等级多久复评?         | A. 半年 / B. 一年 / C. 不定期               | **B. 一年**                |
| 5 | 战略客户是否参与折扣? | A. 不参与(协议价)/ B. 参与(协议折扣率)      | **A. 不参与**              |

## 5. 定价法 ③:紧急加价

### 5.1 一句话定义

**客户要得急,加价;要得不急,原价。**

### 5.2 业务场景

```
客户:"我下周一就要,来得及吗?"
销售:"常规交期 30 天,加急 7 天,但要加 20% 费用。"

客户:"20% 太贵,30 天就 30 天吧。"
```

### 5.3 现状:已有雏形,但不完整

**当前系统已有"是否紧急"字段**(业务梳理 v1.11 新增,影响系数三件套之一):

| 维度         | 现状                               |
| ------------ | ---------------------------------- |
| 字段         | "是否紧急"(不紧急/紧急,可扩展字典) |
| 系数         | "紧急系数"(运营配置)               |
| 作用方式     | 乘在最终报价上(Max 合成)           |
| 业务梳理定位 | "反映加急成本的服务条件调节"       |

**问题**:

- 当前是"乘数",不是"加价" — 加价 = 涨价的具体金额,乘数 = 乘以系数
- 没有明确的"加价率"概念
- 没有"加价的钱花在哪"的成本说明

### 5.4 升级为正式定价法

把现有的"紧急系数"机制**升级**为"紧急加价"定价法:

| 维度     | 现状(乘数)           | 升级后(定价法)             |
| -------- | -------------------- | -------------------------- |
| 触发     | 是否紧急字段         | 是否紧急字段(沿用)         |
| 计算     | 紧急系数 × 最终报价 | **加价率** × 标准价 |
| 客户看到 | 影响系数(订单级乘数) | "紧急加价"独立行           |
| 销售邮件 | 加价理由说明         | 加价金额 + 加价理由        |

### 5.5 加价率建议(待业务方拍板)

| 紧急程度             | 加价率       | 业务场景              |
| -------------------- | ------------ | --------------------- |
| **不紧急**     | 100%(无加价) | 标准价,按正常交期     |
| **紧急**       | 120%(+20%)   | 缩短交期一半          |
| **非常紧急**   | 150%(+50%)   | 周末加班,占用其他资源 |
| **特急(灾难)** | 协议价       | 按项目单谈,不进系统   |

### 5.6 加价的钱花在哪(成本结构)

紧急加价的**合理性**来源于这些真实成本:

| 成本项           | 说明                           |
| ---------------- | ------------------------------ |
| 加班费           | 周末/夜间工作的额外人工费      |
| 外协费           | 临时外请外部资源的费用         |
| 其他订单违约成本 | 因加急占用资源导致其他订单延误 |
| 物流加急费       | 加急运输、临时仓储             |

> **关键**:**加价要反映"真实成本"**,而不是"趁机涨价"。加价率需要业务方基于实际成本测算拍板。

### 5.7 怎么算

**乘法加价**:

```
紧急加价金额 = 标准价 × (加价率 - 1)

例:标准价 100 万
   不紧急:100 × 0%   = 0(不加价)
   紧急:100 × 20%  = 20 万加价
   非常紧急:100 × 50% = 50 万加价

紧急报价 = 标准价 + 加价金额
   = 100 万 + 20 万 = 120 万(紧急)
   = 100 万 + 50 万 = 150 万(非常紧急)
```

### 5.8 适用边界

| 适合                 | 不适合                   |
| -------------------- | ------------------------ |
| 客户主动要求加急     | 销售为了接单擅自承诺加急 |
| 工厂确实能压缩交期   | 加急导致其他订单延误     |
| 加价幅度能被客户接受 | 客户对价格极度敏感       |

### 5.9 与现有"影响系数"的关系

**关键澄清**:**不要与现有"紧急系数"混为一谈**。

| 现有"紧急系数"           | 新增"紧急加价"               |
| ------------------------ | ---------------------------- |
| 是"乘数"(乘在最终报价上) | 是"独立定价法"(算出独立报价) |
| 影响系数的一部分         | 完整定价方法                 |
| 客户看不到(进后台)       | 客户可看到"紧急加价"行       |
| 销售邮件里说明           | 销售邮件里明示金额           |

**业务方需要拍板**:**两者共存还是替换?**

- A. 共存:影响系数用于"服务条件"调节(紧急/地点/时间),紧急加价是独立定价法
- B. 替换:取消现有"紧急系数",全部用"紧急加价"
- **建议:A. 共存**(影响系数保留,新增"紧急加价"作为独立定价法)

### 5.10 关键依赖

| 依赖               | 是否已有 | 说明                 |
| ------------------ | -------- | -------------------- |
| 是否紧急字段       | ✅ 已有  | 沿用                 |
| 紧急系数配置       | ✅ 已有  | 影响系数页已有       |
| 加价率配置         | ❌ 缺失  | 需新增配置页         |
| 加价金额计算       | ❌ 缺失  | 需新增               |
| 加价独立展示       | ❌ 缺失  | 预算页加"紧急加价"行 |
| 与现有影响系数共存 | ❌ 待定  | 需业务方拍板         |

| 2 | 字典如何分?         | A. 不紧急/紧急/非常紧急(3 档)/ B. 5 档 | **A. 3 档**(简单)                      |
| 3 | 与现有影响系数关系? | A. 共存 / B. 替换                      | **A. 共存**                            |
| 4 | 加价金额给客户看吗? | A. 给 / B. 不给(进后台)                | **B. 不给**(沿用 D17 客户侧只看最终价) |
| 5 | 加价的钱花在哪说明? | A. 进销售邮件 / B. 后台可见            | **A. 进销售邮件**                      |

## 6. 3 种定价法的对比与组合

### 6.1 业务场景对比

| 维度                         | 批量优惠  | VIP 客户价       | 紧急加价     |
| ---------------------------- | --------- | ---------------- | ------------ |
| **触发因素**           | 数量/船数 | 客户等级         | 紧急程度     |
| **业务本质**           | 量价关系  | 客户关系         | 时间关系     |
| **适合客户类型**       | 船队/批量 | 长期合作         | 任何(临时的) |
| **决策权**             | 运营/销售 | 系统(按等级)     | 客户自选     |
| **与现有影响系数关系** | 独立      | 独立             | 共存(同维度) |
| **改造复杂度**         | 中        | 高(需建客户档案) | 低           |

### 6.2 三者如何组合

**关键规则**:**同一报价只能选 1 种主定价法**,但附加项可叠加。

```
标准价
   ├─ 应用 VIP 折扣(看客户等级)
   ├─ 应用批量折扣(看数量)
   └─ 应用紧急加价(看紧急程度)

但:
   - VIP 折扣与批量折扣:不可叠加(待业务方拍板)
   - 紧急加价与 VIP/批量:可叠加(加价独立)
```

### 6.3 典型组合示例

| 场景                      | 用哪些                                |
| ------------------------- | ------------------------------------- |
| VIP 金卡客户买 1 台,不急  | VIP 客户价                            |
| 普通客户 5 艘同型号,不急  | 批量优惠(船队)                        |
| 普通客户 1 台,1 项目,紧急 | 紧急加价                              |
| VIP 金卡客户买 5 艘,紧急  | 批量优惠 + 紧急加价(VIP 不与批量叠加) |
| 战略客户,任何场景         | 协议价(不走系统)                      |

## 7. 优先级与工作量

### 7.1 建议优先级

| 优先级       | 定价法                | 工作量               | 建议                        |
| ------------ | --------------------- | -------------------- | --------------------------- |
| **P0** | 紧急加价              | 1 周                 | 先做,改造小,业务可见        |
| **P1** | 客户档案(为 VIP 铺路) | 2 周                 | 必须做,否则 VIP 无法实现    |
| **P1** | VIP 客户价            | 1 周(在 P1-1 基础上) | 客户档案建好即可做          |
| **P2** | 批量优惠              | 2 周                 | 业务流程需重新设计,建议后置 |
| **P2** | 船队批量/项目合并细分 | 1 周                 | 待业务方拍板                |

### 7.2 关键里程碑

| 时间 | 里程碑                                          |
| ---- | ----------------------------------------------- |
| W1   | 紧急加价上线(沿用是否紧急字段,新增加价率配置)   |
| W2   | 客户档案主数据完成(基础 CRUD + 等级字段)        |
| W3   | VIP 客户价上线(询价单关联客户档案,自动应用折扣) |
| W4   | 批量优惠业务设计拍板(船队/项目合并)             |
| W5   | 批量优惠上线                                    |

### 7.3 数据迁移

| 迁移项             | 策略                          |
| ------------------ | ----------------------------- |
| 现有询价单关联客户 | 默认"匿名客户",后续手动补关联 |
| 现有询价单加价     | 默认"不紧急",不加价           |
| 现有询价单批量     | 不适用(无批量概念)            |

## 8. 关键依赖与限制

### 8.1 前置依赖

| # | 前置项                   | 影响           | 应对             |
| - | ------------------------ | -------------- | ---------------- |
| 1 | **客户档案主数据** | VIP 客户价必需 | P1 阶段先建      |
| 2 | 询价单关联客户           | VIP 必需       | 客户档案建好后做 |
| 3 | 批量场景拍板             | 批量优惠必需   | 业务方评审明确   |
| 4 | 加价率配置               | 紧急加价必需   | 后台加配置页     |

### 8.2 与现有功能的关系

| 现有功能                           | 关系                                        |
| ---------------------------------- | ------------------------------------------- |
| **影响系数**(紧急/地点/时间) | 紧急加价与"紧急系数"维度重叠,建议共存不替换 |
| **保底价**                   | 独立机制,与 3 种新定价法正交                |
| **职级口径**                 | 独立机制,不受影响                           |
| **询价单快照**               | 3 种定价法的结果都进快照                    |

### 8.3 风险与缓解

| 风险           | 缓解                                   |
| -------------- | -------------------------------------- |
| 客户档案缺失   | P1 阶段必须建,否则 VIP 无法实现        |
| 批量场景不清   | 业务方评审时先拍板"船队 vs 项目合并"   |
| 加价率拍板困难 | 业务方按"真实成本"测算,而不是拍脑袋    |
| 与影响系数冲突 | 共存方案:系数管"服务条件",加价管"加急" |

## 10. 附录:与成本大表 6 种定价法对照

| # | 成本大表方法   | 客户定价是否借鉴 | 说明                         |
| - | -------------- | ---------------- | ---------------------------- |
| 1 | 成本加成       | ❌ 不适用        | 客户定价无成本加成场景       |
| 2 | 市场导向       | ❌ 不适用        | 客户定价无市场对比           |
| 3 | 边际成本(船套) | ⚠️ 部分借鉴    | 船队批量类似,但不是船套      |
| 4 | 效用           | ❌ 不适用        | 客户定价无按用量计费         |
| 5 | 自定义         | ✅ 沿用          | 客户定价已有"自定义"附加项   |
| 6 | 其他费用/佣金  | ✅ 沿用          | 客户定价已有"代理佣金"附加项 |

**核心结论**:**成本大表的 6 种方法不直接适用**,但其**"可插拔"框架思想**值得借鉴。客户定价需要的 3 种(批量/VIP/紧急)是**业务场景特有的**,而非照搬成本大表。

## 附录:术语表

| 术语       | 解释                                          |
| ---------- | --------------------------------------------- |
| 批量优惠   | 同一型号多艘船 或 单船多项目合并询价,给与折扣 |
| VIP 客户价 | 按客户等级给予不同折扣                        |
| 紧急加价   | 客户要求加急,在标准价基础上加收               |
| 加价率     | 紧急程度的百分比,如 120%(+20%)                |

| 客户档案   | 客户主数据,包含等级、联系信息、历史记录       |
| 船队批量   | 多艘同型号船一起询价的批量优惠                |
| 项目合并   | 单船多个维保项目一起询价的批量优惠            |
| 战略客户   | 单独议价的客户,不参与系统折扣                 |
