## 3. 核心业务理解(必须懂)

### 3.1 成本大表是什么

公司内部"做一笔生意要花多少钱、卖多少钱"的完整记录与定价系统。

**核心组成**:
- 5 个业务阶段(需求对接 / 规划与设计 / 生产 / 交付与实施 / 售后维护)
- 3 个部门(销售 / 采购 / 生产)
- 16 项成本(从 5 × 3 矩阵"有活干"的格子得来)
- 6 种定价方法(4 主方法 + 2 附加项)
- 4 级审批(销售 → 部长 → 副总 → 总裁)
- 9 状态流转(从发起到完成)
- 跨币种 + 汇率快照(报价有依据)

### 3.2 客户定价是什么

船舶维保场景的客户自助询价系统。客户(船东/船管)在嵌入页面自助完成"选设备 → 填需求 → 选方案 → 看预算 → 提交询价",系统实时算出预算,生成询价单邮件推送给销售跟进。

**当前计价公式**(单一):
```
行金额 = Σ(职级费率 × 人数) × 单件标准工时 × 数量
最终报价 = Max(明细合计, 合计保底价) × 影响系数
影响系数 = Max(紧急系数, 地点系数, 时间系数)
```

**关键发现**:
- **客户档案主数据没有**(客户是匿名的)
- **客户等级字段没有**(无 VIP 机制)
- **批量概念没有**(船舶单台大件)
- **加价概念没有**(现有紧急系数只是乘数)

## 4. 借鉴方案结论(调研报告核心)

### 4.1 可借鉴 2 项

| 借鉴项 | 业务价值 | 优先级 |
|---|---|---|
| **定价方法"可插拔"** | 当前单一公式升级为可切换的多种方法 | **P0** |
| **跨币种 + 汇率快照** | 支持国外客户用本币询价 | **P1** |

### 4.2 不建议借鉴 3 项

| 不借鉴 | 原因 |
|---|---|
| 4 级内部审批 | 客户询价是参考,最终报价销售人工确认 |
| 16 项成本类型 | 客户侧不需要看成本构成(D17 已决策) |
| 多部门并行填 | 客户侧无此场景 |

### 4.3 核心判断原则

**借鉴"设计思想"(可切换、快照),不复制"业务流程"(多级审批、多部门协同)。**

## 5. 3 种新定价法(需求草稿核心)

调研报告 §5.1 提到客户定价可加 3 种业务场景特有的定价方法:

| # | 定价法 | 业务定义 | 复杂度 | 优先级 |
|---|---|---|---|---|
| 1 | **批量优惠** | 买得越多越便宜 | ⭐⭐ 中 | P2 |
| 2 | **VIP 客户价** | 同产品对不同等级客户不同价 | ⭐⭐⭐ 高 | P1 |
| 3 | **紧急加价** | 加急加价,标准价基础上加收 | ⭐ 低 | P0 |

### 5.1 紧急加价(P0,1 周)

**沿用现有"是否紧急"字段**,升级为正式定价法:
- 3 档:不紧急 / 紧急(+20%) / 非常紧急(+50%)
- 加价率后台可配
- 建议与现有"紧急系数"**共存**(系数管服务条件,加价管加急)

### 5.2 VIP 客户价(P1,3 周含前置)

**核心难点**:**客户档案主数据缺失**,需从零建。

**前置工作**:
1. 建客户档案主数据(P1-1,2 周)
2. 加客户等级字段 + 评定规则
3. 询价单关联客户档案
4. VIP 折扣率配置 + 自动应用

### 5.3 批量优惠(P2,2 周)

**船舶场景需重新定义**:
- **船队批量**:多艘同型号船一起询价
- **单船多项目合并**:同船多个维保类型一起询价

**关键决策点**:"多船合并询价"是新流程还是改造旧流程?

## 6. 待业务方拍板(共 15 项)

### 6.1 批量优惠(B1-B4)

- **B1**:是否同时支持"船队批量"和"项目合并"? → **建议:两者都做**
- **B2**:折扣率谁配? → **建议:运营配**
- **B3**:折扣率按什么定? → **建议:数量阶梯**
- **B4**:"多船合并询价"如何实现? → **建议:不做,只支持项目合并**(避免大改流程)

### 6.2 VIP 客户价(V1-V5)

- **V1**:是否做客户档案? → **建议:做(VIP 必需)**
- **V2**:等级体系如何定? → **建议:5 级(普通/银卡/金卡/钻石/战略)**
- **V3**:等级谁评定? → **建议:系统自动 + 运营复核**
- **V4**:等级多久复评? → **建议:一年**
- **V5**:战略客户是否参与折扣? → **建议:不参与(协议价)**

### 6.3 紧急加价(U1-U6)

- **U1**:加价率如何配? → **建议:运营配**
- **U2**:字典如何分? → **建议:3 档(不紧急/紧急/非常紧急)**
- **U3**:与现有影响系数关系? → **建议:共存(系数管服务条件,加价管加急)**
- **U4**:加价金额给客户看吗? → **建议:不给(沿用 D17 客户侧只看最终价)**
- **U5**:加价的钱花在哪说明? → **建议:进销售邮件**
- **U6**:字典是否扩"非常紧急"? → **建议:是**

**详细说明见**[需求草稿 §9](../../../Backend/customer-pricing/docs/reports/three-pricing-methods-requirement-draft.md)。

## 10. 关键术语(快速对齐口径)

| 术语 | 解释 |
|---|---|
| 成本大表 | 公司内部定价系统(5 阶段 + 3 部门 + 16 成本 + 6 定价法) |
| 客户定价 | 船舶维保询价系统(船东/船管自助询价) |
| 6 种定价法 | 4 主方法 + 2 附加项(成本加成/市场导向/边际成本/效用 + 自定义/其他费用) |
| 借鉴 | 学习设计思想,不复制业务流程 |
| 主报价方法 | 一份报价的主体定价方法(6 种里 4 选 1) |
| 附加项 | 挂在主报价上的额外费用(2 种可叠加) |
| 修正定价 | 销售谈判后改的实际价格 |
| 4 级审批 | 销售→部长→副总→总裁,各填各的实际售价 |
| 9 状态 | 项目从发起到完成的 9 个状态节点 |
| 汇率快照 | 在"开始定价"时锁定的汇率,后续不变 |
