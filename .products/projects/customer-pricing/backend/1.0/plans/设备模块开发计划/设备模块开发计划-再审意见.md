## 3. 中等问题(本次新增)

### M3. 父分类停用时设备可见性传播语义未明

| 字段 | 内容 |
|------|------|
| 现象 | BR-EQ-02 仅定义"父分类必须存在、未删除、未停用"(新增校验)。停用父分类后,设备本身是否隐藏?nav-tree 中是否消失?by-category 是否仍可调?均未显式说 |
| 隐含语义(demo 推演) | demo 设备分类停用 → 整个分支前台不可见 → 设备叶子也跟着隐藏。这是 nav-tree 内存传播的天然结果,但 plan §6.2/§6.3 没写明 |
| 风险 | 前端拿到 by-category/{categoryId} 接口,父分类已停用时返回空还是抛异常?需要 plan 拍板 |
| 应对 | §3 新增 BR-EQ-09:父分类停用后,设备 by-category 不可见 / nav-tree 该节点隐藏;§6.2 by-category 显式说"父分类停用时按空集处理"或"按 4xx 拒绝" |
| 触发节点 | T1 启动前 |

### M4. 重命名时设备名是否查重未明

| 字段 | 内容 |
|------|------|
| 现象 | BR-EQ-03 写"中文名必填(≤100 字);英文名选填(≤200 字);中英文均参与列表关键词过滤";IN-EQ-05 同义。/rename 接口未提查重 |
| 同构对比 | manufacturer 有中文名精确查重(BR-MFR-03 + IN-MFR-02),设备 plan 漏拍 |
| 风险 | 同分类下两个设备都叫"主机柴油机",前端列表关键词过滤时无法区分 |
| 应对 | §3 新增 BR-EQ-x + IN-EQ-x:重命名是否查重(同分类下?全局?允许重名?)。默认口径建议:同 category_id 下中文名精确查重(对齐 manufacturer 模式),英文名不查重 |
| 触发节点 | T1 启动前拍板 |

### M5. by-category 接口未校验父分类状态

| 字段 | 内容 |
|------|------|
| 现象 | §6.2 `/web/portal/equipment/by-category/{categoryId}` 返回"仅启用设备(id/code/name/nameEn/categoryId,按 code 排序)"。没校验父分类是否存在/启用/未删除 |
| 风险 | 前端传停用分类 id → 返回该分类下启用设备(子表维度正确,但父已停用,语义不当);前端传已删除分类 id → 返回空集(无提示)|
| 应对 | §6.2 接口契约加一行:父分类不存在/已删除 → 抛 803120302;父分类已停用 → 抛 803120303 或按空集处理(对齐 M3) |
| 触发节点 | T3/T5 接口实现前 |

### M6. 设备目录 nav-tree 与本模块 nav-tree 数据源重叠,需明确职责

| 字段 | 内容 |
|------|------|
| 现象 | 设备分类 plan §6.2 `/web/portal/equipment-category/nav-tree` 返分类节点;设备 plan §6.2 `/web/portal/equipment/nav-tree` 返"分类+设备叶子完整树"。两份 nav-tree 各自从零组树,数据源重叠(都需读 wk_equipment_category)|
| 风险 | 两接口性能不一致;缓存策略难统一;前端不知道调哪个 |
| 应对 | 选 A(选 M1 选项 A)后,设备分类 nav-tree 退役,设备 nav-tree 是唯一权威;或两接口职责切分(分类 nav-tree = 仅分类,设备 nav-tree = 仅设备数组)— 需要 plan 显式说 |
| 触发节点 | T0 之前(与 M1 联动拍板) |

## 4. 轻微问题(顺手补)

### C1. T5 前台工时 0.5d 可能偏紧

| 字段 | 内容 |
|------|------|
| 现象 | T5 = 0.5d,含 2 个 portal 接口(by-category + nav-tree)。nav-tree 联合 wk_equipment_category + wk_equipment 查询 + 内存组树 + 启用过滤 + 路径拼接,工作量与设备分类 T5(2 接口含 search 路径生成)等量级 |
| 同构对比 | 设备分类 T5 = 0.5d(2 接口:nav-tree + search),设备 T5 = 0.5d(2 接口:by-category + nav-tree)。nav-tree 联合查询比单表组树稍重 |
| 建议 | T5 调到 1d(0.5d→1d),总工时 5.5d→6d。可接受范围 |
| 触发节点 | v1.1 修订 |

### C2. EquipmentTreeNodeDo 与 EquipmentTreeNodeBo 两个树节点命名歧义

| 字段 | 内容 |
|------|------|
| 现象 | §5.2 同时列 `EquipmentTreeNodeDo.java`(domain 层,nav-tree 节点)和 `EquipmentTreeNodeBo.java`(app 层,分组树节点),命名相似但语义不同 |
| 风险 | 后续维护易混;domain 层 Do 和 app 层 Bo 应该是同构转换关系,但 plan 没显式说 |
| 建议 | §5.2 加 1 句:EquipmentTreeNodeDo 用于 nav-tree 树节点(含分类路径 + 设备数组);EquipmentTreeNodeBo 用于 /list groupBy=category 返回的嵌套结构(轻量,只含 categoryId + equipments)。命名差异合理,但要写明语义 |
| 触发节点 | T1/T3 实现时 |

### C3. 并发兜底路径接口层未显式说

| 字段 | 内容 |
|------|------|
| 现象 | BR-EQ-01 + IN-EQ-01 应用层预校验,uk_code 兜底。/add 接口在并发场景下,两事务同时取 max=5 都生成 X.006,入库时 1 成功 1 抛 uk_code 异常 |
| 风险 | 异常翻译路径(数据库 DuplicateKey → EquipmentExceptionEnum 编码重复 803120301)未在 plan 显式说 |
| 建议 | §8 T2 仓储层任务加 1 句:AccessorImpl 翻译 DuplicateKeyException 为 EquipmentExceptionEnum 编码重复 |
| 触发节点 | T2 实现 |

### C4. EquipmentDomainService 漏写父前缀校验(IN-EQ-07)

| 字段 | 内容 |
|------|------|
| 现象 | §5.1 EquipmentDomainService 方法清单:code 生成(父 code + 3 位序号)、父分类存在性 + 启用态校验、name 校验。IN-EQ-07 父前缀校验(防御)在 §5.1 漏写 |
| 建议 | §5.1 加 1 行:父 code 前缀校验(IN-EQ-07,防止人工绕过) |
| 触发节点 | T1 实现 |

### C5. 操作人快照注入点未显式

| 字段 | 内容 |
|------|------|
| 现象 | BR-EQ-08 + AGENTS §4.2 写"操作人快照",但 §5/§8 没说在哪一层注入 |
| 同构对比 | 已交付 manufacturer 在 RepositoryImpl 写操作时统一注入(已查包结构)|
| 建议 | §5.2 / §8 T2 加 1 句:操作人快照在 EquipmentRepositoryImpl 写操作时由 `UserInfoUtil.getInternalUser()` 取值,统一注入 create_operator/update_operator JSON |
| 触发节点 | T2 实现 |
