## 1. 背景与定位

型号（model）是**设备目录的第四个维护对象**（FR-07 维护顺序：① 厂家 → ② 设备分类树 → ③ 设备 → **④ 型号**），是型号级标准工时配置（labor_standard_model，v1.4 取代已退役的 model_group）的载体，也是询价页选型号 + 默认厂家联动（R-04）的数据源。

- **R-01（硬性规则，继承自设备/分类）**：设备目录不参与定价。型号是设备下的具体机型（含缸数等规格属性），模块内不得出现价格/工时/费率字段；型号是设备（聚合根）的**从属实体**，归属设备（`equipment_id`）。
- **R-02（硬性规则）**：型号直接挂设备下平铺展示，**无系列层级**（D1 已决）；型号组 `model_group` 已于 v1.4 退役（IN-EQ-05 作废），缸径系列共享工时改由 `labor_standard_model` 型号级多选配置直接承载。
- **R-03 / R-04**：型号-厂家**多对多**关联（含 is_license 授权生产标记），可选 `default_manufacturer_id` 字段手动指定默认厂家；**默认厂家必须在关联集合内**（IN-EQ-04）；**价格与厂家无关**——厂家字段不参与计价。
- **R-05**：缸数（cylinder_count）是型号固有属性，1–20 整数（D3 已决）；选型号自动带出、只读；**「自定义型号」才允许手填**（本期按「必填」处理，与设备 v1.4 一致）。
- **数据模型定位**（§3.4/§3.5 ER）：
  - `equipment "1" --> "*" model : 归属`（FK→wk_equipment.id）
  - `model "1" *-- "*" model_manufacturer : 组合-关联实体`（FK→wk_model.id + wk_manufacturer.id）
  - `model "0..1" ..> manufacturer : 默认厂家`
- **依赖**：设备分类 ✅（父设备走 equipment_id 间接链路）+ 厂家 ✅（关联与默认）+ 设备 ✅（FK）。后续依赖方：设备-维保类型挂载（依赖设备 + 维保类型）、标准工时 labor_standard / labor_standard_model（型号级配置 M1 落两级回溯）、套餐 / 展示规则 / 建议项规则（型号级 / 设备级）。
- **里程碑**：M1（目录 + 工时定价），设备目录 6 表完成第 4、5 张（model + model_manufacturer）。

## 3. 业务规则基线

> 编号 BR-MOD-xx，源自 R-01～R-06 + IN-EQ-01/02/04 + demo 行为提炼，写代码注释/测试名时引用。

| 编号       | 规则                                                                                                                                  |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| BR-MOD-01  | 型号 code 由系统自动生成：`MOD` + 4 位递增序号（MOD0001、MOD0002…），全局唯一，**删除后序号不复用**（取现存最大 +1），禁止手填；name 可改 |
| BR-MOD-02  | 所属设备必须存在、未删除、未停用（status=1）；停用父设备时新增型号被拒，提示「父设备已停用，请先启用」                                  |
| BR-MOD-03  | 中文名必填（≤100 字）；英文名选填（≤200 字）；中英文均参与列表关键词过滤（不区分大小写）                                              |
| BR-MOD-04  | 缸数（cylinder_count）必填，1–20 整数（R-05/D3）；power_kw / bore_mm / mark 选填（power_kw DECIMAL(10,2)，bore_mm INT，mark VARCHAR(50)）|
| BR-MOD-05  | `status`：1=启用 0=停用。停用后前台 by-equipment 不可见、list-enabled 不含；后台 `/list` 仍可见（前端置灰）；可重新启用                  |
| BR-MOD-06  | 删除采用逻辑删除（state=3）；**设备「被型号关联不可删」**（BR-EQ-05 补账落地）+ **厂家「被型号关联不可删」**（BR-MFR-06 补账落地）       |
| BR-MOD-07  | 跨模块补账——本模块完成后，**解除设备模块**删除校验的型号维度前置锁；**厂家模块**删除校验需检查「存在未删除型号引用 → 拒绝」               |
| BR-MOD-08  | 型号不参与任何定价解析：模块内零定价字段/计价引用；与产品分离（R-01）                                                                 |
| BR-MOD-09  | 型号-厂家**多对多**关联；至少一个关联厂家；**默认厂家 ∈ 关联集合**（IN-EQ-04）；新增型号时若未指定默认厂家，前端默认选中关联集合第一家     |
| BR-MOD-10  | 关联表（wk_model_manufacturer）含 is_license（1=授权生产 0=自有，默认 0）+ sort_order（INT，默认 99 = 置后；展示时按 ASC 排序）          |
| BR-MOD-11  | **父设备停用时前台可见性传播**：by-equipment 接口按「前台可见性约定」对型号做隐藏/返空集处理（与设备 BR-EQ-09 / 设备分类 BR-CAT-05 同款）|
| BR-MOD-12  | **切换设备（IN-EDT-03 联动）**：编辑时可改归属设备；若原默认厂家不在新设备下关联集合（极少见，仅厂家被新设备下其他型号移除），自动重置     |
| BR-MOD-13  | 关联增量 add/remove（对齐 demo `mdlVendorsHtml` 草稿模式）：删除关联后若该型号无关联厂家 → 拒绝；移除 default_manufacturer_id 关联后自动重置为剩余第一家 |
| BR-MOD-14  | **同设备下中文名精确查重**（对齐设备 BR-EQ-10）：同设备下不允许重名，跨设备允许重名；应用层预校验 + uk_equipment_name(equipment_id, name) 唯一约束兜底 |
| BR-MOD-15  | 名称修改（IN-NAM-01：code 不可变，但 name 可改）：name 改了 → labor_standard_model.models 等下游快照受影响，本期**仅在文档/注释标注**，实际级联更新待 labor_standard_model 模块落地（IN-EDT-03 联动） |
| BR-MOD-16  | **编辑型号缸数 / 切换设备 / 修改规格字段**：缸数变了 → labor_standard_model.cylinder_count 引用（如有）受影响；本期**仅在文档/注释标注补账点**，实际级联待工时计价模块 |
| BR-MOD-17  | 所有写操作记录操作人快照（platform operator 快照列）+ `log.info` 关键节点日志                                                       |
| BR-MOD-18  | mark 字段为 mark/版本号（如 C9.7），可空；不参与任何业务逻辑，仅展示/检索用                                                        |

## 4. 数据模型设计

### 4.1 wk_model 建表 SQL（对齐设计文档 §6.2.4 + 工程表惯例）

> 惯例同 `wk_equipment_category` / `wk_manufacturer` / `wk_equipment`：`wk_` 前缀、`state` 逻辑删除位、`create_time/create_operator/update_time/update_operator` 平台快照列替代设计文档的 `created_at/updated_at`；业务字段原样保留。

```sql
-- 型号（设备下的具体机型；不参与定价，R-01；含缸数属性，D3）
CREATE TABLE IF NOT EXISTS `wk_model`
(
    `id`                      BIGINT                          NOT NULL AUTO_INCREMENT COMMENT '主键id',
    `code`                    VARCHAR(50)                     NOT NULL COMMENT '型号编码，系统生成 MOD+4位序号，全局唯一（BR-MOD-01）',
    `equipment_id`            BIGINT                          NOT NULL COMMENT '所属设备id（FK→wk_equipment.id）',
    `default_manufacturer_id` BIGINT                          NULL     DEFAULT NULL COMMENT '默认厂家id（FK→wk_manufacturer.id，IN-EQ-04 必属关联集合）',
    `name`                    VARCHAR(100)                    NOT NULL COMMENT '型号中文名',
    `name_en`                 VARCHAR(200)                    NULL     DEFAULT NULL COMMENT '型号英文名',
    `mark`                    VARCHAR(50)                     NULL     DEFAULT NULL COMMENT 'mark/版本号（如 C9.7），选填',
    `cylinder_count`          INT                             NOT NULL COMMENT '缸数，1-20（R-05/D3）',
    `power_kw`                DECIMAL(10,2)                   NULL     DEFAULT NULL COMMENT '功率kW（可选维度）',
    `bore_mm`                 INT                             NULL     DEFAULT NULL COMMENT '缸径mm（可选维度）',
    `status`                  TINYINT                         NOT NULL DEFAULT 1 COMMENT '业务状态：1启用 0停用',
    `state`                   TINYINT                         NOT NULL DEFAULT 1 COMMENT '数据状态：1.启用 2.冻结 3.删除',
    `create_time`             DATETIME                        NULL     DEFAULT NULL COMMENT '创建时间',
    `create_operator`         JSON                            NULL     DEFAULT NULL COMMENT '创建人快照',
    `update_time`             DATETIME                        NULL     DEFAULT NULL COMMENT '更新时间',
    `update_operator`         JSON                            NULL     DEFAULT NULL COMMENT '更新人快照',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_code` (`code`),
    UNIQUE KEY `uk_equipment_name` (`equipment_id`, `name`) COMMENT '同设备下中文名精确唯一（BR-MOD-14）',
    KEY `idx_equipment` (`equipment_id`),
    KEY `idx_default_manufacturer` (`default_manufacturer_id`)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4
  COLLATE = utf8mb4_general_ci COMMENT ='型号（设备下的具体机型；含缸数属性）';
```

### 4.2 wk_model_manufacturer 建表 SQL（对齐设计文档 §6.2.5）

```sql
-- 型号-厂家关联（多对多；含授权生产标记 + 展示排序）
CREATE TABLE IF NOT EXISTS `wk_model_manufacturer`
(
    `id`              BIGINT  NOT NULL AUTO_INCREMENT COMMENT '主键id',
    `model_id`        BIGINT  NOT NULL COMMENT '型号id（FK→wk_model.id）',
    `manufacturer_id` BIGINT  NOT NULL COMMENT '厂家id（FK→wk_manufacturer.id）',
    `is_license`      TINYINT NOT NULL DEFAULT 0 COMMENT '1=授权生产 0=自有（BR-MOD-10）',
    `sort_order`      INT     NOT NULL DEFAULT 99 COMMENT '展示排序，升序；默认 99=置后（BR-MOD-10）',
    `create_time`     DATETIME NULL DEFAULT NULL COMMENT '创建时间',
    `create_operator` JSON     NULL DEFAULT NULL COMMENT '创建人快照',
    `update_time`     DATETIME NULL DEFAULT NULL COMMENT '更新时间',
    `update_operator` JSON     NULL DEFAULT NULL COMMENT '更新人快照',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_model_manufacturer` (`model_id`, `manufacturer_id`),
    KEY `idx_manufacturer` (`manufacturer_id`)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4
  COLLATE = utf8mb4_general_ci COMMENT ='型号-厂家关联（多对多；含授权生产标记 + 展示排序）';
```

### 4.3 设计要点

1. **型号是设备下的从属实体**：`equipment_id` 外键，应用层校验存在 + 未删除 + 启用，不加数据库 FOREIGN KEY（与设备分类/厂家/设备一致，工程惯例）。
2. **默认厂家（default_manufacturer_id）独立字段**：可空；若空则前端默认选中关联集合排序第一的厂家；编辑时可单独指定（IN-EQ-04 校验归属）。
3. **多对多拆两张表**：型号聚合内部实体 `ModelManufacturerLink` 对应 `wk_model_manufacturer` 表（DDD §6.1）；厂家本体仅按 id 引用（不持有外键）。
4. **规格字段独立列**：`cylinder_count` 必填，`power_kw` / `bore_mm` / `mark` 选填；选填字段允许 NULL；**不参与定价**（R-01，模块内零价格/费率字段）。
5. **status 与 state 职责分离**：`status` = 业务启停（前台可见性）；`state` = 平台数据状态（逻辑删除）。
6. **DDL 唯一约束**：`uk_code` 全局唯一（型号编码唯一性，IN-MOD-01）+ `uk_equipment_name(equipment_id, name)` 同设备下中文名精确唯一（BR-MOD-14）。
7. **跨模块补账**：型号落库后，设备删除校验需查询 `wk_model where equipment_id=? AND state=1`；厂家删除校验需查询 `wk_model_manufacturer where manufacturer_id=? AND model.state=1`。

## 5. 领域模型与分层设计

### 5.1 领域模型（对齐 DDD §6.1 Model 聚合）

- **ModelDomain（聚合根）**：id、code、equipmentId、defaultManufacturerId、name、nameEn、mark、cylinderCount、powerKw、boreMm、status、state、平台快照字段。
- **ModelSpec（值对象，本期不单独建类）**：缸数/功率/缸径作为聚合根内字段承载；与 DDD §6.1 `ModelSpec` 值对象对应（聚合内嵌）。
- **ModelManufacturerLink（聚合内部实体）**：id、modelId、manufacturerId、isLicense、sortOrder、平台快照字段；与 DDD §6.1 `ModelManufacturerLink` 内部实体对应（组合 `*--`）。
- **ModelDomainService**：code 生成（MOD+4 位）、设备校验（存在+未删除+启用）、缸数 1–20 校验、规格字段合法性校验、默认厂家 ∈ 关联集合校验（IN-EQ-04）。
- **ModelDomainValidationService**（校验服务）：同设备下中文名查重、code 全局唯一性预校验——纯 Java 纯函数，便于单测。
