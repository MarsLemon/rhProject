## 1. 背景与定位

厂家（manufacturer）是**设备目录的第一个维护对象**（FR-07 维护顺序：① 厂家 → ② 设备分类树 → ③ 设备 → ④ 型号），是型号-厂家多对多关联（R-03）与默认厂家（IN-EQ-04）的全局字典。

- **R-04（硬性规则）**：**价格与厂家无关**。厂家模块内不得出现任何与价格/工时/费率相关的字段或逻辑，厂家仅是主数据字典。
- **现状**：设备分类（②）已先期交付；厂家（①）与设备分类相互独立、无表间依赖，随时可并行开发。型号模块（④）依赖本模块。

## 3. 业务规则基线（开发与验收共同依据）

> 编号 BR-MFR-xx，源自 R-03/R-04 + demo 行为 + 表设计提炼。

| 编号 | 规则 |
|------|------|
| BR-MFR-01 | 厂家编码由系统自动生成：`M` + 4 位递增序号（M0001、M0002…），全局唯一，**删除后序号不复用**（取现存最大 +1），禁止手填 |
| BR-MFR-02 | 中文名必填（≤100 字）；英文名选填（≤200 字）；中英文名参与列表关键词过滤 |
| BR-MFR-03 | 中文名**精确重复拒绝**（demo：`VENDORS.includes(v)` 查重），新增与编辑（排除自身）均校验；英文名不查重 |
| BR-MFR-04 | `status`：1=启用 0=停用。停用后**不出现在启用厂家列表**（型号维护下拉、询价页）；已被型号关联的历史关系不受影响；可重新启用 |
| BR-MFR-05 | 重命名仅改中英文名，编码不可改 |
| BR-MFR-06 | 删除为逻辑删除（state=3）；「被型号关联不可删」校验**本期不实现**，随型号模块补充（demo 行为：被关联时提示先解除关联） |
| BR-MFR-07 | 厂家不参与任何定价解析（R-04）：模块内无价格字段、无费率引用 |
| BR-MFR-08 | 所有写操作记录操作人快照 + `log.info` 关键节点日志 |

## 4. 数据模型设计

### 4.1 建表 SQL（对齐设计文档 §6.2.1 业务字段 + 工程表惯例）

> 惯例同 `wk_equipment_category`：`wk_` 前缀、`state` 逻辑删除位、`create_time/create_operator/update_time/update_operator` 平台快照列替代设计文档的 `created_at/updated_at`；业务字段（code/name/name_en/status）原样保留。

```sql
-- 厂家字典（R-03：型号-厂家多对多的全局字典；R-04：价格与厂家无关）
CREATE TABLE IF NOT EXISTS `wk_manufacturer`
(
    `id`              BIGINT                                                        NOT NULL AUTO_INCREMENT COMMENT '主键id',
    `code`            VARCHAR(50) CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci  NOT NULL COMMENT '厂家编码，系统生成（M+4位序号），全局唯一',
    `name`            VARCHAR(100) CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci NOT NULL COMMENT '厂家中文名，精确唯一',
    `name_en`         VARCHAR(200) CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci NULL     DEFAULT NULL COMMENT '厂家英文名',
    `status`          TINYINT                                                       NOT NULL DEFAULT 1 COMMENT '业务状态：1启用 0停用，停用后不出现在启用厂家列表',
    `state`           TINYINT                                                       NOT NULL DEFAULT 1 COMMENT '数据状态：1.启用 2.冻结 3.删除',
    `create_time`     DATETIME                                                      NULL     DEFAULT NULL COMMENT '创建时间',
    `create_operator` JSON                                                          NULL     DEFAULT NULL COMMENT '创建人快照',
    `update_time`     DATETIME                                                      NULL     DEFAULT NULL COMMENT '更新时间',
    `update_operator` JSON                                                          NULL     DEFAULT NULL COMMENT '更新人快照',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_code` (`code`),
    KEY `idx_name` (`name`)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4
  COLLATE = utf8mb4_general_ci COMMENT ='厂家字典';
```

> 索引说明：`idx_name` 支撑中文名精确查重与关键词过滤；唯一约束只放 code（name 查重在应用层执行，中文 utf8mb4 下唯一索引体积大且 demo 语义为提示性拦截）。

### 4.2 设计要点

1. 厂家是**平铺字典**（无层级、无父子），比设备分类树简单：无组树、无停用传播，停用只影响自身在下拉/前台的出现。
2. 与型号的关系（model_manufacturer）按 DDD 梳理属于型号聚合内部，本模块零外键、零关联查询。
