## 1. 背景与定位

服务信息与影响系数是**询价闭环的关键前置**——询价提交时采集的 3 项订单级字段(是否紧急/服务地点/服务时间)+ 3 类影响系数 + 保底价 = R-19 最终报价公式 `Max(合计保底价, 明细合计) × 影响系数` 的全部输入。

- **D16(保底价)**:项保底价 = 综合费率 × 最低计费工时(默认 8h,`pricing_param`),**按一份计**,不乘数量
- **D17(影响系数)**:影响系数 = `Max(紧急K, 地点K, 时间K)`,未命中 = 1.0,**只作用于订单级最终报价**
- **Q-9 已决(2026-09-18 业务拍板)**:取最大值(不连乘),紧急/临近排期不再叠加
- **业务意义**:3 张字典量级小(地点/紧急/时间),无前置数据依赖,**看板 §6 明示"可按需提前启动"**
- **里程碑定位**:保底价 + 影响系数(本期)(独立里程碑,M1 完成后即可启动)

## 4. 数据模型设计

### 4.1 wk_pricing_param DDL(单行全局参数)

> 字典量级:1 行(本期单租户);预留扩展。

```sql
CREATE TABLE IF NOT EXISTS `wk_customer_pricing`.`wk_pricing_param`
(
    `id`           BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键id',
    `param_key`    VARCHAR(50)  NOT NULL COMMENT '参数键(min_billable_hours/floor_enabled/hours_per_day)',
    `param_value`  VARCHAR(200) NOT NULL COMMENT '参数值(数字或布尔字符串,按 value_type 解析)',
    `value_type`   VARCHAR(20)  NOT NULL DEFAULT 'string' COMMENT '值类型:int/decimal/bool/string(Demo 后端解析用)',
    `remark`       VARCHAR(500) DEFAULT NULL COMMENT '说明',
    `state`        TINYINT      NOT NULL DEFAULT 1 COMMENT '1.启用 2.冻结 3.删除',
    `create_time`  DATETIME     DEFAULT NULL,
    `create_operator` JSON      DEFAULT NULL,
    `update_time`  DATETIME     DEFAULT NULL,
    `update_operator` JSON      DEFAULT NULL,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_param_key` (`param_key`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='计价参数(单行全局配置)';
```

### 4.2 wk_service_location DDL(3 级树)

> level 1(大地区)→ 2(国家)→ 3(地点),共 3 表字段同构,通过 level + parent_id 区分。

```sql
CREATE TABLE IF NOT EXISTS `wk_customer_pricing`.`wk_service_location`
(
    `id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键id',
    `parent_id`   BIGINT       DEFAULT NULL COMMENT '父节点id(大地区=NULL)',
    `level`       TINYINT      NOT NULL COMMENT '1=大地区 2=国家 3=地点',
    `code`        VARCHAR(50)  NOT NULL COMMENT '编码(同层内唯一;全球唯一推荐)',
    `name`        VARCHAR(100) NOT NULL COMMENT '名称(东南亚/新加坡/裕廊船厂)',
    `sort_order`  INT          NOT NULL DEFAULT 0 COMMENT '同级展示排序',
    `status`      TINYINT      NOT NULL DEFAULT 1 COMMENT '1=启用 0=停用',
    `state`       TINYINT      NOT NULL DEFAULT 1 COMMENT '1.启用 2.冻结 3.删除',
    `create_time` DATETIME     DEFAULT NULL,
    `create_operator` JSON     DEFAULT NULL,
    `update_time` DATETIME     DEFAULT NULL,
    `update_operator` JSON     DEFAULT NULL,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_code` (`code`),
    KEY `idx_parent` (`parent_id`),
    KEY `idx_level` (`level`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='服务地点(大地区>国家>地点)';
```

### 4.6 设计要点

1. **`pricing_param` 单租户 + 单行配置**:业务简化,后期可扩展多租户(无需本期预留)
2. **`urgency_level.code` 字符串 PK**:业务枚举值,INT 自增无意义
3. **`lead_time_coefficient` 区间完整性**:保存/更新时校验 `∀区间不重叠 + 全覆盖[0,∞)`,**任一区间缺失拒绝**(IN-MC-18)
4. **`location_coefficient` 单 location 唯一约束**:同一点只配一条;解析按"地点级>国家级>大地区级"取
5. **status 双轨**:`status`(业务启停)+ `state`(数据生命周期),职责分离
6. **索引设计**:`service_location(parent_id, level)` 支持树查询;`location_coefficient(location_id)` 唯一;`lead_time_coefficient(min_days, max_days)` 支持范围查询
7. **外键不落库**:所有 FK 应用层校验(与设备分类/厂家/设备/型号一致)
8. **影响系数合成器**:`PricingCoefficientService.compose()` 是**纯函数**——可单测,无状态,无 IO 缓存(避免缓存一致性问题)
