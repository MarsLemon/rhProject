## 1. 背景与定位

设备分类树（equipment_category）是船舶维保定价系统的**设备目录主数据入口**：

- **R-01（硬性规则）**：设备分类树**仅用于导航**，叶子节点 = 设备，**不参与定价**。模块内不得出现任何与价格/工时/费率相关的字段或逻辑。
- **FR-07 维护顺序**：① 厂家 → **② 设备分类树** → ③ 设备 → ④ 型号。本模块是 ③设备、④型号 模块的**前置依赖**，属于里程碑 **M1（目录+工时定价）** 的第一块落地内容。
- **现状**：工程当前仅有客户报价单（CustomerQuote）骨架代码（49 个类），设备目录相关代码为零。本计划是从 0 新建 `equipmentcategory` 包族的完整开发计划。

## 3. 业务规则基线（开发与验收共同依据）

> 编号 BR-CAT-xx，源自 R-01 + demo 行为提炼，写代码注释/测试名时引用。

| 编号 | 规则 |
|------|------|
| BR-CAT-01 | 分类编码由**系统按层级自动生成**，禁止手填：一级分类 = 现有最大数字编码 +1（如 1、2、3…）；子分类 = 父编码 + `.` + 三位序号（如 `6.001`、`6.001.002`） |
| BR-CAT-02 | 编码全局唯一（表唯一键兜底 + 应用层预校验）；同级序号取"同父下现存最大序号 +1"，**不复用已删节点序号**，防止编码漂移 |
| BR-CAT-03 | 中文名必填（≤100），英文名选填（≤200）；中英文均参与搜索 |
| BR-CAT-04 | `level` 由系统计算：一级=1，子级=父级+1，入参不得传 level；存在层级上限（默认 5，常量可配，见 Q-CAT-1） |
| BR-CAT-05 | `sort_order` 同级排序，升序；提供同级批量排序接口 |
| BR-CAT-06 | `status`：1=启用 0=停用。停用后**前台导航隐藏该节点及其全部子孙**（查询时内存计算，不落库冗余）；后台树仍可见（返回 status 供前端置灰）；可重新启用；存量业务数据不受影响 |
| BR-CAT-07 | 删除仅限"空节点"：存在未删除子分类 → 拒绝；节点挂载设备后亦不可删（该校验**在设备模块落地时补充**，本期设备表未建，不预置空桩） |
| BR-CAT-08 | 分类下若已挂载设备，则不可再新增子分类（demo：设备叶子下不能再挂节点）。**依赖设备模块，本期不实现**，在设备模块计划中补充该校验 |
| BR-CAT-09 | 重命名仅改中英文名，编码/层级/父级均不可改 |
| BR-CAT-10 | 删除采用**逻辑删除**（state=3，对齐工程现有惯例），非物理删除 |
| BR-CAT-11 | 前台接口仅返回启用节点；搜索支持 code / name / name_en 关键词，命中节点返回**完整分类路径**（如：机械设备主要部件 → 推进用柴油机 → 柴油机 → 主机柴油机） |
| BR-CAT-12 | 所有写操作记录操作人快照（平台 operator 快照列）+ `log.info` 关键节点日志 |

## 4. 数据模型设计

### 4.1 建表 SQL（对齐设计文档 §3.2 业务字段 + 工程现有表惯例）

> 工程惯例说明：表名使用 `wk_` 前缀（用户指定统一前缀），并沿用 `state` 逻辑删除位、`create_time/create_operator/update_time/update_operator` 平台快照列（参照 `t_customer_quote` 既有结构）；设计文档的 `created_at/updated_at` 由这套快照列替代，业务字段（parent_id/code/name/name_en/level/sort_order/status）原样保留。既有 `t_customer_quote` 表为项目初始化模板代码，**不做迁移处理，仅作表结构风格参考**（Q-CAT-8 已明确）。

```sql
-- 设备分类树（仅导航，R-01）
CREATE TABLE IF NOT EXISTS `wk_equipment_category`
(
    `id`              BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键id',
    `parent_id`       BIGINT       NULL     DEFAULT NULL COMMENT '父节点id，NULL=一级分类',
    `code`            VARCHAR(50)  NOT NULL COMMENT '分类编码，系统按层级自动生成，全局唯一（BR-CAT-01）',
    `name`            VARCHAR(100) NOT NULL COMMENT '分类中文名',
    `name_en`         VARCHAR(200) NULL     DEFAULT NULL COMMENT '分类英文名，中英双语搜索用',
    `level`           INT          NOT NULL COMMENT '层级深度：1=一级分类，系统计算（BR-CAT-04）',
    `sort_order`      INT          NOT NULL DEFAULT 0 COMMENT '同级排序号，升序',
    `status`          TINYINT      NOT NULL DEFAULT 1 COMMENT '业务状态：1启用 0停用（停用后前台导航隐藏，BR-CAT-06）',
    `state`           TINYINT      NOT NULL DEFAULT 1 COMMENT '数据状态：1.启用 2.冻结 3.删除',
    `create_time`     DATETIME     NULL     DEFAULT NULL COMMENT '创建时间',
    `create_operator` JSON         NULL     DEFAULT NULL COMMENT '创建人快照',
    `update_time`     DATETIME     NULL     DEFAULT NULL COMMENT '更新时间',
    `update_operator` JSON         NULL     DEFAULT NULL COMMENT '更新人快照',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_code` (`code`),
    KEY `idx_parent` (`parent_id`)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4
  COLLATE = utf8mb4_general_ci COMMENT ='设备分类树（仅导航，叶子=设备）';
```

### 4.2 设计要点

1. **树形存储**：邻接表（parent_id）+ level 冗余列。数据量小（分类节点远小于服务项<500 的量级），查询一律"全量拉取启用节点 → 内存组树"，无递归 SQL。
2. **停用传递不落库**：BR-CAT-06 的"停用父级 → 子孙前台隐藏"在查询侧内存计算（从根向下传播有效状态），避免停用/启用时的批量 UPDATE 与一致性问题。
3. **status 与 state 职责分离**：status=业务启停（前台可见性）；state=平台数据状态（逻辑删除）。

## 5. 领域模型与分层设计

### 5.1 领域模型（对齐 DDD 梳理 §6.1）

- **EquipmentCategoryDomain（聚合根）**：导航树节点。字段：id、parentId、code、name、nameEn、level、sortOrder、status。
  - *取舍说明*：DDD 文档定义了 `BilingualName`/`CategoryPath` 值对象；为对齐工程现有朴素风格（CustomerQuoteDomain 平铺字段），本期以**平铺字段 + 领域服务方法**承载双语与路径逻辑，值对象抽取列为可选重构项。

前台导航树的最终形态是"分类节点 + 设备叶子"的混合树（demo 前台首页）。本期接口仅返回**分类部分**；设备模块落地后，由前台 BFF/聚合查询把设备叶子按 category_id 挂入树中（接口出参为嵌套树结构，天然支持合并，无需变更本模块契约）。
