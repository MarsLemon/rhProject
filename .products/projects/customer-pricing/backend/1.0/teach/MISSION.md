# 学习目标:成本大表业务计算逻辑

## 学习主题

**成本大表**(成本核算大表 / Cost Accounting Big Table)的完整业务计算逻辑。

成本大表是公司内部销售视角的成熟定价体系,支持 6 种定价方法、4 级审批、跨币种处理等。本学习旨在完全掌握其业务本质,为后续借鉴到客户定价系统(customer-pricing)做准备。

## 为什么学这个

领导要求客户定价系统参考成本大表的设计逻辑。为了:

1. **写好借鉴方案报告** — 必须先懂成本大表才能判断什么可借鉴
2. **设计"可插拔定价方法"** — 借鉴 Bo 抽象思想(纯业务层面)
3. **设计"跨币种询价"** — 借鉴汇率快照机制(纯业务层面)
4. **与领导对齐决策** — 能讲清楚借鉴什么、不借鉴什么、为什么

## 学习边界

### ✅ 要学的(纯业务)

- 5 个业务阶段是什么、为什么这样分
- 3 个部门的职责划分
- 16 项成本类型的来由(阶段 × 部门矩阵)
- 总成本怎么汇总(跨币种怎么处理)
- 6 种定价方法的业务含义与适用场景
- 4 级审批的业务逻辑(为什么需要、怎么审)
- 9 个项目状态的流转
- 跨币种 + 汇率快照的业务意义
- 报价 ↔ 成本项的关联关系

### ❌ 不学的(代码层面)

- Java 类名、字段、抽象基类、继承结构
- 数据表结构、SQL、字段类型
- 接口路径、API 设计
- 任何代码层面的实现细节

## 完成标志

能够:

1. **白板讲解**:不看任何资料,在白板上画出"成本大表"完整业务流图
2. **业务判断**:领导问"客户定价要不要借鉴 XX",能准确判断借鉴 / 不借鉴 / 改造后借鉴
3. **写报告**:能独立写出借鉴方案的完整业务描述(不含代码)
4. **教学他人**:能把成本大表讲给完全不懂的同事听明白

## 学习方法

- **从最基础开始**:什么是成本大表 → 为什么需要 → 阶段 → 部门 → 成本项 → 汇总 → 定价 → 审批
- **每个 lesson 一个主题**:lesson 之间衔接但不重复
- **强化记忆**:每个 lesson 含 retrieval practice(自测题)
- **可视化优先**:用图表、流程图、矩阵讲业务
