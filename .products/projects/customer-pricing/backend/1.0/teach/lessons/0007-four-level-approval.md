# Lesson 0007:定价后的 4 级审批

<div class="meta">主题:4 级审批 | 难度:★★☆ | 阅读时间:6 分钟</div>

---

## 一句话

**销售定好报价后,不能直接拍板卖给客户 — 要过 4 级审批,每级都有"售价区间"硬约束,层层把关。**

---

## 为什么需要 4 级审批

销售定完价,**自由权太大**会带来风险:

```
销售权力过大:
├─ 卖太低 → 公司亏本
├─ 卖太高 → 客户跑了
├─ 私下让利 → 滋生腐败
└─ 瞎定 → 客户对公司没信心
```

4 级审批 + 售价区间 = **给销售自主权,但不让销售失控**。

---

## 4 级是谁

```
① 销售人员    → 业务第一线,定初步售价
② 销售部长    → 部门把关,看整体毛利率
③ 销售副总    → 分管层,跨部门平衡
④ 总裁        → 终审,定最终价格
```

> 每级**都要填自己的实际售价**,不能由一个人代办。

---

## 每级的"售价区间"

**核心约束**:**每级只能在规定的"售价区间"内定价**。

```
售价区间 = 系统给的硬性范围
   ↑ 怎么算的
   ├─ 项目总报价 × 区间系数
   └─ 系数从基础数据快照来(锁定时点 = 开始定价)
```

**算例**:
```
项目总报价 = 118 万
售价区间系数(基础数据已配):
   ├─ 销售人员: 95% ~ 105%
   ├─ 销售部长: 90% ~ 110%
   ├─ 销售副总: 85% ~ 115%
   └─ 总裁:     80% ~ 120%

各级可填范围:
   ├─ 销售人员: 112.1 ~ 123.9 万
   ├─ 销售部长: 106.2 ~ 129.8 万
   ├─ 销售副总: 100.3 ~ 135.7 万
   └─ 总裁:      94.4 ~ 141.6 万
```

> **关键**:**级别越高,可填范围越宽** — 但都有上下限。

---

## 每级的"3 件套"

每级审批都要填 3 个东西:

| # | 字段 | 含义 |
|---|---|---|
| 1 | **售价区间** | 系统给的范围(只读) |
| 2 | **实际售价** | 本级填的具体金额 |
| 3 | **预估毛利率** | 系统自动算 = 1 - 实际售价 / 总成本 |

---

## 4 级流程

```
销售人员 → 销售部长 → 销售副总 → 总裁
   ①          ②          ③          ④
   ↓
销售先定(在 95~105% 区间内)
   ↓
部长审(在 90~110% 区间内,可改)
   ↓
副总审(在 85~115% 区间内,可改)
   ↓
总裁终审(在 80~120% 区间内,可改)
   ↓
项目最终总报价 = 总裁的实际售价
```

> **关键洞察**:**虽然每级都能改售价,但级别越高改得越慎重**(因为有 audit trail)。

---

## 4 级的"权限递进"

| 级别 | 区间 | 权限 |
|---|---|---|
| 销售人员 | 最窄 | 只能在很小的范围内微调 |
| 销售部长 | 较宽 | 可以有部门级让步 |
| 销售副总 | 更宽 | 可以跨部门平衡 |
| 总裁 | 最宽 | 终审,可做最大决策 |

> **本质**:**越高层,越接近战略决策** — 所以区间越宽;但每层都不能出区间。

---

## 4 级填不同的售价会怎样

**关键规则**:**项目最终总报价 = 总裁填的实际售价**。

```
销售人员填:118 万(在 112.1~123.9 内)  ✓
销售部长填:115 万(在 106.2~129.8 内)  ✓
销售副总填:113 万(在 100.3~135.7 内)  ✓
总裁填:    112 万(在 94.4~141.6 内)   ✓

项目最终总报价 = 112 万(总裁定的)
```

> **但**:**每一级都有自己的实际售价**,总裁定的只是最终值,其他级别的售价也都有据可查。

---

## "售价区间"是怎么来的

```
基础数据(销售副总/CEO 配置):
   销售人员区间系数: 95% ~ 105%
   销售部长区间系数: 90% ~ 110%
   销售副总区间系数: 85% ~ 115%
   总裁区间系数:     80% ~ 120%

项目 X 开始定价时:
   → 系统快照这些系数
   → 项目 X 整个生命周期都用这套系数
```

> **关键**:**基准数据是项目级快照**,跟汇率快照一样,锁定后不再变。

---

## 4 级审批的"防御机制"

| 防御点 | 防什么 |
|---|---|
| **售价区间** | 防销售乱定(出区间不允许) |
| **4 级都要填** | 防一言堂(一个人不能定) |
| **每级都有 audit** | 防私下让利(谁定的有据可查) |
| **预估毛利率** | 防亏本卖(系统实时算毛利率) |

---

## 关键认知

| # | 要点 |
|---|---|
| 1 | 4 级 = 销售 → 部长 → 副总 → 总裁 |
| 2 | 每级都有**售价区间**硬约束 |
| 3 | 每级都要填**实际售价 + 预估毛利率**(自动算) |
| 4 | **项目最终总报价 = 总裁填的实际售价** |
| 5 | 区间系数从基础数据**快照**,锁定后不变 |

## 自测题

<div class="quiz">

**Q1. "售价区间"的上下限从哪里来?**

- A. 销售自己定的
- B. 项目总报价 × 基础数据配置的区间系数
- C. 客户给的
- D. 法律规定的

<details>
<summary>显示答案</summary>
<div class="quiz-answer">
<strong>B</strong> — 售价区间 = 项目总报价 × 区间系数。系数从基础数据来,在开始定价时快照锁定。
</div>
</details>

</div>

<div class="quiz">

**Q2. 项目最终总报价等于谁填的售价?**

- A. 销售人员
- B. 销售部长
- C. 销售副总
- D. 总裁

<details>
<summary>显示答案</summary>
<div class="quiz-answer">
<strong>D</strong> — 项目最终总报价 = <strong>总裁填的实际售价</strong>。其他级别都填,但总裁的才是最终值。
</div>
</details>

</div>

<div class="quiz">

**Q3. 销售部长可以把售价定在销售人员区间之外吗?**

- A. 可以,部长权限大
- B. 不行,部长的区间也有限制

<details>
<summary>显示答案</summary>
<div class="quiz-answer">
<strong>B</strong> — 销售部长只能在<strong>自己的区间</strong>内定价(90~110%)。超出不允许。区间越往高层越宽,但都有限制。
</div>
</details>
