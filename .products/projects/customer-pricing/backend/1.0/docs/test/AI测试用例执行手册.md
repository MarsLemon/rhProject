# Apifox AI 测试用例 · 执行手册

> 版本：v1.0 | 适用：客户定价系统（项目 ID 8869726）
> 配套：`docs/test/Apifox-AI提示词模板.md`
> 目标：在不依赖 AI 模型局限性的前提下，借助 Apifox 内置 AI 给所有 60+ 接口批量生成等价类用例

---

## 📑 前置准备（5 分钟）

### 1. 登录 Apifox
- 打开 https://app.apifox.com 并登录（如未登录先走手机号验证）
- 进入「客户定价系统」项目（ID 8869726）

### 2. 配置环境变量（项目级一次性）
1. 顶部菜单 → 「环境管理」→ 选择「本地（默认）」
2. 在「环境变量」面板添加：
   | 变量名 | 初值 | 说明 |
   |--------|------|------|
   | `baseUrl` | `http://localhost:8031` | 后端服务地址 |
   | `token` | `<JWT裸token>` | 从登录接口获取，无 `Bearer ` 前缀 |
3. 在「全局认证」选 apikey 方式：key=`Authorization`,value=`{{token}}`,in=header
4. 保存

### 3. 后端确认（保底）
- 确认本地后端已启动：`curl http://localhost:8031/actuator/health` 应返回 200
- MySQL 已连接（DB UP）；RabbitMQ DOWN 不影响本批次用例

## 🚀 批量操作流程（每接口 2-3 分钟）

### 步骤 1：选中接口
左侧接口树 → 展开目标模块（如「设备字典维护」）→ 点击具体接口（如「新增设备」POST `/web/equipment/add`）

### 步骤 2：切到「测试用例」标签
右侧主面板顶部 → 「调试 / 设计 / 文档预览 / 测试用例 / Mock」 → 点击「**测试用例**」

### 步骤 3：点「🤖 AI 生成用例」
测试用例列表右上 → 「**+ 添加用例**」下拉 → 选择「**🤖 AI 生成用例**」（或左下角直接点「AI 生成用例」按钮）

### 步骤 4：选择测试类型（推荐 4 类全选）
右侧弹出面板：
| 维度 | 推荐勾选 | 说明 |
|------|---------|------|
| **正向** | ✅ 全选 | 仅必填字段 / 覆盖选项 / 其他枚举值 / 其他正常 |
| **负向** | ✅ 全选 | 无效值 / 缺失必填字段 / 类型错误 / 类型错误 / 语义语法 |
| **边界值** | ✅ 全选 | 版本/极大/极小值 / 超出最大 / 超出最小 / Null/空值/空字符串 / 字符串过长 / 过短 |
| **安全性** | ⚠️ 视情况 | 鉴权控制 / SQL 注入 / XSS 注入 / 命中断言 / JSON 注入 |

> 实际项目可不勾选安全性（鉴权由 Apifox 全局头统一处理），如需 XSS/SQL 注入再单独勾

### 步骤 5：粘贴模块级提示词（关键步骤）
右侧面板下方「输入更多要求」文本框 → 完整粘贴 [`Apifox-AI提示词模板.md`](./Apifox-AI提示词模板.md) 中「模块 X」整段提示词
（如设备字典维护：复制「模块 3」整段 + 通用前缀）

### 步骤 6：点「生成」
AI 会根据接口 schema 自动生成 6-10 条用例到列表底部
- 等待 5-15 秒（取决于提示词长度与接口复杂度）
- 生成完成后会弹窗提示，可「全部接受」或「逐条审核」

### 步骤 7：审核 + 微调
- 每条用例点击「运行」调试一次（确认变量提取、断言通过）
- 失败用例右键「编辑」微调请求体或断言
- 关键字段提取（如 `pm.collectionVariables.set('equipmentId', body.data.id)`）写入测试脚本

### 步骤 8：批量运行 + 导出报告
- 测试用例列表顶部 → 「运行」按钮 → 选择「**批量运行**」
- 范围：「当前文件夹」或「选中用例」
- 报告自动生成在「测试报告」菜单

## 🧪 验证用例质量的关键检查

每生成一个模块的用例集，必须逐条检查：

### A. 断言合规性
- ✅ 第一断言必须是 `pm.response.to.have.status(200)`
- ✅ 第二断言必须是 `pm.expect(body.code).to.eql('00000000')`（成功）或 `pm.expect(body.code).to.not.eql('00000000')`（失败）
- ❌ 严禁出现 `pm.response.to.have.status(400/401/403/404/500)` 等 HTTP 层断言

### B. 变量提取
- ✅ 创建型接口用例必须有 `pm.collectionVariables.set('xxxId', body.data.id)` 用于后续链式用例
- ❌ 严禁写死 id（如 `"id": 12345`）

### C. 错误码准确性
- ✅ 失败用例的断言中提到的 code 必须能在 `PricingCoefficientExceptionEnum` / `ModelExceptionEnum` 等枚举中找到
- ❌ 严禁出现错误码段「8 位长度不符」或「段号越界」

### D. 业务约束覆盖
每个接口至少覆盖：
- 必填字段缺失（@NotNull / @NotBlank）
- 唯一性校验（uk_code / uk_name / uk_location）
- 引用保护（被引用不允许删除）
- 状态机约束（status 仅允许 0/1）

## 🔍 常见问题排查

### Q1：AI 生成的用例断言不合规？
A：手动编辑用例的「测试脚本」标签，把 `pm.response.to.have.status(400)` 改为：
```javascript
pm.test("HTTP 恒 200", function () { pm.response.to.have.status(200); });
var body = pm.response.json();
pm.test("code 非零（业务失败）", function () { pm.expect(body.code).to.not.eql('00000000'); });
pm.test("msg 包含关键字", function () { pm.expect(body.msg).to.include('xxx'); });
```

### Q2：变量提取失败（body.data.id 为 undefined）？
A：先调试运行一次，看响应 JSON 结构是 `data.id` 还是 `data.data.id`。Apifox 项目可能包了一层，需手动调整 set 语句。

### Q3：AI 生成的失败用例期望的 code 与实际不一致？
A：实际 code 以 `PricingCoefficientExceptionEnum.java` 为准，手动修改期望值。

### Q4：批量运行报告中有失败用例怎么办？
A：分两种情况：
1. **后端 Bug** → 把失败用例「添加为问题」跟踪，提单给后端修复
2. **用例数据问题** → 调整请求体（如依赖 id 已删则改用新创建），重新运行

### Q5：链式用例（依赖上游 id）跑不通？
A：先单独运行上游用例，确认变量已写入（点击用例「测试脚本」查看 `pm.collectionVariables.set` 语句）。然后运行链式用例。

## 💡 进阶玩法

### 1. 用 Apifox 自动化测试做 CI
- 测试用例列表 → 「自动化测试」→ 创建场景
- 场景可设置「请求前延迟」「失败重试」「数据驱动」
- 触发方式：定时 / Webhook / Apifox CLI / GitHub Actions

### 2. 用 Mock 服务做前端并行开发
- 接口 → 「Mock」标签 → 启用「智能 Mock」/「自定义 Mock」
- 前端无需等后端即可调用 `/mock/xxx` 拿到示例数据

### 3. 用 OpenAPI 导出做客户端 SDK 生成
- 项目设置 → 「导出 OpenAPI」→ 选择语言（TypeScript / Java / Go 等）
- 自动生成类型安全的 API 客户端代码
