## 1. 系统概述

### 1.1 一句话业务

客户（船东/船管公司）在嵌入页面自助完成 **选设备 → 填维保需求 → 选维保方案 → 看预算 → 提交询价**，系统按标准目录实时算出预算估算，提交后冻结价格快照并邮件通知销售跟进。

### 1.2 角色

| 角色 | 使用场景 | 关注点 |
|------|---------|--------|
| 客户 | 前台三步流程 | 找到设备、看懂方案、拿到预算参考、留下询价 |
| 运营管理员 | 后台维护 | 维护设备/厂家/型号、标准工时/费率、套餐与展示规则 |
| 销售 | 系统外 | 接收询价邮件，人工确认最终报价并跟进 |

### 1.3 系统边界

| 系统内（本期建设） | 系统外（不建） |
|------------------|--------------|
| 设备/维保目录维护（含标准工时、费率） | 客户主数据（复用已有登录态取姓名/电话/邮箱） |
| 方案展示规则解析 | 销售跟进过程管理（CRM） |
| 预算实时计算（工时推导唯一路径，D15） | 正式报价单、订单、合同 |
| 询价单/咨询单受理、快照冻结、邮件通知 | 支付、结算 |

### 1.4 两个核心认识

1. **定价是两层**：目录定价（后台维护的标准价格体系）+ 询价定价（客户上下文实时算出的结果）。
2. **给客户看的永远是"预算估算"，不是成交价**。最终报价由销售在系统外人工确认。本系统的产出是：客户侧=价格参考+询价线索；销售侧=结构完整的跟进线索（含工时构成）。

### FR-03 定价引擎（核心，工时推导唯一路径）

统一入口：`estimate(pricingContext, selection) → budget`。**无状态、可反复调用**（每次选择变化都触发）。

**pricingContext**：型号规格快照（缸数）、维保类型、保养周期（可空）、币种。
**selection**：套餐选择（套餐×勾选明细×数量）、建议项选择（项×数量）。
**serviceInfo**（v1.8 新增，D17）：是否紧急（urgencyCode）、服务地点（region/country/location，location 可空）、服务日期与距询价天数（leadDays）。

逐行推导单价（详细算法见 §7.2）：

```
for each 勾选的明细行（套餐明细或建议项）:
    (crew, hours) = 工时推导解析（两级回溯 IN-MC-12，费率生效 IN-MC-13；v1.11 去件数系数，D18）
    任一要素缺失 → 该行不可计价：前台不展示/置灰提示，后台预警
    unit_price = Σ(rate×headcount) × hours                  # 单价（每单位）
    qty = 客户调整值(≥1) if 有 else 默认数量(数量来源解析, 见 7.3)
    line_amount = unit_price × qty
套餐小计 = Σ(该套餐勾选明细行金额)                    # 无折扣、无份数（D11）
明细合计 = Σ(各套餐小计) + Σ(勾选建议项行金额)

# 保底价（D16）：逐项兜底，按一份计
项保底价 = 该项综合费率(Σ 构成人数×生效费率) × min_billable_hours   # 默认 8h，取 pricing_param
合计保底价 = Σ(各已勾选服务项的项保底价)              # 不乘数量、不看实际工时
计价基数 = Max(合计保底价, 明细合计)                  # 不足按保底托底
保底补足额 = Max(0, 合计保底价 − 明细合计)

# 影响系数（D17）：取三者最大值（Max），各未命中=1.0，只作用于最终报价
影响系数 = Max(紧急系数, 地点系数, 时间系数)
最终报价 = Round(计价基数 × 影响系数, 2)
```

**各行额外输出推导要素**（构成明细/费率明细/标准工时），供快照（FR-05）与销售邮件（FR-05）使用；**客户侧预算页仅展示最终报价**——工时/系数/保底构成一律不外显（R-36 口径扩展，2026-09-11 确认）。

### FR-11 后台影响系数与保底参数维护（v1.8 新增，D16/D17）

```

5. 时间影响系数（lead_time_coefficient）：天数区间 + 系数；保存校验（IN-MC-18，拒绝保存）——
   启用区间**不重叠**且并集**连续覆盖 [0, +∞)**（必须存在 max_days IS NULL 的一行）
```

## 7. 计算规则详解（可执行规格）

### 7.1 ~~直价解析~~ 【已退役 v1.1（D15）】

> 原两级回溯直价 SQL 随 service_item_price 退役删除；单价解析统一为 **7.2 工时推导解析**。基础服务费解析仍按 型号级>设备级 两级回溯执行（见 7.4 中 IN-MC-11）——**基础服务费不是服务项价格**，不受 D15 影响。

### 7.2 工时推导解析（唯一路径，D14/D15）

```
步骤① 解析标准工时（IN-MC-12，两级回溯，v1.4）：
SELECT ls.* FROM labor_standard ls
LEFT JOIN labor_standard_model lsm
       ON lsm.labor_standard_id = ls.id AND lsm.model_id = :modelId
WHERE ls.service_item_id = :itemId
  AND ls.maintenance_type_id = :mtId
  AND ls.maintenance_cycle_id <=> :cycleId
  AND ( lsm.model_id IS NOT NULL                            -- ① 型号级（一条配置可挂多型号）
     OR (lsm.model_id IS NULL AND ls.model_id IS NULL
         AND ls.equipment_id = :equipmentId) )              -- ② 设备级兜底
  AND ls.status = 1
ORDER BY (lsm.model_id IS NOT NULL) DESC
LIMIT 1;
-- 空结果 = 不可计价

命中后：单件工时 H0 = ls.duration_hours
若存在缸数分档（labor_duration_tier）且 :cylinderCount 落在 [min_cyl,max_cyl] 某档
  → H0 = 该档 duration_hours（有分档但缸数未命中任何档 = 配置错误，按不可计价+预警）

步骤② 解析费率（IN-MC-13）：对构成行(labor_crew_line)的每个 rank_id：
SELECT hourly_rate FROM rank_rate_card
WHERE rank_id = :rankId AND status = 1
  AND effective_from <= :today AND (effective_to IS NULL OR effective_to > :today)
LIMIT 1;
-- 任一职级无生效行 = 不可计价 + 预警

步骤③ 计算（v1.11：件数系数环节已随 D18 退役，不再有 K）：
综合费率       R  = Σ(hourly_rate_i × headcount_i)        # 以构成行为准，忽略 ls.headcount 字段
单价           UP = R × H0
明细行的 unit_price = UP
```

### 7.3 默认数量解析（数量来源）

| quantity_mode | 默认数量 | 前置条件 |
|---------------|---------|---------|
| fixed | default_qty | — |
| auto_cylinder | model.cylinder_count | 型号缸数必须已知（自定义型号需客户手填，IN-MC-05） |
| auto_per_2cylinder | CEIL(model.cylinder_count / 2) | 同上 |

客户对**所有**明细数量可调（≥1），调整值优先于默认值。

### 7.4 行金额与合计

```
行金额     = unit_price × quantity                      # R-16
套餐小计   = Σ(勾选明细行金额)                          # 无折扣、无份数（D11）
明细合计   = Σ(各套餐小计) + Σ(勾选建议项行金额)

# —— 保底价（D16/R-30）：逐项兜底，按"一份"计 ——
项保底价   = 该项综合费率(Σ 构成人数 × 生效费率) × min_billable_hours   # 默认 8h（pricing_param）
合计保底价 = Σ(各已勾选服务项的项保底价)                # 不乘数量、不看实际标准工时
计价基数   = Max(合计保底价, 明细合计)
保底补足额 = Max(0, 合计保底价 − 明细合计)

# —— 影响系数（D17/R-41）：取三者最大值（Max），各未命中=1.0 ——
紧急系数   = urgency_level.coefficient（按 urgency_code；未命中=1.0）
地点系数   = location_coefficient（地点级 > 国家级 > 大地区级；留空=任意兜底；全未配置=1.0）
时间系数   = lead_time_coefficient（按 lead_days 命中区间；未命中=1.0 并预警）
影响系数   = Max(紧急系数, 地点系数, 时间系数)          # 只作用于最终报价（取三者最大值，Q-9 已决）
最终报价   = Round(计价基数 × 影响系数, 2)
```

### 7.5 快照冻结（提交时，一次性写入）

- inquiry：冗余 型号名/厂家名/周期名/缸数/**服务信息（紧急/服务地点/服务日期/距询价天数）**/**最低计费工时/明细合计/合计保底价/保底补足额/计价基数/三类系数与合成系数/最终报价**/币种；
- inquiry_snapshot：逐行写 item_name/unit_price/quantity/line_amount +（package行）package_subtotal + **floor_amount（项保底价，按一份计）** +（推导要素）labor_rate_detail/crew_detail/standard_hours（v1.11 去 qty_coefficient）；
- 冻结后：目录任何变更（调价/调费率/改工时/改系数/下架）**不得**影响已提交询价单（IN-INQ-02）。实现要求：读历史单只读快照表，禁止回查目录表重算。

## 9. 非功能需求与全局约定

1. **币种**：全系统金额带 currency，本期统一 USD（D5）；不做多币种切换，字段预留。
2. **快照不可变**：inquiry / inquiry_snapshot 提交后禁止 UPDATE/DELETE（应用层拦截）。
3. **实时性**：预算计算为内存级纯函数（目录数据量：型号<100、服务项<500、价格/工时行<5000，单次询价全量重算无性能压力；无需缓存失效策略）。
4. **调价即时生效**：对新询价即时生效；可选支持"定时生效"（预留 effective 字段，本期不做）。
5. **审计**：后台对 价格/费率/工时/系数 的变更记录操作日志（who/when/before/after）。
6. **技术栈中立**：不规定框架；但定价引擎必须实现为**独立纯函数模块**（输入定价上下文+选择结果，输出预算），与持久化/接口层解耦（DDD 估算上下文要求）。
7. **前端展示口径**：客户侧只展示**最终报价**（含套餐小计、可选项金额等常规价格行）；工时/费率构成、影响系数、保底价与补足额只在 销售邮件 与 后台视图 出现（R-36 口径扩展，2026-09-11 确认）。前台不得出现任何系数与计价工时文案。
