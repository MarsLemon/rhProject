**优先级与写法**:

| 层级                | 测试目标                             | 推荐写法                                                                     | 备注                                                        |
| ------------------- | ------------------------------------ | ---------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 领域纯函数          | 编码生成、唯一性校验、组树、状态流转 | 直接`new` 领域实现类,不依赖仓储(CLAUDE.md §4.7)                              | 优先覆盖                                                    |
| 应用层编排          | AppOpService/AppQueryService         | Mockito 注入 Repos stub                                                      | 验证事务边界                                                |
| 仓储实现            | OpRepository / QueryRepository       | **Spy 子类 + JDK Proxy** 绕 MyBatis-Plus BaseMapper mock 坑(2026-09-14 经验) | 三件套必备:`@BeforeEach` 调 `TableInfoHelper.initTableInfo` |
| Converter / Factory | DTO ↔ Command ↔ Domain ↔ Entity      | 纯函数,直接断言                                                              | —                                                           |

**Spy + JDK Proxy 模板**(2026-09-14 经验):

```java
// 1. Spy 子类重写 ServiceImpl 的 list/getOne
static class SpyXxxServiceImpl extends XxxServiceImpl {
    private List<Xxx> listStub;
    SpyXxxServiceImpl(XxxMapper mapper /* 其余依赖 */) {
        super(mapper /* 传 null 也行 */);
    }
    void setListStub(List<Xxx> stub) { this.listStub = stub; }
    @Override public List<Xxx> list(Wrapper<Xxx> q) {
        return listStub != null ? listStub : Collections.emptyList();
    }
}

// 2. JDK Proxy 替代 @Mock BaseMapper
private static XxxMapper newXxxMapperProxy() {
    return (XxxMapper) Proxy.newProxyInstance(
        XxxMapper.class.getClassLoader(),
        new Class<?>[]{XxxMapper.class},
        (proxy, method, args) -> {
            // 按方法名 stub;其他返回默认值(int=0, long=0L, List=emptyList, 其他=null)
            Class<?> r = method.getReturnType();
            if (r == int.class || r == Integer.class) return 0;
            if (r == long.class || r == Long.class) return 0L;
            if (r == List.class) return Collections.emptyList();
            return null;
        }
    );
}

// 3. @BeforeEach 必须 init TableInfo
@BeforeEach void setUp() {
    MybatisConfiguration cfg = new MybatisConfiguration();
    MapperBuilderAssistant assistant = new MapperBuilderAssistant(cfg, "");
    TableInfoHelper.initTableInfo(assistant, XxxEntity.class);
    service = new SpyXxxServiceImpl(newXxxMapperProxy());
}
```

**通过标准**:

- exit 0
- `Tests run: X, Failures: 0, Errors: 0`
- 核心模块覆盖率 ≥ 70%(优先:领域服务、纯函数、状态流转)

**反模式**(2026-09-17 验证维度):

- ❌ mock 全返 `true` / `false` 让覆盖率假绿 — 实际不覆盖任何分支
- ❌ 改了仓储方法忘改接口声明 → L1 编译报"找不到符号"
- ❌ 只跑新增模块单测,不复跑既有单测 → 回归失败静默漏出
- ❌ 看到 `Tests run: 0` 不报警(可能是 JUnit 4 注解被 surefire 忽略,CLAUDE.md §4.7 警告)

## 3. L3 接口契约

**触发**: L2 通过后。

**前置**: Postman 集合已在 `docs/api/<模块英文名>/` 目录交付(v2.1 格式,含 `code=00000000` 断言脚本 + 集合变量 `baseUrl` + `token` + apikey 方式 Authorization 裸 token 预置)。

**执行步骤**:

1. 启动后端:`mvn spring-boot:run -pl wk-customer-pricing-api`(端口 8031)
2. 打开 Postman + Swagger UI(`http://localhost:8031/swagger-ui.html`)
3. 逐接口跑三套用例:
   - **happy path**: 正常参数 → 断言 `code="00000000"` + 关键字段非空
   - **边界值**: 空集合 / 超长字符串(255 边界) / 极值数字 / 特殊字符(`<script>`、`'; DROP TABLE` 等)
   - **错误流**: 缺失权限点 → 401;非法状态(如停用项被引用) → 业务异常码(各模块分段见 CLAUDE.md §六 错误码分段,设备分类 `8031201xx` / 厂家 `8031202xx` / 设备 `8031203xx` / 型号 `8031204xx`…)
4. 跨模块校验补账(闸 3 联动): 厂家→型号、设备分类→设备的互引用关系

**通过标准**:

- 每个 `/web/<模块>/*` 接口 = ≥1 个 Postman 用例(覆盖 happy + ≥1 边界 + ≥1 错误)
- `code="00000000"` 断言全绿
- 权限点校验:`@WkAclPermissions("pricing:web:<模块>:<动作>")` 缺失/错误权限返回 401
- 错误流业务异常码 = 该模块分段内编号

**反模式**:

- ❌ 跳过 Swagger UI 手工跑,只信 Postman 自动通过(可能 Postman 用例本身错)
- ❌ 只跑 happy path,忽略错误码 → 业务异常时分段码乱写,后期收账成本高
- ❌ 跨模块补账项不验,等联调才暴露
- ❌ 响应 msg 字段用英文技术栈术语,前端没法透出给用户

## 4. L4 E2E 集成

**触发**: L3 通过后。

**前提**(2026-09-20 主人拍板): **demo 仅作 oracle 对照,不动 demo 代码**。demo 当前是 IndexedDB 离线模式,marketing-ui 接入时才走真 E2E。本阶段"集成"= 后端内部跨模块场景化链路 + 关键计算口径复算,与 demo 数字对齐。

**执行步骤**:

1. 后端起在 8031,Postman 已含跨模块场景用例
2. 跑场景化链路(每个模块交付至少 1 个):
   - **场景 1 — 设备目录链**: 创建设备分类 → 创建设备 → 创建型号(含型号-厂家多对多 IN-EQ-04)→ 校验型号列表能查到
   - **场景 2 — 工时两级回溯链**: 创建维保类型 + 服务项 + 型号级工时标准(多型号)→ 校验型号命中 + 设备级兜底回溯(TC-R32 两级回溯口径)
   - **场景 3 — 询价快照冻结链(M2)**: 创建询价 → 校验快照含服务信息三项 + 保底三要素 + 影响系数快照(IN-INQ-05/06)
3. **计算口径复算**(对照 demo 2026-09-11 闭环数字):
   - 单价 = Σ(职级费率 × 人数) × 单件标准工时(D15)
   - 行金额 = 单价 × 数量(**D18 退役件数系数后**,多件全额计,不得再乘任何件数系数)
   - 项保底价 = 综合费率 × 最低计费工时(默认 8h,D16,**按一份计**,数量变化不改保底)
   - 合计保底价 = Σ(各已勾选服务项的项保底价)
   - 影响系数 = Max(紧急, 地点, 时间)(2026-09-18 决,各未命中 = 1.0)
   - 最终报价 = Max(合计保底价, 明细合计) × 影响系数(D16/D17)

**通过标准**:

- 场景化链路全通
- 计算口径数字 = demo 闭环数字(误差 = 0,小数点末位对齐)
- 客户侧展示口径(R-36 扩展): 客户预算页只返最终报价;保底补足额/影响系数/工时构成只在销售邮件 + 后台视图出现

**反模式**:

- ❌ 复算只看主路径,忽略 demo 演示用的边界 case(如 0 件 / 单件 / 多件切换)
- ❌ 复算忽略 R-36 客户侧口径 → 误把保底/系数外泄给前端
- ❌ 把 demo IndexedDB 数据当真值复算 → demo 是设计演示,不是基线数据

- ❌ 补账点不写明"由哪个模块触发" → 依赖方找不到该在哪实现
