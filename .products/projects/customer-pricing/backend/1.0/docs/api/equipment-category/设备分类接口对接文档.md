# 设备分类树 接口对接文档

> 版本：v1.1 | 日期：2026-09-03 | 对应后端：`equipmentcategory` 模块（设备分类树，R-01：仅导航、不参与定价）
>
> 面向前端/AI 辅助对接：每个接口给出**可复制的请求/响应 JSON 示例**。通用约定（响应包络、鉴权、环境）见 [README.md](../README.md)。
>
> **Postman 集合**：[equipment-category.postman_collection.json](./equipment-category.postman_collection.json) —— 可直接导入 Postman 测试：9 个请求按后台/前台分目录、每个请求带可切换的响应示例与内置 `code=00000000` 断言脚本；导入后在集合 **Variables** 中按环境修改 `baseUrl`（默认 `http://localhost:8031`）。

## 1. 接口总览

| # | 接口 | 方法 | 路径 | 用途 | 权限点 |
|---|------|------|------|------|--------|
| 1 | 后台分类树 | GET | `/web/equipment-category/tree` | 后台维护主视图，含停用节点 | `pricing:web:equipment-category:tree` |
| 2 | 新增分类 | POST | `/web/equipment-category/add` | 新建一级分类或子分类 | `pricing:web:equipment-category:add` |
| 3 | 重命名 | PUT | `/web/equipment-category/rename` | 改中/英文名 | `pricing:web:equipment-category:rename` |
| 4 | 启用/停用 | PUT | `/web/equipment-category/change-status` | 控制前台导航可见性 | `pricing:web:equipment-category:change-status` |
| 5 | 同级排序 | PUT | `/web/equipment-category/sort` | 拖拽后整体提交顺序 | `pricing:web:equipment-category:sort` |
| 6 | 删除分类 | GET | `/web/equipment-category/delete/{id}` | 仅空节点可删 | `pricing:web:equipment-category:delete` |
| 7 | 详情回显 | GET | `/web/equipment-category/detail/{id}` | 编辑表单回显 | `pricing:web:equipment-category:detail` |
| 8 | 前台导航树 | GET | `/web/portal/equipment-category/nav-tree` | 询价页分类导航（仅启用） | 登录态即可 |
| 9 | 前台搜索 | GET | `/web/portal/equipment-category/search` | 编码/中文名/英文名搜索 | 登录态即可 |

## 2. 码表与公共字段说明

### 2.1 status 业务状态（区别于系统级逻辑删除，前端只会见到 1/0）

| 码 | 含义 | 前台导航表现 |
|----|------|------------|
| 1 | 启用 | 可见 |
| 0 | 停用 | 该节点**及其全部子孙**隐藏（后端查询侧传播，前端无需处理） |

后台树中停用节点仍返回（前端置灰展示），启用后恢复。

### 2.2 分类编码 code（只读，系统生成）

- 一级分类：递增数字，如 `1`、`6`、`7`；
- 子分类：`父编码.三位序号`，如 `6.001`、`6.001.001`；
- 新增后立即返回，**前端不可手填、不可编辑**；
- 删除后序号不复用（删了 `6.002`，下个新增仍是 `6.003`）。

### 2.3 level 层级（只读，系统计算）

一级=1，子级=父级+1，当前上限 5 层。入参传 level 无效。

## 3. 后台接口明细

### 3.1 后台分类树（含停用节点）

```
GET /web/equipment-category/tree
```

**入参**：无

**响应 data**：`EquipmentCategoryTreeNodeVo[]`（嵌套树）

```json
[
  {
    "id": 6,
    "parentId": null,
    "code": "6",
    "name": "机械设备主要部件",
    "nameEn": "MECHANICAL EQUIPMENT MAIN COMPONENTS",
    "level": 1,
    "sortOrder": 0,
    "status": 1,
    "children": [
      {
        "id": 61,
        "parentId": 6,
        "code": "6.001",
        "name": "推进用柴油机",
        "nameEn": "PROPULSION DIESEL ENGINE",
        "level": 2,
        "sortOrder": 0,
        "status": 1,
        "children": [
          {
            "id": 611,
            "parentId": 61,
            "code": "6.001.001",
            "name": "主机柴油机",
            "nameEn": "MAIN DIESEL ENGINE",
            "level": 3,
            "sortOrder": 0,
            "status": 1,
            "children": []
          }
        ]
      }
    ]
  },
  {
    "id": 7,
    "parentId": null,
    "code": "7",
    "name": "管路及阀件系统",
    "nameEn": "PIPING AND VALVES",
    "level": 1,
    "sortOrder": 1,
    "status": 0,
    "children": []
  }
]
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | long | 节点 id，写接口的入参依据 |
| parentId | long\|null | 父节点 id，null=一级分类 |
| code | string | 分类编码，只读 |
| name / nameEn | string | 中文/英文名，nameEn 可为 null |
| level | int | 层级深度，只读 |
| sortOrder | int | 同级排序号，升序 |
| status | int | 1 启用 / 0 停用（停用节点前端置灰） |
| children | array | 子节点列表，叶子为 `[]` |

**前端渲染建议**：同级顺序后端已按 sortOrder 排好，直接按数组顺序渲染即可。

### 3.2 新增分类

```
POST /web/equipment-category/add
Content-Type: application/json
```

**入参**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| parentId | long | 否 | 为空/null = 新增一级分类；否则为父节点 id |
| name | string | 是 | 中文名，1~100 字 |
| nameEn | string | 否 | 英文名，≤200 字 |
| sortOrder | int | 否 | 不传自动追加到同级末尾 |

```json
{ "parentId": 61, "name": "喷油器", "nameEn": "FUEL INJECTOR" }
```

**响应 data**（`EquipmentCategoryAddVo`，编码已生成，可直接回显树）：

```json
{ "id": 62, "code": "6.001.002" }
```

**失败场景**：父节点不存在（803120102）、层级超上限（803120103）、编码冲突（803120101，并发极小概率，提示刷新重试即可）。

**典型交互**：选中新节点 → 点击「＋ 新增子节点」→ parentId 传选中节点 id；一级分类入口 → parentId 不传。

---

### 3.3 重命名

```
PUT /web/equipment-category/rename
```

```json
{ "id": 62, "name": "喷油器总成", "nameEn": "FUEL INJECTOR ASSEMBLY" }
```

**响应 data**：`null`（code=00000000 即成功）。

**约束**：仅中英文名可改；name 必填 1~100 字；nameEn 传空字符串/不传即清空英文名；编码、层级、父级不可改（没有对应接口）。

---

### 3.4 启用 / 停用

```
PUT /web/equipment-category/change-status
```

```json
{ "id": 7, "status": 0 }
```

**响应 data**：`null`。

**约束**：status 仅允许 0/1；停用后前台导航隐藏该节点及全部子孙（前端不用逐个处理子节点）；可随时重新启用（status 传 1）。

---

### 3.5 同级排序

```
PUT /web/equipment-category/sort
```

**入参**：拖拽结束后，把该父级下**全部**节点的 id 按目标顺序整体提交：

```json
{ "parentId": 61, "orderedIds": [611, 62, 613] }
```

**响应 data**：`null`；orderedIds 为空数组时视为无操作直接成功。

**失败场景**：任一 id 不存在（803120100）、任一节点不属于该父级（803120106，必须同父级整体排序）。

**前端实现建议**：树节点拖拽只允许同级内排序；drop 后取目标父级 children 的全量 id 顺序提交，成功后刷新树。

---

### 3.6 删除分类

```
GET /web/equipment-category/delete/{id}
```

示例：`GET /web/equipment-category/delete/62`

**响应 data**：`null`。

**失败场景**：节点不存在（803120100）、存在子分类（803120104）。

**前端实现建议**：删除前先做本地预检——树节点 `children.length > 0` 时直接禁用删除按钮/提示「先删除子节点」，减少无效请求。确认弹窗必配（删除为逻辑删除，可后台恢复数据但界面不可见）。

---

### 3.7 详情回显

```
GET /web/equipment-category/detail/{id}
```

示例：`GET /web/equipment-category/detail/61`

**响应 data**（`EquipmentCategoryDetailVo`；不存在时返回 code=非 00000000，data 为空）：

```json
{
  "id": 61,
  "parentId": 6,
  "code": "6.001",
  "name": "推进用柴油机",
  "nameEn": "PROPULSION DIESEL ENGINE",
  "level": 2,
  "sortOrder": 0,
  "status": 1,
  "updateTime": "2026/09/03 10:30:00",
  "updateBy": "张三"
}
```

编辑表单只允许改 `name`、`nameEn`（对应 3.3 重命名接口）；`code`/`level`/`parentId`/`status` 仅作展示。

## 4. 前台接口明细（询价嵌入页）

### 4.1 导航树（仅启用节点）

```
GET /web/portal/equipment-category/nav-tree
```

**响应 data**：`PortalEquipmentCategoryTreeNodeVo[]`，结构与后台树类似但**字段更少**（不含 parentId/sortOrder/status），且停用节点及其子孙已剔除：

```json
[
  {
    "id": 6,
    "code": "6",
    "name": "机械设备主要部件",
    "nameEn": "MECHANICAL EQUIPMENT MAIN COMPONENTS",
    "level": 1,
    "children": [
      {
        "id": 61,
        "code": "6.001",
        "name": "推进用柴油机",
        "nameEn": "PROPULSION DIESEL ENGINE",
        "level": 2,
        "children": [
          {
            "id": 611,
            "code": "6.001.001",
            "name": "主机柴油机",
            "nameEn": "MAIN DIESEL ENGINE",
            "level": 3,
            "children": []
          }
        ]
      }
    ]
  }
]
```

> **范围说明**：本期仅返回分类部分。最终形态是「分类节点 + 设备叶子」混合树，设备叶子由设备模块落地后按 id 挂入 children（接口契约不变，前端渲染逻辑无需预留特殊处理，按 children 递归渲染即可）。分类节点仅作导航，**点击分类节点不进入询价、不产生价格**（R-01）。

---

### 4.2 搜索（中英双语）

```
GET /web/portal/equipment-category/search?keyword={keyword}
```

示例：`GET /web/portal/equipment-category/search?keyword=diesel`

**入参**：

| 字段 | 位置 | 必填 | 说明 |
|------|------|------|------|
| keyword | query | 是 | 关键词，匹配 编码/中文名/英文名，不区分大小写；空白串返回空列表 |

**响应 data**：`PortalEquipmentCategoryPathVo[]`（**平铺列表**，非树；每项带完整路径文本，供导航树定位回显）：

```json
[
  {
    "id": 611,
    "code": "6.001.001",
    "name": "主机柴油机",
    "nameEn": "Main Diesel Engine",
    "level": 3,
    "pathText": "机械设备主要部件 / 推进用柴油机 / 主机柴油机"
  }
]
```

**前端实现建议**：输入防抖（300ms）+ 空关键词时切回整树渲染；命中结果点击后按 `pathText` 逐级展开导航树并高亮 `id` 节点。

## 5. 错误码表（本模块）

| code | 场景 | 前端处理建议 |
|------|------|------------|
| 00000000 | 成功 | — |
| 803120100 | 分类不存在或已删除 | 刷新树；提示「节点已被删除」 |
| 803120101 | 分类编码已存在（并发冲突） | 提示「请刷新后重试」 |
| 803120102 | 父级分类不存在 | 刷新树后重选父级 |
| 803120103 | 层级超出上限（5 层） | 禁止在 5 级节点下再展示「新增子节点」入口 |
| 803120104 | 存在子分类不可删 | 预检 children 后禁用删除按钮 |
| 803120105 | status 取值非法 | 前端固定 0/1 下拉，正常不会触发 |
| 803120106 | 排序节点不属于同一父级 | 排序严格取同一父级下全量 id |

其余非 00000000 的 code（系统异常、登录失效、无权限等）统一 toast `msg` 文案即可。

## 6. 典型对接流程（AI 辅助生成代码时的调用顺序）

**后台维护页**：

```
进入页面 → GET /tree 渲染树
  ├─ 一级分类「＋」 → POST /add {parentId: null}
  ├─ 选中节点「＋子级」 → POST /add {parentId: 选中id}
  ├─ 行内编辑名称失焦 → PUT /rename
  ├─ 置灰开关 → PUT /change-status
  ├─ 拖拽结束 → PUT /sort（同级全量 id）
  └─ 删除（children 为空才可点） → GET /delete/{id}
每次写操作成功后 → GET /tree 刷新整树
```

**前台询价页第一步（选设备）**：

```
进入页面 → GET /web/portal/equipment-category/nav-tree 渲染导航
搜索框输入（防抖） → GET /web/portal/equipment-category/search?keyword=xx
  ├─ 有命中 → 平铺展示 pathText，点击定位展开树节点
  └─ 无命中 → 展示「没找到？联系我们」咨询入口（FR-06，接口待设备模块）
点击树节点逐级展开；叶子层级的设备挂载由设备模块接口提供（本期占位）
```
