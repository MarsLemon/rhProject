# 🔴 附录：2026-07-19 max-effort code-review HIGH bug 清单

**对照前面"基本逻辑偏差体检"的结论——先前说"无重大偏差"是错的**。max-effort review（10 角度并行，48 candidate → 18 dedup → 15 final）暴露 7 个 HIGH bug，全部是 mobile vs v2 PC 行为分叉导致，直接影响生产。

## 7 个 HIGH bug（按 severity 排）

### H1. dashScopeFileIds 完全丢失（multi-round file-id 失效）
- 文件：`useChatSession.ts:413, 434`（老路径）；`sendMessage:479-486`；`loadHistoryDetail:771-772`
- mobile `sendMessage` 接收 options 但**没有 `dashScopeFileIds` 字段**；`generateAiResponse` 内部传 `streamChatCompletion` 时也没传。`loadHistoryDetail` 恢复 `msg.dashScopeFileIds` 但下游从未消费。retry/sendMessage/history 三条路径全丢。
- 触发：用户发文件 → 第二轮问"这份报告第三章" → 后端拿不到 file-id → 走无引用降级
- 对照 v2：`chatSession.js:261/302/317/338-347/757-766` 完整三路径透传

### H2. image_list/file_list 在 Agent 网关分支被丢（多模态坏）
- 文件：`chatStreamGateway.ts:84-137` `buildStreamParams`
- 仅从 history messages 内的 `fileList` 取，**未消费 `options.image_list`**（用户当场发的图）；无 `getPrivateFileUrlBatch` 签名调用
- 触发：用户当场发图提问 → Agent 网关拿不到图 URL → "AI 不读图"

### H3. TrainingAssistantView 直接调 chatAppStream，绕过灰度开关
- 文件：`TrainingAssistantView.vue:289`（openingRemark）、`429`（finishTrainingWithScore）
- 直接 `import chatAppStream`，**不经过 `streamChatCompletion`**。`VITE_USE_AI_GATEWAY=true` 时，开场白/评分仍走老 dashscope 直连；新网关拿不到 promptKey/kbList/dashScopeFileIds
- 触发：灰度开关开了 → 监控显示 agent 网关 0 流量但生产有 AI 回复 → 误判灰度失效

### H4. kbList 多选知识库被静默降级为单选
- 文件：`useChatSession.ts:483` / `502-504` / `529-536`
- `sendMessage` 接收 `kbList: string[]`，计算 `enableKb`，但 `generateAiResponse` 调用**没把 kbList 透传**（只有 `enableKnowledgeBase` boolean）。Agent 网关 buildStreamParams 收不到多选 → 走 `kbChoose='none'` 或单选
- 触发：用户选 training+gongwu 多选 → Agent 网关只接单选或 none

### H5. syncToBackend 不存 fileList/citations/thoughts/dashScopeFileIds
- 文件：`useChatSession.ts:223-262`
- payload 只含 askId/type/chatHistory/userId。对比 v2 `chatSession.js:597-661` 有完整 type=20/10 分支持久化（citations JSON.stringify / thoughts {items,duration} / fileList / dashScopeFileIds）
- 触发：用户发附件 → 杀进程 → 重进历史详情 → 附件图标/引用来源/思考过程全丢

### H6. HTTP status → errorCode 仅 3 分支，后端真实错误码被压平
- 文件：`common.ts:1098-1106` `chatAgentStream`
- 只识别 401/403/429 → AI_AUTH_FAIL/AI_RATE_LIMIT，其余一律 AI_INTERNAL+retryable=true。AI_QUOTA_EXCEED / AI_TOOL_FAIL / 5xx 全混作"稍后重试"
- 触发：额度用完 → 用户反复重试烧光配额；管理员收重试轰炸

### H7. buildStreamParams 缺 currentUserMsg 显式入参（P4 修复缺失）
- 文件：`chatStreamGateway.ts:84-137`
- 走"找 messages 最后一条 user 合并 fileList"路径。retry/撤回重发时，history 已被 buildHistoryContext slice 排除，导致 fileList 错挂到历史 user
- 触发：retry → file-id 错配 → 后端读到错的 fileList
