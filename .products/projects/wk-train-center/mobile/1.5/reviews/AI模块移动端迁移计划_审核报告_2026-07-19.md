## 二、计划假设 vs 仓库事实

### 2.1 致命偏差 #1：源选错（v2 → v3）

**计划声称**：
> v2 前端架构现状（wk-train-center-ui）：分层架构采用 DDD 风格分为 4 层——base（外壳）、conversation（会话领域）、modes（业务模式）、components（UI 子组件）、shared（共享工具）。

**仓库事实**：
- `wk-train-center-ui/src/views/web/ai/components/AiAssistant/` 确实是 vue2 版本，结构为 `base/` / `conversation/infrastructure/` / `modes/{answer,training}/` / `shared/` / `components/`
- **`wk-train-center-ui-v3/src/views/web/ai/components/AiAssistant/` 已经存在**，结构几乎与 v2 一一对应，但全部用 Vue 3 + TypeScript + Composition API 重写
- v3 的 `shared/` 目录已有：`markdownRenderer.ts` / `sanitizeHtml.ts` / `fileType.ts` / `historyTitle.ts` / `sseStream.ts` / `citationPreviewFacade.ts`
- v3 的 `modes/answer/` 和 `modes/training/` 都已落地，组件名同 v2

**影响**：计划把已现代化一轮的 v3 当成"未迁移"，会让"搬运"工作多绕一道弯——v2→v3 已经做过的事要重新规划。

**建议**：源改为 `wk-train-center-ui-v3/src/views/web/ai/components/AiAssistant/`，复用 v3 已经类型化、组合式化的版本。

### 2.2 致命偏差 #2：mobile 端已有 AI 骨架

**计划声称**：
> 移动端现状（wk-mhc-mobile）：现有 AI 功能：`ai-assistant.html`（WebView 页面）、`train-center.html`（培训中页面）；API 层基于 axios，有完整的拦截器和 token 管理。

**仓库事实**：mobile 端 AI 至少有 4 套入口在并存：

| 位置 | 性质 | 完整度 |
|---|---|---|
| `src/pages/smart-training/components/ai/` | 当前主入口 | **高**：`AnswerAssistantView.vue` / `TrainingAssistantView.vue` / `AiChatPanel.vue` / `AiInputBar.vue` / `AiMessageList.vue` / `AiHistorySheet.vue` / `AiVoiceRecordOverlay.vue` / `AiImageCapturePreview.vue` / `AiImageRecognitionPopup.vue` / `AiFilePreviewList.vue` / `AiCourseFilePicker.vue` |
| `src/composables/ai/` | 状态/适配层 | **高**：`useChatSession.ts` + `adapters.ts`（已含 `answerAdapter`）+ `splitChatAttachments.ts` + `types.ts` |
| `src/pages/ai/{index,history}.vue` | 旧入口 | 中：仍存在，未废弃 |
| `src/components/knowledge-Ai/` + `src/components/ai/` | 历史遗留 | 中：早期实现，可能已被 smart-training 取代 |

**计划规划的目录**（§2.3）：
```
wk-mhc-mobile/src/
├── views/                    ← 项目根本没有 views/ 目录，是 pages/
│   └── ai-assistant/
```

**影响**：
1. 计划规划 `views/ai-assistant/`，但 mobile 端用的是 `pages/` 目录
2. 计划规划 `composables/{useChatSession,useVoiceInput,useFileUpload,useAiAssistant}.ts` 4 个文件，**`useChatSession.ts` 已存在**
3. 计划规划 `components/{base,chat,nodes,file,training,preview}/` 6 个子目录，**mobile 端 `pages/smart-training/components/ai/` 已经是这套结构**

**建议**：目录规划对齐 mobile 现有 `pages/smart-training/components/ai/`，而不是从零搭一个 `views/ai-assistant/`。

### 2.3 数据失真 #1：chatStreamGateway 行数

**计划声称**：`chatStreamGateway.js`（734 行）

**仓库事实**：
- `wk-train-center-ui/src/views/web/ai/components/AiAssistant/conversation/infrastructure/chatStreamGateway.js` 实际 **347 行**
- 路径也不在计划的 `shared/` 范围内，而是在 `conversation/infrastructure/`
- v3 已经重写为 `shared/sseStream.ts`，且自带注释："继承 v2 chatAppStream 思路"——说明 v2 原文件可能叫 `chatAppStream.js` 而不是 `chatStreamGateway.js`

**影响**：计划的"核心通信机制"描述基于错误数据。

### 2.5 后端 SSE 协议对齐缺失

**计划声称**：
> SSE 事件协议：`thought_delta` / `tool_call_start` / `tool_call_delta` / `tool_call_end` / `reference` / `suggest` / `delta` / `complete`

**仓库事实**：v3 `shared/sseStream.ts` 注释明确写：
> "v3 简化 SSE 解析（只处理标准 data: / [DONE] 格式，不做 v2 复杂的 chunk 处理）"
> "后端真实 SSE API 端点待业务方提供（目前 store 走"占位 fallback"分支）"

**影响**：mobile 端如果直接复用 v3 `sseStream.ts`，就走"简化协议"；如果按计划搬 v2 `chatStreamGateway.js`，就走"8 事件协议"。**两种协议不能同时满足，必须先与后端对齐 `/aiGateway/chatStream` 真实事件格式**。

## 四、v2 问题审核报告的归宿（§6）

§6 是计划最有价值的部分。三个严重问题 + 四个中等问题，**不应该夹带在迁移 PR 里**，应该独立提单到 `wk-train-center-ui-v3` 仓库处理：

| 严重度 | 问题 | 归属 |
|---|---|---|
| 严重 | SSE 无重连机制 | v3 `sseStream.ts` 待加固，独立 issue |
| 严重 | tool_call JSON 解析脆弱 | v2 chatStreamGateway 问题，v3 简化协议已规避，标记"无需修复" |
| 严重 | OneTimeFileManager 上传无进度 | mobile 端 `AiFilePreviewList.vue` 评估后独立 PR |
| 中等 | historyContext 无上下文窗口限制 | mobile `useChatSession.ts` 评估是否需要加 |
| 中等 | markdownRenderer XSS 风险 | mobile 复用 v3 `sanitizeHtml.ts` + DOMPurify 双保险 |
| 中等 | voiceManager 录音无超时 | mobile 走 App Bridge 时由原生控制 |
| 中等 | TTS 无取消机制 | mobile 走原生 TTS（自带 cancel） |

**建议**：把 §6 整段抽到 `wk-train-center-ui-v3/docs/technical-debt/ai-module.md`，作为独立技术债清单，不绑定迁移 PR。

### 5.3 计划未覆盖的盲点（建议补）

1. **离线/弱网兜底**：mobile 切后台 SSE 必然断开，是否需要 store 持久化最后一条 AI 消息 + 重连后自动续接？
2. **WebView 版本碎片**：Android WebView 对 `fetch + ReadableStream + SSE` 支持参差，要不要 polyfill？最低支持哪个 Android 版本？
3. **iOS Safari 滚动穿透**：message list 长列表 + 输入框聚焦触发橡皮筋，是否需要 `overscroll-behavior`？
4. **国际化**：v2 硬编码中文文案，mobile 是直接继承还是切 i18n？mobile 项目本身是否已经有 i18n 方案？
5. **埋点/监控**：v2 PC 端 AI 模块埋点（哪些事件、字段、上报地址）如何映射到 mobile？
6. **灰度方案**：APP 端发版如何灰度——直接覆盖 `ai-assistant.html` WebView，还是新建入口 + 路由开关？
7. **安全区适配**：iPhone 刘海/灵动岛 + Android 全面屏 gesture bar，`AiAssistantShell.vue` 怎么适配？
8. **键盘弹起布局**：mobile 端输入框聚焦时键盘弹起，message list 怎么自适应？
