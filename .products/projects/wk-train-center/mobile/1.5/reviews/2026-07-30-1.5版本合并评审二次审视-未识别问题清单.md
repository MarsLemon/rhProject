## 三、评审**未识别**的问题(暴击区)

> 评审结论"全部 P0/P1 已修复、可发布"。下面这些会让发版翻车。

### 🔴 P0-致命(必须本迭代修复)

#### 1. `yf-web/pom.xml` deploy-to-server 钩子 — 凭证裸写在 pom.properties

- 默认值 `<skipDeploy>false</skipDeploy>` + `<deploy.host>47.104.4.152</deploy.host>` + `<deploy.user>root</deploy.user>`,本地 `mvn package` 默默往生产 IP scp + ssh 重启
- 即便有 `<skip>` 跳过,默认值仍为 false 极易踩雷;production 编译/部署口令以明文进 git,违反 GitOps 准则
- **修复**:默认 `<skipDeploy>true</skipDeploy>`,凭证走 `settings.xml` / env,加 `hostname` 校验,真正禁止本地误推

#### 2. `BusinessAskDemoController` 实际无鉴权 — SEC-A01 修复**未真正落位**

- 评审说"✅ 已修复",但控制器类本身没有 `@RequiresPermissions`,仅依赖外层(若有) Shiro 拦截器
- `/api/business/demo/ask` 是 AI 算力入口,任何登录用户都能调 `AgentInvoker.invoke()`,塞 `overrides` 改模型 / thinkingBudget 滥刷 token
- 同时该路径默认走 `QA_AGENT_ID`,等于给登录用户绕到 QA 链路
- **修复**:类级别加 `@RequiresPermissions("sys:config:prop")` 或至少新建 `@RequiresPermissions("ai:agent:demo")` 权限点

#### 3. `AgentInvoker.applyOverrides` — temperature/topP **静默失效**

- 文件注释自承"temperature/topP 当前在 ReAct 执行链路中未被消费,override 后暂不影响实际调用"
- 用户拖调试台 slider 改 temperature 没有任何效果,但前端 UI 暗示可生效 → **信任崩塌**
- **修复**:`BailianChatRequest` / `ResponsesRequest` 已加 `.temperature(...)` 接线,但 AgentInvoker 的 overrides 进 `ReactRequest.modelOverride` 后未贯穿到 Executor 的请求构造;需在 `AgentReActExecutorImpl.pickTemperature` 处确认 modelOverride 真传到 chatReq/responsesReq(已部分做,但 Responses 路径只有 temperature+topP,**缺 thinkingBudget,且 maxOutputTokens 未接线**)

### 🟠 P1-严重(下迭代必修)

#### 4. SQL `<trim prefix="AND (" suffix=")">` 残尾空 WHERE

- `StatScoreRangeMapper.xml` 与 `StatTotalScoreMapper.xml` 把 `<where>` 改成 `<trim prefix="AND (" suffix=")" prefixOverrides="OR">`
- 三个 `<if>` 全空时生成 `WHERE ... AND ()`,MySQL 严格模式 SQL syntax error;Oracle/PostgreSQL 必挂
- 评审只点了"部门人数 SQL 补 state=0",完全没扫**同文件同作者的其他 Mapper 改写**
- **修复**:trim 加 `prefixOverrides="OR|AND"` 后验证空集合语义,或外层用 `<where>` 包内层 `<trim>`

#### 5. `AgentConfigResolver.merge` 使用 `readerForUpdating` — 已知 Jackson 坑

- `readerForUpdating` 会把 fallback 对象就地修改。fallback 是 `@Cacheable` 返回的共享对象 → 二次调用读到的就是被合并过的对象,**污染缓存**
- 此外 `Models` 是 `Double/Integer`,DB 里若存 `"0.7"` 字符串,Jackson 反序列化可能保留原类型 → 后续数值比较全错
- **修复**:merge 前 `objectMapper.readValue(dbJson, fallback.getClass())` 创建新对象,或 fallback 每次新建

#### 6. `@Cacheable` 返回含 `AiAgentEntity` 的 `LinkedHashMap` — Redis 序列化爆雷

- `AgentConfigQueryServiceImpl.loadFullConfig` 把 `AiAgentEntity` 字段塞进 Map 缓存;Entity 没 Serializable,Redis Cache 序列化失败
- 同类问题:`AgentConfigServiceImpl.getDefaultModel()` 调 `resolvedModels().getDefaultModel()`,DB 一行配置变更 → `@EvictAgentCaches` 清了 `ai:agent:config`,但 yml fallback 字段(`react.enabled=true`) 永远返回硬编码 true,不与 DB 行互动
- **修复**:Entity 实现 Serializable,或缓存层只放纯数据 Map

### 🟡 P2-中危

#### 7. `AgentConfigResolver` 默认 `resolvedReact.enabled=true` 是硬编码

- 即便 DB 把 `react.enabled` 显式置 false,fallback 还是 true 覆盖回去
- 用户在控制台关 ReAct 实际不生效
- **修复**:`fromPropertiesReact` 不预填 enabled,由 DB 完全控制

#### 8. `useTableQuery.js` 中央防线基于 `JSON.stringify` 比较 — 性能 + 顺序陷阱

- 评审 F-PERF 提了,但没指出:同一引用不同 key 顺序的 ListQuery 在 Strict-Equal 失败,会**误清选中**
- 大量请求场景下 stringify 大对象卡 UI 线程
- **修复**:用浅比对 + watch on params 引用即可,或存 hash 而非 stringify

#### 9. `@xenova/transformers` 删除 + vendor 分包排除 → 旧 chunk 名仍被 prefetch 屏蔽列表引用

- `prefetch.fileBlacklist` 删了 `chunk-transformers`,但 `vue.config.js` 的 externals/externals 路径里仍残留引用
- 评审未触及:删除依赖前先确认没有别的入口间接引用,目前残留在 prefetch 注释和(已删)Gzip 白名单

#### 10. `vue.config.js` `performance.hints` 仅按 isDev 切换 → dev 跳过体积警告

- 调试大型文件时不再有警告,29.6MB app.js 类问题可能复发
- **修复**:dev 设 `hints: 'warning'` 但 `maxAssetSize: 500000`(放宽阈值),而不是直接关

#### 11. `agent/index.vue` 单文件 1124 行 + 5 区块 — F1 修复是 false positive

- 评审 F1 提了"agent/index.vue 285 行",但实际新建的 `agent/index.vue` 是 **1124 行**,远超标称
- 评审 F1/F2 "已修复" 与实际不符 — 只新建了周边文件(ChatStreamGateway 等),主文件未拆
- **修复**:把 AgentManager 拆为 `AgentListPanel` / `AgentConfigPanel` / `AgentDebugPanel` / `AgentDiffDialog` / `AgentCreateDialog` / `AgentCopyDialog` 6 个子组件

#### 12. `DepartTreeSelect.vue` slot-scope 中 `data[props.value]` 误用

- 在 el-tree v-slot 解构后 `props` 是父组件 props(改写是 `props.value`),不是子节点 data,这里直接写 `data[props.value]` 实际能跑但**语义错乱**,后续若有人加 data 字段会触发同名混淆
- **修复**:slot-scope 解构应 `{ node, data }`,直接用 `data.deptCode`

### 🟢 改进项

#### 13. `.claude/settings.local.json` 已加 .gitignore,但 `wk-modules/wk-module-ai/` 没有任何 agent 配置项被忽略

- 评审 G6 通配权限 `*` 缺文档,但更关键:`PermissionDirective` 前端 `permission.js` 通配只覆盖前端 `v-permission`;后端 `@RequiresPermissions("sys:config:prop")` 与前端权限串可能不一致
- **修复**:前后端权限串对齐测试 + 通配权限文档化

#### 14. DB 初始化脚本 `ai_agent_config.enabled=1` 过滤 — Mapper 文件未确认

- `AiAgentConfigMapper.xml` 用 `enabled=1`,但 `AiAgentConfigEntity` 没 `enabled` 字段或字段名差异可能直接导致死查询(无法证实,需打开 mapper 确认;但评审同样未触及)
- **修复**:打开 `AiAgentConfigMapper.xml` 与 `AiAgentConfigEntity.java` 对照,确认 enabled 字段映射正确
