## 2. 后端实现

### 2.1 `wk-module-ai-gateway` 新建

参照 [README.md §4](README.md#4-架构分层后端新建-wk-module-ai-gateway)。

关键文件:
- `api/AiGatewayController.java` — `@PostMapping("/{appKey}/chat-stream")`,返回 `SseEmitter`
- `api/AiGatewayAppExceptionHandler.java` — 统一 envelope
- `application/AiChatService.java` — 入口编排
- `domain/port/ChatProviderPort.java` — 抽象
- `infra/provider/bailian/BailianChatProvider.java` — 实现:接 `BailianConfigDTO` + dashscope OpenAI 兼容 endpoint
- `infra/config/AiGatewayProperties.java` — `appKey → appId` 映射、灰度配置

### 2.2 appKey 注册

```yaml
# application-local.yml
ai-gateway:
  apps:
    answer_assistant_app: { appId: "e23e7edc65dc48968e114e0a7051668f", provider: bailian, bizParams: {} }
    training_assistant_app: { appId: "fa6fc426f1c24cfd87502f537e320b64", provider: bailian, bizParams: {} }
  fallback:
    enabled: true                       # 总开关
    userIds: []                          # 白名单(空=全量走新)
```

### 2.3 灰度判逻辑

`AiGatewayController` 入口:
```java
boolean useNew = featureToggle.isEnabled(userId, appKey);
if (!useNew) return fallbackToOld(appKey, request);  // 转发到 /api/ai/legacy/**
```

→ 老逻辑入口必须保留 100% 可用,M1 必修。

## 4. 前端 v2 切换

### 4.1 新增 `src/utils/sse-client.js`

公共 SSE 客户端(替代散落的 `chatAppStream` 解析逻辑):
- `connect(url, options, callbacks)` → EventSource 封装
- 内部按 `data: {type:...}` 反序列化
- 支持 AbortSignal、重连(`retry: 3, backoff: 1s/2s/4s`)
- 异常统一抛 `fallback: true` 时上层切老逻辑

### 4.2 答疑页切流

[src/views/web/ai/components/AiAssistant](wk-train-center-ui/src/views/web/ai/components/AiAssistant) 改造:
- `chatStreamGateway.js` 改 `import { postSSE } from '@utils/sse-client'`
- `buildStreamParams` 改成 `buildGatewayParams`(去掉 `appId`,改 `appKey`)
- `getBailianAppIdByAssistantMode` 保留(老逻辑兜底用),新增 `getAppKeyByAssistantMode`
- 加灰度判断:`localStorage.getItem('ai:gateway:enabled')` 为 true 才走新

### 4.3 不切流的端点

- 出题(`quiz_gen_agent`)、陪练(`training_assistant_app`)本期**保持老逻辑**,M2 再切
