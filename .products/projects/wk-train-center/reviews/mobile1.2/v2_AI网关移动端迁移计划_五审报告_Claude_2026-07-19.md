## 12 HIGH + 3 MEDIUM

### 🔴 HIGH（12 条 — 建议下一轮立即修）

#### H1. 后端契约类型全字段错位（7 字段合一）
- 文件：`wk-mhc-mobile/src/pages/smart-training/composables/ai/types.ts:103-116`
- 字段错位清单：
  - `ToolStep.result: string` ← 后端 `toolResult.results: List<Map>`
  - `thoughts[].observation: string` ← 后端实际是 `Object {content: Array<Map>}`
  - `citations` 缺 `content`(snippet)字段
  - `usage.promptTokens/completionTokens` ← 后端**只发** `totalTokens` + `searchCount`
  - `errorMessage` 字段 ← 后端用 `chunk.content` 承载，**不存在**此字段
  - `toolCall` 缺 `toolType` 字段（区分 KB/web/code）
  - `errorCode: number` ← 实际后端用 string（如 `AI_AUTH_FAIL`）
- 影响：UI 渲染 `[object Object]`、`msg.usage` 永远 undefined、KB/网页/代码工具无法区分

#### H2. UI 不渲染 msg.toolSteps / AI 生成 fileList
- 文件：`AiMessageList.vue:218, 247`
- chatStreamGateway 已累积 `msg.toolSteps` / `msg.fileList`，但 AiMessageList 不消费
- AI 生成 PPT/报告附件完全看不见
- 工具调用时间线对用户不可见

#### H3. 训练模式 promptKey fallback 到 answer_assistant
- 文件：`TrainingAssistantView.vue:289, 429` + `useChatSession.ts:473`
- opening remark / score / 日常对话 三处均未传 `promptKey`
- mobile `chatStreamGateway.ts:144` 走 `appId.includes('training')` 兜底 `'answer_assistant'`
- **影响**：训练模式走答疑 prompt，角色化指令失效

#### H4. Citation 渲染缺字段 + 缺 kbLabel + 缺详情展开
- 文件：`AiCitationList.vue:31-39`
- name fallback 只查 `title`，不查 `doc_name/dataName/name` → "未知来源"
- 缺 `kbLabel` 标签（M1.0 网关 D29 决策）
- 缺 expandable detail 渲染 KB 检索的 snippet

#### H5. UI 双渲染 typing indicator + thoughts section
- 文件：`AiMessageList.vue:236`
- thoughts 流式时同时显示 thoughts panel 和"思考中"dots
- PC v2 显式抑制 typing indicator when thoughts exist

#### H6. 长按 550ms timer 无 touchmove 取消
- 文件：`AiMessageList.vue:175`
- 用户滚动 550ms 即触发 action sheet
- 移动端独有 UX bug，PC 无对应

#### H7. loadHistoryDetail 无 isLoading 守卫
- 文件：`useChatSession.ts:780`
- 切换历史时旧流继续写，孤儿记录入库
- isLoading 可能错乱

#### H8. onDone isLoading=false 早于 syncToBackend
- 文件：`useChatSession.ts:447`
- 用户可立刻发新消息，旧 AI 还在落库
- addRecord 同 askId 双写，index 错位

#### H9. 缺 AI_TOOL_FAIL → AI_INTERNAL 降级
- 文件：`useChatSession.ts:365`
- PC v2 有（`chatSession.js:549-557`）
- KB 工具成功但 LLM 后续 IO 异常 → mobile 误报"工具失败"

#### H10. 缺 msg.toolCallError 字段
- 文件：`types.ts:22`
- PC v2 写 `msg.toolCallError`，UI 可显式错误态
- mobile 错误码丢失，埋点/恢复无法做

#### H11. SSE error 时未 flushPendingThoughts
- 文件：`chatStreamGateway.ts:489-502`
- PC v2 gateway 在 onError 前 flush
- mobile 错误前最后一批思考丢失

#### H12. opening remark 持久化孤儿 rows
- 文件：`TrainingAssistantView.vue:302`
- `syncToBackend('system', ...)` 和 `syncToBackend('user', L.openingPrompt, ...)` 无 messageIndex
- `bindMessageIndex` 找不到匹配 → 孤儿行入库
- 历史回放计数错乱

## 教训

1. **静态类型 ≠ 运行时兼容**：`types.ts:103-116` 定义看似完整，与后端 `AgentChatChunkVo.java` 完全对不上。TypeScript 类型保护只在开发期有效，运行时 chunk 反序列化后类型全错。
2. **多轮 deep-scan 比单轮 review 强**：本轮发现 12 HIGH，上轮只发现 7 HIGH。3 轮扫描把"路径分叉静默丢字段"问题系统性挖出来了。
3. **场景模拟优于源码阅读**：轮 3 walkthrough 8 个 user 场景，找到 loadHistoryDetail 无守卫、opening remark 孤儿行、currentUserMsg dead code 等源码读时根本看不到的 bug。

下次 mobile vs PC 对比任务，**默认走 3 轮 deep-scan**，不再单轮拍板。
