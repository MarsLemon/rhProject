### Row 10 — 学习任务 · 一键补考(必带延期)

| 字段 | 内容 |
|---|---|
| 功能模块 | 学习任务 |
| 需求名称 | 一键补考(必带延期) |
| 需求类型 | 功能需求 |
| 提出人 | 杨晓鹏 |
| 优先级 | 1 |
| 业务相关方 | 人力资源部 |
| 需求详情 | 考试未通过的学员需批量重设补考;当前无法批量;**且补考必须同步设置补考时间(等于强制延期)** |
| 系统解决方案 | 1. **入口同样在"学习任务总览"页**(与 row9 一键延期并列)<br>2. 一键选中所有考试"未通过"学员;**每人的每一门未通过考试均纳入补考池**<br>3. 弹窗:人员/考试明细列表 + 补考时间(**必填**)<br>4. **业务硬约束:补考时间 = 延期时间,不可只补考不延期**;弹窗顶部红字提示"补考一定伴随延期"(源:docx 原文"补考是一定要延期的")<br>5. 多次补考可循环执行;**补考通过的学员自动划入"已完成",不再纳入下次一键补考范围**<br>6. 补考完成后,补考通过者的"最终考试时间"与"考试次数"落入任务维统计 |
| 验收标准 | 1) 总览页有入口;<br>2) 未通过/未完成两类操作**互不误伤**(只改各自目标池);<br>3) 补考必须带时间,无时间**不可提交**;<br>4) 通过者自动从补考池剔除;<br>5) 补考次数可在任务明细页查询 |
| 备注 | 与 row9(延期)**不可合并**:虽然技术上可合并到同一按钮组,但**"补考必带延期"这条硬约束必须独立成行**,才能在验收阶段被明确卡住;docx 研讨也明确拆为两步操作 |

### Row 11 — 学习任务 · 概览字段补全与列布局优化

| 字段 | 内容 |
|---|---|
| 功能模块 | 学习任务 |
| 需求名称 | 概览字段补全与列布局优化 |
| 需求类型 | 功能需求 |
| 提出人 | 六世豪 |
| 优先级 | 1 |
| 业务相关方 | 人力资源部 |
| 需求详情 | 概览当前仅有"完成/未完成"两类,无法支撑数据汇总;字段乱、加载慢;明细数据(学习时长/分数/次数)放概览页致列表崩溃 |
| 系统解决方案 | 1. **列布局改为 4 列**:姓名(**左固定**) / 开始时间 / 完成时间 / 总完成状态(**右固定**);**中间**依次为:课程项目数、课程完成情况、考试项目数、考试完成情况<br>2. **总完成状态 = 课程 + 考试汇总**(各列下设合并行样式,源:docx "两两行合一行")<br>3. **概览页不展示**:课程学习时长/考试分数/考试次数 — **这些全部下沉到节点明细页**(防列表崩,源:docx "统一放到对应节点的明细页面展示")<br>4. **数据双源**:<br>　- 任务维度 — 仅统计**当前任务内**的考试/课程数据(考试次数、分数、最终通过时间)<br>　- 全局维度 — 全量考试数据**单独留存**,与任务维数据互不干扰<br>5. 筛选条件:支持"课程未完成"勾选;支持一键延期/一键补考入口(row9/row10)<br>6. 状态枚举统一:<br>　- 考试:完成中 / 未通过 / 未开始(原"进行中"统一改为"未通过")<br>　- 课程:已完成 / 进行中(等同未完成) / 未开始 |
| 验收标准 | 1) 列固定生效(姓名左、总状态右不滚动);<br>2) 课程学习时长/考试分数/考试次数**不**在概览出现,只能在节点明细查;<br>3) 任务维与全局维数据源**物理隔离**;<br>4) 状态枚举与原口径一致(进行中=未完成,考试"进行中"=未通过);<br>5) 筛选/批量操作可用 |
| 备注 | **吸收原 row5「学习任务-数据统计」**(原 row5 仅描述"乱、没法用",本行给出完整方案);原 row5 在本表删除 |
