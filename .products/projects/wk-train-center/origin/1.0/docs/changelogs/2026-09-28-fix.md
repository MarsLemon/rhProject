## 修复白话(按时间顺序)

### T1 阶段(Critical 必修)

#### T1.1 删除年度培训计划功能

**什么问题**:年度培训计划收集这个功能,代码写了但后端根本没接口对应。9 个接口点了都是 404。管理员菜单一直 loading 转圈,学员填报入口也是坏的。

**怎么改的**:整个前端目录都删了。删了 8 个文件 + 4 个空目录。后端代码碰都不碰(DB 表保留,以后想用可以重启)。

**影响**:管理员菜单里"年度培训计划收集"没了(以前点了也是 404)。数据库里数据保留,以后真要用可以重做。

#### T1.2 培训计划删除时不清理学员数据(领域事件模式首次应用)

**什么问题**:管理员点"删除培训计划",系统只删了计划本身。学员端还能看到已删计划的进度,补考通知还是会发到学员那——完全是孤儿数据。

**怎么改的**:
- 新建 `PlanDeletedEvent`(领域事件,跨模块清理用)
- 新建 `PlanDeletedPlanUserListener`(监听者,主事务提交后才触发)
- 新建 `PlanMakeupService`(原来只有 Mapper,没有 Service,Listener 没法注入)
- `PlanUserService` 和 `NodeService` 加 `removeByPlanId()` 方法
- `PlanServiceImpl.delete()` 改为发布事件,不再直接跨域调用

**为什么这样设计**:以前 PlanService 直接调 UserService/CourseService,违反 DDD 跨域边界。现在通过事件解耦,主事务回滚时 Listener 不触发,数据一致。

**影响**:管理员删计划后,学员端立刻看不到已删计划进度。补考通知不会再指向已删计划。

#### T1.3 课程删除时不校验不级联(course 模块同样抽事件)

**什么问题**:课程被删后,学员的学习进度变成孤儿。管理员可以删已有学员在学的课程——无任何阻止。

**怎么改的**:
- 加校验:`courseLearnService.countByCourseId() > 0` 抛"已有 X 名学员学习,无法删除,请改'禁用'"
- 新建 `CourseDeletedEvent` + `CourseDeletedCourseLearnListener`(course 模块示例)
- `CourseLearnService` 加 `countByCourseId()` + `detachPlanIdByCourseId()`(脱钩 plan_id,不物理删学习记录保留学时)
- 合并修复 B-002 + B-009

**影响**:管理员不能再物理删除有学员学习的课程,必须改"禁用"。如果以后允许"彻底删除",监听器会脱钩 plan_id。

#### T1.4 AI 答疑模块加字段

**什么问题**:AI 陪练历史无法关联到具体培训计划/节点,所有陪练记录混在一起。学员端"AI 陪练历史"看不到是哪个任务的陪练。

**怎么改的**:`TrainingRecordEntity` 加 `planId` + `nodeRefId` 2 个字段。数据库 v1.2 DDL 早就加了,代码一直漏声明。Service/DTO 透传下一轮做。

**影响**:字段加了但 Service 还没接业务,前端传 planId 也存不进去(下一轮兼容性增强)。

#### T1.5 站内信加路由字段(跳过,等 DBA)

**什么问题**:站内信点通知只能跳到模板默认页,跳不到"加业务页"(补考/延期/学习任务)。决策文档 2026-06-24 已经立项 row7,但代码没做。

**怎么改的**:**本次跳过**(主公 2026-09-28 拍板:需 DBA 排期 1.5.2/notify/msg-add-route.sql 新建 DDL,留到下一轮)。

#### T1.6 事务内定时任务泄漏(afterCommit 钩子模式)

**什么问题**:培训计划保存失败回滚了,但定时任务还是被写了——"学员收到通知但任务找不到"。

**怎么改的**(主公 2026-09-28 拍板:**仅修 plan 模块 7 处**,其他模块历史代码低风险慢慢修):
- 6 处事务内 `addCronJob` 改 `TransactionSynchronizationManager.registerSynchronization(afterCommit)`,主事务提交后才写 Quartz
- `PlanFirstCheckJob` jobName 从 null 改固定 `"PlanFirstCheck_<planId>"`,JobServiceImpl 已先 deleteJob 后 scheduleJob 自动幂等
- 加 `isSynchronizationActive()` 守卫,兼容非事务场景(测试/Job回调)

**影响**:培训计划保存失败,定时任务不再落地。重复保存计划,定时任务不再堆积。

#### T1.8 节点软删除过滤误伤历史数据

**什么问题**:节点软删除字段(`deleted`)过滤,缺这种值的行(历史数据 `deleted IS NULL`)会被误过滤。学员"重新解锁"流程卡死。

**怎么改的**:用 `.eq("deleted", 0)`(依赖 db/1.2/upgrade_v1.2_all.sql 加 el_plan_node.deleted DEFAULT 0,主公 2026-09-28 确认 DBA 已执行)。

**影响**:测试兼容性 OK + 真实环境工作正常。早期我用 `IFNULL(deleted, 0) = 0` 反而测试失败,改回 `eq("deleted", 0)`。

#### T1.9 节点通知三个功能假实现

**什么问题**:"只通知未开始学员""提前 N 天提醒""定时发送"三个功能在 UI 上有,但选了等于没选——后端只 log.info 一行,没真过滤,没真调度。

**怎么改的**:
- scope=2 真实过滤:`PlanUser.state=0` 交集
- trigger=false 真实调用 `jobService.addCronJob` + `CronUtils.dateToCron`
- enableAdvance + advanceDays 真实消费,生成 job 在节点开始前 N 天提醒

**影响**:管理员选的"未开始学员"真的只发给未开始学员,"提前 N 天提醒"真的会调度,"定时发送"真的会定时触发。

#### T1.10 编辑计划删节点,学员进度静默丢失改抛异常

**什么问题**:管理员编辑计划删节点,学员的进度被静悄悄丢了。管理员完全无感知,学员端"我的学习"完成度倒退。

**怎么改的**:`migrateProgress` 收集所有无法迁移的 refId + nodeType,一次性抛 `ServiceException`,前端可捕。

**影响**:前端收到异常后弹 confirm 让管理员确认"这些进度无法迁移,是否继续"。管理员有感知。

#### T1.11 开始培训无防丢锁(前后端双层防护)

**什么问题**:管理员连续点"开始培训",高并发插重复 `PlanUser` 行,完成率超过 100%,学员收到 2-3 条重复通知。

**怎么改的**(双层):
- 前端 `updatePlanState` 加 `stateLoadingMap[id]`,planId 维度锁
- 后端 `PlanUserClientServiceImpl.firstStart` 加 `@RedisLock(key = "'plan:start:' + #planId + '-' + #userId")`,锁粒度 planId + userId

**影响**:连续点击或绕过前端直接调 API 都会拦截。完成率数据不再 >100%。

## T3 阶段(Medium 业务性能 + 字段冗余 + 前端细节)

T3.x 共做了 4 个 commit,实际修复 5 项(经验 15 验证后跳 10 项,理由充分):

### T3.1 业务性能 3 项修

#### B-025 题库统计 1 次 GROUP BY 替代 25 次 SELECT COUNT

**什么问题**:题库统计每次访问要 25 次 SELECT COUNT(0)全表扫。大题库(10 万+)单次 5-8 秒。

**怎么改的**:
- 新建 `StatRepoMapper.groupByTypeLevelCount` 接口 + XML
- SELECT qu_type, qu_level, COUNT(*) FROM el_qu WHERE repo_id=? AND qu_type IN(?) AND qu_level IN(?) GROUP BY qu_type, qu_level
- Java 端 pivot 成 5×5 矩阵

**影响**:25 次 → 1 次 SQL,大题库首屏从 5-8 秒降到 <1 秒。

#### B-026 1000 updateById → updateBatchById

**什么问题**:`migrateProgress` 每个 entry 内 N 条进度 = N 次单条 UPDATE = 1000 条 = 1000 次 DB round trip。

**怎么改的**:同 entry 内 progressList 一次性 `updateBatchById`,减少 round trip。

**影响**:整体 N 个 entry × 1 次 batch,远比 N*M 次快。

#### B-029 //@CacheEvict 注释打开(2 处)

**什么问题**:模板修订后缓存不失效,继续走旧数据 → 学员答对判错 / 答错判对(评分事故)。

**怎么改的**:`ExamQuCorrectServiceImpl.firstCorrect` + `TmplQuServiceImpl.saveAll` 打开 `@CacheEvict(value = CacheKey.EXAM_TMPL, allEntries = true)`。

**影响**:模板修订后学员侧立刻看到新模板(不再走旧缓存)。

### T3.3 字段冗余 3 项修

#### B-031 MsgServiceImpl.save 抛 UnsupportedOperationException

**什么问题**:空方法静默吞调用,误调用方无感知。

**怎么改的**:抛异常提示用 sendNotify。

#### B-033 PlanDTO.fromCopy 加 @JsonIgnore

**什么问题**:内部标记未加 JsonIgnore,序列化为前端后可能干扰前端业务逻辑。

**怎么改的**:加 `@JsonIgnore` 阻止 Jackson 序列化。

#### B-035 __splice_abc 不静默

**什么问题**:`catch (NumberFormatException ignore)` 让脏数据整条消息 splice 全丢。

**怎么改的**:`log.warn` 留痕(ibatis Log 单参数拼接)。

### T3.4 前端细节 1 项修

#### B-043 公告列表时间显示加东八区时区

**什么问题**:`moment(time).format('YYYY-MM-DD')` 默认浏览器本地时区,服务端 UTC + 浏览器 tz 不一致 = 日期显示错位(跨日)。

**怎么改的**:`moment(time).utcOffset('+08:00').format('YYYY-MM-DD')` 强制东八区。

#### F-010 错误信息不直接展示 err.message

**什么问题**:`发布失败:${err.message}` 可能含后端 SQL/堆栈等敏感信息,直接给前端用户看。

**怎么改的**:`console.error` 留痕(开发者调试),前端展示固定文案。
