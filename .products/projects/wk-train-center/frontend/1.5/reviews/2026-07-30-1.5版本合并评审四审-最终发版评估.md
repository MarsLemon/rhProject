## 三、三审自身遗漏的真问题

三审评级 A 的关键依据是"全部 P0/P1 已修复"。但下面 3 个问题三审完全未触及或定性错误,**会直接影响发版决策**。

### 🔴 P0-致命

#### 1. `yf-web/pom.xml` deploy-to-server 钩子(三审说"不在本次代码审查修复范围")

- 三审把这条划入"环境/基建类,不在代码审查范围" — 但这是 `pom.xml` 改动,本质是构建配置改动,**就是代码审查范围**
- 默认值 `<skipDeploy>false</skipDeploy>` + 凭证裸写,本地 `mvn package` 即可触发 scp 到生产 IP
- 三审把它"移出评审范围"是**判断失误**,这恰恰是发布流程最危险的踩雷点
- **结论**:此问题三审误判为"非代码范围",实际属于构建脚本 + 部署凭证的双重红线,必须本迭代处理

### 🟠 P1-严重

#### 2. `AiConfigController /all` 路径的鉴权范围(评审仅说"✅ 已修复",三审未复核)

- 三审验证 `AiConfigController.java` 第 60、86 行有 `@RequiresPermissions("sys:config:prop")`
- 但 `/all` 路径返回内容含 API Key 范围是否真被该注解覆盖,需对照接口映射 — **三审未做接口与注解的端到端对照**
- 一审 SEC-A02 原始描述"返回内容包含 API Key,应限制为管理员" — 三审只看了类级别注解存在,未验证方法级别路径 `/all` 实际位置

#### 3. `AgentInvoker.applyOverrides` 的 `temperature/topP` 静默失效注释仍在

- 三审只确认了 `maxOutputTokens` 接线(Chat 路径),但**没复盘原文件注释**:
  > "temperature/topP 当前在 ReAct 执行链路中未被消费(BailianChatRequest/Responses 请求体均不携带),override 后暂不影响实际调用"
- 即便 maxOutputTokens 已加,前端的 temperature/topP slider 仍是"无操作" UI
- 三审应在 maxOutputTokens 修复批次同步处理 temperature/topP,否则 UI 仍误导用户
