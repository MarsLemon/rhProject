## 一、P0 上线阻断（1 项，必须上线前处置）

### P0-1｜后端构建默认自动部署：任何 mvn package 都会推 jar 并重启远程 dev 服务器
- **位置**：`wk-train-center-service/yf-web/pom.xml:20-26`（属性）+ `:262-297`（antrun deploy execution）
- **现状**：注释声称"不打 -Ddeploy.env 时 skipDeploy=true、默认不推送"，但实际属性为 `<skipDeploy>false</skipDeploy>` + `<deploy.env>dev</deploy.env>`，antrun 绑定在 package 阶段（`<skip>${skipDeploy}</skip>`），会 scp jar 到 root@47.104.4.152:/opt/wk-train-center/dev/ 并执行 run.sh restart。
- **风险**：注释意图与实际行为完全相反。上线窗口期任何人（开发本地、发布人员、CI）执行普通 `mvn package` 都会把构建产物推到 47.104.4.152 并重启服务，可能打断测试/预发环境。三位审查员独立命中同一问题。
- **修复**：改为 `<skipDeploy>true</skipDeploy>`（与注释一致），正式部署显式 `-DskipDeploy=false`；发布演练确认构建命令不触发该钩子。一行改动。
- **修复状态**：✅ 已修复（2026-08-03，L22 已改为 `<skipDeploy>true</skipDeploy>`，工作区未提交，待随版提交）

## 二、P1 上线前必须处理（7 项）

### P1-1｜Agent 管理页菜单数据未随版提供，功能可能对所有人不可见
- **位置**：前端路由完全由后端菜单表驱动（`wk-train-center-ui/src/store/modules/permission.js:101-109`），无静态 agent 路由；随版 SQL 目录 `.products/projects/wk-train-center-service/db/1.5/` 仅含 3 个脚本，无菜单 INSERT。权限点（sys:config:prop）本身无缺口。
- **处置**：上线前人工确认目标库菜单表已存在 Agent 管理入口；若无，补菜单 INSERT 随上线执行。

### P1-2｜数据库脚本硬前置（必须在后端发布前执行完毕）
- `db/1.5/ai/01_ddl_ai_agent.sql` + `02_dml_ai_agent_init.sql`：ai_agent/ai_agent_config 双表 + ai-qa-assistant 种子数据。表缺失时 Agent 管理页全部报错；聊天主链路虽有 yml fallback，但 SSE 超时/限流将回退默认值（限流 20s→10s）。
- `db/1.5/repo/01_ddl_repo_unique_title.sql`：el_repo 唯一索引（title, create_by，**不含 deleted 列**）+ 存量去重归并 DML（会改写 el_qu.repo_id、软删重复题库）。
- **处置**：按 ai → repo 顺序执行；repo 归并 DML 建议低峰窗口执行并先备份（不可逆）；向业务说明"删除过的题库名不能原样重建"（同名软删库存在时导入新建会唯一键冲突）。

### P1-3｜service 与 v2-ui 必须同一窗口上线（三处硬耦合破坏点）
1. fileList `List<String>`→`List<FileItem>` 硬破坏：AgentChatRequestDto.java:105、TrainingRecordAddDto.java:40、AnswerRecordAddDto.java:31、AnswerImportRecordDto.java:34。新旧任一端错配 → 聊天带附件直接 400。
2. `POST /dashscope/upload-token` 端点删除（WkAiAgentController.java:304 改为后端代理上传）→ 旧前端 404，附件上传全断。
3. 超管权限改为返回 "*"（SysUserServiceImpl.java:415-422）→ 旧前端 permission.js 无通配判断，超管所有 v-permission 按钮全部隐藏。
- **结论**：service 与 v2-ui 任何发布先后差都会造成功能性故障，必须同发。mobile 向后兼容可独立发布，但建议同批。
- **回滚警示**：新版本产生的 chatHistory 为 FileItem 对象格式，回滚旧后端会导致新会话历史读取异常；唯一索引/归并 DML 不可逆。回滚预案须以"前端同步回滚 + 接受新会话记录异常"为代价评估。

### P1-4｜会话级 suggestions 导入后被静默丢弃（功能承诺未兑现）
- **位置**：`wk-modules/wk-module-ai/.../AnswerRecordAppOpServiceImpl.java:58-107`（importSession 全文无 getSuggestions 调用）；`AnswerImportRecordDto.java:36-44`（toRecordCommand 不传 suggestions）
- **现状**：AnswerImportDto 把会话级 suggestions 装进 AnswerImportCommand（Javadoc 承诺"导入后挂到最后一条 AI 回复"），但 importSession 从不消费；Factory 消费的是记录级 AnswerRecordCommand.getSuggestions()，恒为 null。前端 AnswerAssistantView.vue:276 确实发送了 suggestions → 导入后静默丢失。
- **修复**：importSession 在 save 前将 command.getSuggestions() 挂到最后一条 AI 回复记录，一行级改动。
- **修复状态**：✅ 已修复（2026-08-03）：importSession 在 Factory 构建前倒序定位最后一条 type=10 记录并 setSuggestions，复用 Factory 既有会话级 suggestions 写入通道；wk-module-ai 离线编译通过（工作区未提交）。注：实现中确认 suggestions 实为会话级字段（非记录级），与 AnswerRecordInfoVo 结构一致
- 备注：本项经两位审查员分歧后代码级裁决确认为真实问题（完整性审查初判"闭环"有误，已修正）。

### P1-5｜PC 端 suggestions 不落库，刷新即丢（违反 PC/移动端同步规则）
- **位置**：`wk-train-center-ui/src/views/web/ai/components/AiAssistant/shared/chatSession.js:708-744`（syncToBackend type===10 分支 payload 无 suggestions）；`conversation/domain/historyContext.js:144-186`（mapOneRecord 无 suggestions 映射）

- **修复**：type===10 分支补 `payload.suggestions`；历史加载处补会话级 suggestions 回填。改动量小。
- **修复状态**：✅ 已修复（2026-08-03）：chatSession.js syncToBackend type===10 分支补 payload.suggestions（数组，对齐 List<String>）；historyContext.js 新增 attachSessionSuggestions 回填（倒序定位最后一条 AI 消息），loadHistoryDetail 透传 res.data.suggestions；ESLint 无新增问题（工作区未提交）。注：mobile 端历史加载同样未回填 suggestions，属后续同步事项，本次未越界改动

### P1-6｜试题导出行为三重变化，需业务公告 + 定向回归
