## 二、拆分原则（验证可行）

### 2.1 拆分模式

按职责单一原则拆为 3 类文件：

1. **`XxxMain.vue`**（< 200 行）：组件入口，组合子组件
2. **`XxxPart.vue`**（< 250 行）：单一职责的子组件
3. **`xxxHelpers.ts`**（< 200 行）：纯函数工具（可独立单测）
4. **`types.ts`**（< 50 行）：TS 类型定义

### 2.2 Vue3 特色保留

- `<script setup lang="ts">`：类型安全
- `defineProps<{ ... }>()`：编译时类型检查
- `defineEmits<{ (e: 'xxx', val: T): void }>()`：类型化事件
- `computed()` / `ref()` / `reactive()`：Composition API
- `markRaw()` 用于纯展示图标（避免不必要的响应式包装）

### 2.3 基本逻辑一致性

- ✅ 拆分前后 props/emits 接口完全相同
- ✅ 拆分前后 CSS 类名完全保留（不引入视觉差异）
- ✅ 拆分前后辅助函数行为完全一致
- ✅ 拆分前后 emits 触发时机与参数完全一致

## 五、拆分工作方法论（可复用）

### 步骤

1. **扫描**：用 `scripts/scan-large-components.cjs` 列出 > 500 行组件
2. **识别职责**：阅读文件，识别 2-4 个独立职责
3. **提取 helpers**：把纯函数提取到 `xxxHelpers.ts`（便于单测）
4. **提取类型**：把所有 interface 提取到 `types.ts`
5. **创建子组件**：每个职责创建一个 `.vue` 子组件
6. **重写主入口**：保留 props/emits，组合子组件
7. **验证**：每次拆分后必须通过 typecheck + build

### 拆分模板代码

```typescript
// types.ts - 集中类型定义
export interface XxxItem { id: string; name: string }

// xxxHelpers.ts - 纯函数工具
export function formatXxx(item: XxxItem): string { ... }

// XxxPart.vue - 单一职责子组件
defineProps<{ item: XxxItem }>()
defineEmits<{ (e: 'select', id: string): void }>()

// XxxMain.vue - 主入口（薄）
<XxxPart v-for="item in items" :item="item" @select="handleSelect" />
```
