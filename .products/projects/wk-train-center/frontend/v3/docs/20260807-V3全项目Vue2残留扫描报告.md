## 五、V3 团队的整体迁移策略

根据实际扫描结果，V3 团队的迁移策略可总结为：

### 5.1 主动重写策略（90%+ 模块）

V3 团队**没有**采用"v2 copy → 改 Vue3 语法"的传统迁移路径，而是：
1. **保留核心功能**：所有用户高频功能完整保留
2. **重写为 Vue3 标准**：全部使用 `<script setup lang="ts">` + Composition API
3. **改进 API 风格**：`postAction` → `post<T>()`、`this.$message` → `ElMessage`
4. **统一图标**：`el-icon-*` 字符串 → `<Plus />` 等 icon 组件
5. **类型化增强**：JSDoc → 完整 TypeScript 类型定义

### 5.2 内联优先策略（特殊模块）

对于 composables 工具类（如 admin/course 的 5 个 composables），V3 团队选择了：
- **优先内联**：把工具函数直接写在组件中（如 `DirList.vue` 内联 useDirectoryOps 逻辑）
- **再考虑抽象**：在需要复用时再抽取为独立 composable

本次 Batch C 创建了 5 个独立 .ts composables 作为"标准库"存在，V3 团队可按需重构组件引用。
