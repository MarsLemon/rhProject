## 1. 概述

### 1.1 背景

V3 迁移在 2026-08-07 收尾：① V2 语法残留 0 处（228 文件）；② API 层迁移 ~95%；③ 业务功能发现 61 文件 V3 比 V2 旧。

但此前工作（Batch A-J）仅解决了"V2 残留"和"语法迁移"，未同步 V2 业务增量更新。`20260807-BatchJ-V2V3差异迁移报告` 仅迁 1/7 高优文件即停。

本次计划目标：将这 61 个业务功能差异文件按依赖顺序分批迁移到 V3。

### 1.2 目标

1. V3 业务功能与 V2 同步（业务能力上对齐）
2. 每批结束保证 `typecheck` + `build` 0 error
3. 保持 V3 已有的 Vue3 模式（不重写）

### 1.3 范围

**在范围内**：61 个 V3 落后 V2 的文件（已排除 1 个已迁文件 `UserCourseFileList.vue`）

**在范围外**：
- ❌ `web/plan/*`（已确认不做）
- ❌ 重写为 Vue3 模式（V3 已 Vue3 化，无须重写）
- ❌ 引入新依赖
- ❌ 修与本次迁移无关的 lint / type 警告

### 1.4 角色与上游约束

## 4. 批次执行标准流程

```
对每个批次 Bx：

[1] 读目标文件清单（V3 当前内容）
[2] 用 scripts/diff-v2-v3.cjs 重跑得到本批实际差异
    （或人工 diff 补全）
[3] 逐文件评估：V3 主动重构 or 真落后
    ├ 真落后 → 增量迁移
    └ 主动重构 → 标记 "无需追赶"，记录在报告中
[4] 修改 + 增量迁移 + TypeScript 适配
[5] npm run typecheck ─→ 必须 0 error
[6] npm run build ─→ 必须 0 error
[7] 产出本批报告 documents/<日期>-Batch<X>-<模块>.md
[8] 用户验收，进下一批
```

## 5. 关键技术约束

### 5.1 V2→V3 模式映射（参考 vue2-to-vue3-component-migration skill）

| V2 模式 | V3 等价 |
|--------|--------|
| `this.$confirm` | `ElMessageBox.confirm` |
| `this.$message.success/error` | `ElMessage.success/error` |
| `Vue.observable({})` | `reactive({})` |
| `process.env.VUE_APP_BASE_API` | `import.meta.env.VITE_APP_BASE_API` |
| `::v-deep` / `>>>` | `:deep(...)` |
| `slot="reference"` / `slot="footer"` | `<template #reference>` / `<template #footer>` |
| `marked.parse(text)` | `marked.parse(text, { async: false })` |
| `import ElementUI` | `import { ElMessage, ElMessageBox } from 'element-plus'` |
| `this.$nextTick` | `import { nextTick } from 'vue'` |

### 5.2 增量迁移原则

- 只动差异点，**不重写整个文件**
- 保留 V3 已有的 `defineProps / defineEmits / <script setup lang="ts">` 结构
- 任何 try/catch 边界不改
- 第三方依赖签名变更时按 V3 当前命名规范

### 5.3 自动声明文件

`src/components.d.ts` 由 `vite-plugin-components` 在 dev / build 时自动重生成，**不手工改**。如有差异，构建会自动收敛。

### 5.4 CSS / SCSS 文件

- SCSS / CSS 文件的差异多为变量、mixin、媒体查询
- 直接用 V2 内容覆盖 V3 是安全的（语法兼容）
- 唯一例外：`:deep()` / `>>>` 写法差异需要保留 V3 现有规范
