## 三、修正后的具体步骤

### ✅ Step 1: Grep 验证 + Store Actions 清单 (P0, 10 分钟)

#### 1.1 提取 affected files

```bash
grep -oP '"vue2_path":\s*"[^"]+[^"]+"' vue2-v3-migration-audit.json \
  | grep -A1 'vuex_not_migrated' \
  | head -200 \
  | cut -d'"' -f4 | sort -u > temp/vuex_affected_files.txt
```

**预期**: 27 个文件路径列表

#### 1.2 提取 Vuex actions

```bash
jq '.severity_breakdown.p1_logic_deviation[]
    | select(.issues[].type=="vuex_not_migrated")
    | .issues[]
    | select(.type=="vuex_not_migrated")
    | .vuexActions' vue2-v3-migration-audit.json \
    | tr -d '[],"' \
    | sort -u > temp/vuex_actions.txt
```

**预期**: 44 个 action 名称

#### 1.3 Grep 7 个 Pinia stores 的 actions

```bash
cd wk-train-center-ui-v3/src/stores/modules/

for store in ai app knowledge permission settings tagsView user; do
  echo "=== $store.ts ==="
  grep -E "async\s+\w+\(" "$store.ts" | sed 's/.*async //' | cut -d'(' -f1
done > temp/pinia_store_actions.txt
```

**产出**:
- `temp/vuex_affected_files.txt` (27 行)
- `temp/vuex_actions.txt` (44 行)
- `temp/pinia_store_actions.txt` (7 个 store 的 action 列表)

**时间**: ~10 分钟

#### 比对逻辑:

1. 对于每个 Vuex action (如 `user/fetchMsg`):
   - 提取 module (`user`) 和 action name (`fetchMsg`)
   - 查找对应 Pinia store (`stores/modules/user.ts`)
   - 检查是否有同名 action
   - 记录结果

2. 分类标准:
   | Status | 含义 | 示例 |
   |--------|------|------|
   | ✅ | 完全等价 | Vuex `user/fetchMsg` → Pinia `user.fetchMsg` |
   | 🟡 | 改名重构 | Vuex `knowledge/createCourse` → Pinia `knowledge.createCourseFromFiles` |
   | ❌ | 未迁移 | Vuex `exam/startExam` → Pinia 无此 action |

### ✅ Step 3: 逐文件深度比对 (P1, 80 分钟)

对 27 个文件的每一个进行详细比对:

#### 3.1 v2 code 分析

```javascript
// App.vue
import { getToken } from '@/utils/auth'
export default {
  created() {
    this.$store.dispatch('user/fetchMsg')
    this.fetchMsgOnce()
  },
  methods: {
    fetchMsgOnce() {
      if (getToken()) {
        this.$store.dispatch('user/fetchMsg')
      }
    }
  }
}
```

**提取信息**:
- Vuex module: `user`
- Actions used: `fetchMsg`
- Methods using it: `fetchMsgOnce`

#### 3.2 v3 code 分析

```typescript
// App.vue
import { useUserStore } from '@/stores/modules/user'
const userStore = useUserStore()
onMounted(async () => {
  if (userStore.hasToken) {
    await userStore.fetchMsg()
  }
})
```

**提取信息**:
- Pinia store: `useUserStore`
- Actions called: `fetchMsg`
- Methods calling it: inline in onMounted

#### 3.3 比对判定

| 情况 | 判定 | 说明 |
|------|------|------|
| v2/v3都调用了相同的 action | ✅ 等价 | 功能一致，只是实现方式变了 |
| v3 没有调用该 action | ❌ 缺失 | 可能需要补全 |
| v3 调用的是改名后的 action | 🟡 重构 | 功能相同但接口变了 |
| v3 完全没用 store | 🟢 新实现 | 可能重新设计了逻辑 |

**时间**: ~80 分钟 (27 文件 × ~3 分钟/文件)
