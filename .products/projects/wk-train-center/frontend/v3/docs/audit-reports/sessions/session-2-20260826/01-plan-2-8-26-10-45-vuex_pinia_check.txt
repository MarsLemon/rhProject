## 三、本轮具体步骤

### 🎯 B-2 任务 - Vuex→Pinia 迁移检查 (P0 优先级)

#### Step 1: 提取 vuex_not_migrated 条目

从 `vue2-v3-migration-audit.json` 中提取所有:
```json
{
  "type": "vuex_not_migrated",
  "vuexActions": ["user/fetchMsg", "course/...", ...]
}
```

预计数量: ~80 个 actions

#### Step 2: 建立 Vuex action 到 Pinia store 的映射表

**v2 Vuex structure**:
```javascript
// store/modules/user.js
export default {
  state: { ... },
  mutations: { ... },
  actions: { fetchMsg, ... }
}
```

**v3 Pinia structure**:
```typescript
// stores/modules/user.ts
export const useUserStore = defineStore('user', {
  state: () => ({ ... }),
  actions: { async fetchMsg() { ... } }
})
```

#### Step 3: 逐 file 验证

对每个有 vuex_not_migrated 的文件:
1. 提取其引用的 Vuex module 和 actions
2. 检查对应 Pinia store 是否有同名 action
3. 分类标记:
   - ✅ 已迁移 (action 存在且等价)
   - ❌ 未迁移 (action 不存在)
   - 🟡 重构 (action 改名或合并)

#### Step 4: 输出完整清单

| Vue2 文件 | Vuex Module | Action | v3 Pinia Store | Status | Evidence |
|---------|------------|--------|---------------|--------|----------|
| App.vue | user | fetchMsg | stores/modules/user.ts | ❌ 未迁移 | store 无此 action |
| CourseList.vue | course | fetchList | stores/modules/course.ts | ✅ 已迁移 | store.actionFetchList 存在 |

### 🔜 B-3 任务 - branch_count_mismatch 深度分析 (P1 优先级)

#### Step 1: 筛选 Top 50 差异最大的文件

从报告中提取 condition branch count 差异 > 50% 的文件:
```json
{
  "type": "branch_count_mismatch",
  "description": "Vue2 (6) vs Vue3 (12)",
  "severity": "high"
}
```

#### Step 2: 人工逐分支比对

对 Top 50 文件中的每个条件分支:
- v2: `if (this.role === 'admin')`
- v3: `if (role.value === 'admin' || role.value === 'editor')`

判断:
- ✅ 等价重构 (功能一致，写法不同)
- ❌ 业务变更 ( intentionally changed)
- ⚠️ 可能漏迁移 (需要人工确认)

#### Step 3: 输出详细对比表

| Vue2 文件 | Branch # | v2 条件 | v3 条件 | 判定 | 说明 |
|---------|---------|-------|-------|------|------|
| ExamForm.vue | 1 | if (score < 60) | if (score.value < 60) | ✅ 等价 | ref 包装 |
| ExamForm.vue | 3 | if (isOverdue && isAdmin) | if (isOverdue.value || isAdmin.value) | ⚠️ 需人工 | 逻辑可能变化 |

#### Step 4: 统计最终报告

| 判定类型 | 数量 | 占比 |
|---------|------|------|
| ✅ 等价重构 | ~200 | 80% |
| ❌ 业务变更 | ~40 | 16% |
| ⚠️ 需人工 | ~10 | 4% |

### 🔜 可选任务 - AST 能力提升 (长期优化)

#### Step 1: 支持 mixin/composable 读取

扩展 `logic-extractor.js`:
- 读取 `.vue` 文件的 `<script>`部分
- 解析 `mixins`、`extends`、`setup()`引用
- 递归提取外部 JS 文件中的 axios 调用

#### Step 2: 支持 API 模块追踪

从 `@/api/xxx` import 反向查找:
- 定位 API 模块文件
- 提取其中所有 axios 调用
- 构建完整的 API 调用链图

#### Step 3: 降低动态 URL 误报

识别常见模式:
- URL 拼接：`'/api/users/' + id`
- 参数化：`axios.get('/api/users', { params })`
- 常量定义：`const BASE_URL = '/api'; axios.get(BASE_URL + '/users')`
