## 详细审查

### ✅ 计划方向正确

- 从 JSON 提取 vuex_not_migrated 条目
- 对比 v3 Pinia stores/modules
- 分类标记 ✅已迁 / ❌未迁 / 🟡未使用
- 三步流程合理

### ❌ 实测工作量与计划不符

| 项 | 计划估 | JSON 实测 | 偏差 |
|---|---|---|---|
| 受影响文件 | ~80 | **27** | -66% |
| Vuex actions | ~80 | **44** | -45% |
| 预计耗时 | 2-3h | **1-1.5h**(估) | 砍半 |

### ✅ v3 Pinia store 现状(已存在)

`wk-train-center-ui-v3/src/stores/modules/`:
- ai.ts / app.ts / knowledge.ts / permission.ts / settings.ts / tagsView.ts / user.ts

**7 个 store 已落地**,对应 v2 Vuex modules(`app / user / settings / tagsView / knowledge / permission`)。多数 Vuex actions 应该已在 Pinia store 中。

### ⚠️ 高风险点

**报告说"未迁移"≠ 实际未迁移**

vuex_not_migrated 检测逻辑(`logic-extractor.js`):
- 检测 v2 文件里有 `dispatch('storeName/actionName')` → 标记
- v3 文件里没找到 `useStore().actionName()` 调用 → 报"未迁移"

但 v3 可能:
- 用 `import { useXxxStore }` 直接调用 action(工具识别不到)
- action 已迁到不同 store 文件(跨 store 重组)

**建议先做一轮 grep 验证**(实测迁移率),再分类。

### 2. B-2 前置:快速迁移率验证(~15 分钟)

```bash
# 对每个 action 名,grep v3 stores/modules 找匹配
for action in <44 actions>; do
  v3_has=$(grep -r "$action" wk-train-center-ui-v3/src/stores/)
  echo "$action: ${v3_has:+已迁}${v3_has:-未迁}"
done
```

输出可能:
- 真未迁(需补 Pinia action):预期 ~5-10 个
- 误报(已迁但工具漏识别):预期 ~30+
- 工具能力问题:值得修 logic-extractor

### 3. B-2 阶段分两段
