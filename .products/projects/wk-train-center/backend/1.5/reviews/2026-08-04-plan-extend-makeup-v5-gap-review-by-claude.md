## 二、v5 新漏洞 + 漏判(3 条)

### N14. [P0] 第八部分实施顺序章节未更新
- **位置**: 第八部分 line 405-422
- **现状**: 批次1 写"1.1 DDL + 1.2 DDL + 1.3 DDL",但新结构是 1.1 DDL + 1.2 DML + 1.3 DDL(el_paper)+ 1.4 DDL(el_exam_record)
- **问题**:
  - 批次1 引用"1.2 DDL"实际是新 1.3(el_paper)→ 含义错
  - 完全漏掉 1.2 DML(数据迁移)
- **风险**: 实施者按批次1 顺序跑 SQL,先跑 DDL 后跑 DML → 但 DML 依赖 DDL 的新字段 → 如果实施者按字面顺序跑可能执行失败
- **修**: 批次1 改为"1.1 DDL + 1.2 DML + 1.3 DDL(el_paper)+ 1.4 DDL(el_exam_record)"

### N15. [P1] 1.2 DML 迁移 SQL 假设旧 extend_count 字段存在
- **位置**: 1.2 DML line 35
- **现状**: `UPDATE el_plan_user SET extend_deadline_count = extend_count WHERE extend_count > 0;`
- **问题**:
  - 第一部分标题才改为"DDL + DML" → 暗示新装环境跑这套 SQL
  - 但 DML 假设旧环境已有 `extend_count` 字段
  - 新装环境跑 1.1 DDL 后 `extend_count` 不存在 → 1.2 DML 报 unknown column
- **修**: 1.2 DML 加 IF 保护:
  ```sql
  -- 仅当旧 extend_count 字段存在时执行
  SET @sql = (SELECT IF(
    (SELECT COUNT(*) FROM information_schema.COLUMNS
     WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'el_plan_user' AND COLUMN_NAME = 'extend_count') > 0,
    'UPDATE el_plan_user SET extend_deadline_count = extend_count WHERE extend_count > 0',
    'SELECT 1'
  ));
  PREPARE stmt FROM @sql;
  EXECUTE stmt;
  DEALLOCATE PREPARE stmt;
  ```
  或更简单:把 DML 标注"仅升级环境跑,新装环境跳过"

### N16. [P2] 14.1 声称"全部修复"但未量化剩余风险
- **位置**: 14.4 line 674 "真实修复率:95%(38/40 彻底修复)"
- **问题**: 38/40 没说哪 2 条没修,也没说修复质量
