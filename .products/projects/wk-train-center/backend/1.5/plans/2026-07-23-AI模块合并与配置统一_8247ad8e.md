## 一、后端:统一配置接口(在 wk-module-ai 新增)

### 1.1 新增 `AiConfigController`

路径:`wk-module-ai/.../ai/controller/AiConfigController.java`

**读取接口** `POST /api/wk/ai/config/all`
- 内部循环调 `CfgPropService.detail()` 读 4 行:
  - type=ai, provider=bailian
  - type=voice, provider=bailian
  - type=vision, provider=bailian
  - type=bailian_kb, provider=default
- 再调 `CfgPropService.listByType("ai_prompt")` 拿 prompt 列表
- 聚合返回:`{ chat:{}, voice:{}, vision:{}, kb:{}, prompts:[...] }`

**保存接口** `POST /api/wk/ai/config/save-all`
- 接收完整 JSON
- 委托给新增的 `cfgPropService.saveAll(rows)`(**不在 controller 标事务,见 §1.2**)
- 单独调 `cfgPropService.listByType("ai_prompt")` 拿 prompt 列表一并写入

### 1.2 impl 层新增 `saveAll(List<CfgPropDTO> rows)` — 整批原子

文件:`yf-ability/.../config/service/impl/CfgPropServiceImpl.java`

```java
@Transactional(rollbackFor = Exception.class)
@CacheEvict(value = "sys:config", allEntries = true)  // ★ 只在最外层清一次
@Override
public void saveAll(List<CfgPropDTO> rows) {
    for (CfgPropDTO row : rows) {
        this.save(row);  // 同 bean 内调用,Spring 6.1 自代理生效
    }
}
```

**为什么放 impl 而不是 controller**:
- 控制器 @Transactional + 循环调 service.save() 是经典自调用陷阱(代理不生效,事务失效)
- 放 impl 后 `this.save()` 走代理,整批真正原子

**缓存优化**:
- 单行 `save()` 自带 `@CacheEvict(allEntries=true)`(见 CfgPropServiceImpl.java:50)
- 批量场景下不优化就是 O(N²) 缓存清除
- `saveAll` 走最外层一次全清,内层每次 save 也会清但被外层清的语义覆盖,可接受

### 1.3 `mergeConfigSecrets` catch 改 throw — 拒绝静默失败

文件:`CfgPropServiceImpl.java:180-183`

```java
} catch (Exception e) {
    log.warn("merge config secrets failed, type={}", type, e);
    return newJson;  // ❌ 反模式:命中 2026-07-14 哑巴功能经验
}

// 改为:
} catch (Exception e) {
    throw new ServiceException("配置合并失败(type=" + type + "): " + e.getMessage(), e);

```

**为什么改**:前端传 `dashscopeApiKey=""` 想保留旧值,JSON 解析异常时静默回退会把空串写入,语音能力直接挂(线上事故风险)。

## 四、后端:老 CfgPropController 收口

### 4.1 `save()` 方法 — ai 4 行 + ai_prompt 改 308 重定向

文件:`yf-ability/.../config/controller/CfgPropController.java`

```java
private static final Set<String> AI_TYPES = Set.of(
    "ai", "voice", "vision", "bailian_kb", "ai_prompt"
);

@RequiresPermissions(value = {"sys:config:prop", "notify:config:save"}, logical = Logical.OR)
@LogInject(title = "保存配置信息", logType = LogType.SYSTEM)
@Operation(summary = "添加或修改")
@PostMapping("/save")
public ResponseEntity<?> save(@RequestBody CfgPropDTO reqDTO) {
    if (AI_TYPES.contains(reqDTO.getType())) {
        // ★ 强制走新入口,避免双入口 race
        return ResponseEntity.status(HttpStatus.PERMANENT_REDIRECT)  // 308
                .header(HttpHeaders.LOCATION, "/api/wk/ai/config/save-all")
                .build();
    }
    baseService.save(reqDTO);
    return ResponseEntity.ok(ApiRest.ok());
}
```

**308 而不是 410 的原因**:
- 308 浏览器/Postman/curl 自动跟,老师傅点老页面保存 = 自动跳新接口 = 零感知
- 1 周共存期,日志看 308 命中率 0 后再考虑删
- 410 Gone 太狠,会让老运维脚本直接挂

### 4.2 `change()` 方法 — **不动**

**自检结论**:`change()` 被多域共享,不能改:

| 前端文件 | 用 change 做什么 |
|---|---|
| [wk-train-center-ui/src/api/sys/config/prop.js:34](../wk-train-center-ui/src/api/sys/config/prop.js#L34) | 切换 AI 服务商 |
| [wk-train-center-ui-v3/src/api/admin/sys/config.ts:71](../wk-train-center-ui-v3/src/api/admin/sys/config.ts#L71) | 切换上传方案(OSS/COS/Local) |
| [UploadConfig.vue:32](../wk-train-center-ui-v3/src/views/admin/sys/config/components/UploadConfig/UploadConfig.vue#L32) | v3 上传配置切换 provider |

**全切 = 把上传/通知/人脸/直播的切换也误伤,这些不在合并范围**。

## 五、前端:AiConfig.vue 改单次请求

文件:`wk-train-center-ui-v3/src/views/admin/sys/config/components/AiConfig.vue`(或同等路径)

### 5.1 读取

**前**:`fetchData()` 5 次 `fetchDetail/listByType` 并发
**后**:`fetchData()` 1 次 `POST /api/wk/ai/config/all`

### 5.2 保存

**前**:`submitForm()` 7 次 `saveData` 串行
**后**:`submitForm()` 1 次 `POST /api/wk/ai/config/save-all`

### 5.3 新增 API 函数

文件:`src/api/ai/config.js`(新建)

```js
export function fetchAiConfigAll() {
    return post('/api/wk/ai/config/all')
}

export function saveAiConfigAll(data) {
    return post('/api/wk/ai/config/save-all', data)
}
```

**注意自检**:落地前必看 `AiConfig.vue` 当前 `fetchData` 的 `await` 写法:
- 如果是 `Promise.all` 并发 → 改单次请求**首屏延迟反而增加**(批量 save-all 内部串行循环)
- 如果是 `await this.fetchDetail()` 串行 → 改单次请求**首屏明显加快**

按当前实际写法决定有没有真实节省延迟。
