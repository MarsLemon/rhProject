# 对话片段导出/导入功能实施计划

## 概述
在 **答疑助手（answer 模式，仅答疑，不含陪练）** 实现对话片段的导出/导入：
- **导出**：顶部菜单「导出对话」→ 当前消息列表进入多选模式（每组"用户+AI"成对勾选）→ 底部工具条（全选 / 已选 N 组 / 取消 / 导出JSON）→ 前端构建 JSON → 下载文件 `share-<会话概述>.json`。纯前端，无后端调用。
- **导入**：顶部菜单「导入对话」→ 选本地 `.json` → 前端解析+校验 → 调**新增后端接口** `POST /api/wk/answer/student/import`（一次原子新建 askId + 写全部记录）→ 返回新记录**主键 id** → 前端 `loadHistoryDetail(id)` 加载为当前会话，可续聊。
- 保真度：正文 + 引用(citations) + 附件(fileList)，**不含思考(thoughts)**。

目标工程：前端 `e:\rhProject\wk-train-center-ui`（Vue 2，端口 4212）；后端 `e:\rhProject\wk-train-center-service`（`wk-module-ai`）。

## 数据契约（导出/导入唯一格式）
文件名：`share-<overview>.json`（overview 清洗非法字符 `\ / : * ? " < > |` 与控制符，截断 ≤80 字；空则回退 `share-<timestamp>`）。

```json
{
  "version": 1,
  "source": "wk-train-center-answer",
  "overview": "会话概述",
  "exportedAt": "2026-07-22T13:20:00.000Z",
  "records": [
    { "type": 20, "chatHistory": "用户提问", "fileList": [ { "url": "...", "dashScopeFileId": "...", "name": "..." } ] },
    { "type": 10, "chatHistory": "AI 回答", "citations": "<JSON 字符串>", "fileList": [ "https://.../a.pdf" ] }
  ]
}
```
- `type`：20=用户、10=AI。
- **records 形状与后端 `AnswerRecordAddDto`/`AnswerHistoryRecordVo` 对齐**，导入时 records 可几乎直接转发给后端 import DTO：
  - `citations`：**JSON 字符串**（仅 type=10）。导出时把前端 `msg.citations`（数组）`JSON.stringify` 成字符串；导入回放时现有 `mapRecordListToMessages` 会 `JSON.parse` 回数组。
  - `fileList`：用户记录取前端 `msg.file_list`（对象数组 `{url,dashScopeFileId,name}`）；AI 记录取 `msg.fileList`（URL 字符串数组）。后端 `FileItem` 反序列化器同时兼容字符串与对象两种形态。
  - **不写 `thoughts` 字段**（导出显式剔除；导入不传）。

### B4. Service 实现：`application/impl/AnswerRecordAppOpServiceImpl.java`（关键：单次插入 + 返回主键 id）
```java
@Override
@Transactional
public String importSession(AnswerImportCommand command) {
    // 与现有 aiAskId() 完全一致的生成规则
    String askId = System.currentTimeMillis() + UserUtils.getUserId();
    AnswerRecord domain = null;
    for (AnswerRecordCommand rec : command.getRecords()) {
        rec.setAskId(askId);
        if (domain == null) {
            domain = answerRecordFactory.create(rec);   // 首条：初始化会话，index=askId+1
        } else {
            answerRecordFactory.edit(domain, rec);       // 其余：追加，index=askId+(size+1)
        }
    }
    if (domain == null) {
        throw new ServiceException("导入内容为空");
    }
    if (StringUtils.isNotBlank(command.getOverview())) {
        domain.setOverview(command.getOverview());       // 用分享概述覆盖，历史列表标题友好
    }
    answerRecordRepository.save(domain);                 // ★ 仅一次 insert（内存构建全部记录后落库）
    // ★ 关键修正：getRecord 按主键 id 查询（selectById），必须返回主键 id 而非 askId
    return answerRecordRepository.findByAskId(askId).getId();
}
```
- 说明：`AnswerRecordConverter.toDomain` 会 set `id`（已核实），故 `findByAskId` 能拿到 MyBatis-Plus 生成的主键。为省一次查询也可在 `AnswerRecordRepository` 加 `saveAndReturnId`，但为最小改动采用 `findByAskId`（导入低频，成本可忽略）。
- 需 import：`com.yf.system.modules.user.UserUtils`、`org.apache.commons.lang3.StringUtils`、`com.yf.base.api.exception.ServiceException`。

### B5. Controller 新增端点：`controller/WkAnswerStudentController.java`
```java
@Operation(summary = "答疑记录-导入对话")
@LogInject(title = "答疑记录-导入对话", logType = LogType.ANSWER)
@PostMapping("/import")
public RespVo<String> importSession(@RequestBody @Valid AnswerImportDto dto) {
    return ResponseUtils.success(answerRecordAppOpService.importSession(dto.toImportCommand()));
}
```
- 返回值 = 新会话**主键 id**（前端用于 `loadHistoryDetail`）。

### B6. 后端防御
- `records` `@NotEmpty`；service 内校验 record 数量上限（如 ≤ 2000）、`type ∈ {10,20}`，越界抛 `ServiceException`。
- `@Transactional` 保证任一步失败整体回滚，不残留半场会话。

## 交互流程
- **导出**：菜单「导出对话」→ 进多选（复制/撤回等隐藏，导航仍在）→ 勾选若干组/全选 → 底部「导出JSON」→ 下载 `share-<overview>.json` → 自动退出多选。
- **导入**：菜单「导入对话」→ 选 `.json` → 解析校验（失败给中文提示，不请求后端）→ 调 `/import` → 返回主键 id → `loadHistoryDetail(id)` 渲染为当前会话 → 刷新历史列表 → 可直接续聊；导入的消息带后端 `index`，撤回/重试/删除均正常。

## 边界与校验
- 欢迎语（`isWelcome`）与 system 记录不参与分组/导出。
- AI 仍在 `loading` 的组不导出；`isLoading` 时禁止进入多选与导入。
- overview 为空 → 文件名回退 `share-<timestamp>`。
- 导入错误分类（中文）：JSON 解析失败→"文件格式错误，无法解析"；version/source 不符→"不是有效的对话分享文件"；records 空→"文件中没有可导入的对话"；超限→"文件过大或对话条数过多"；网络/后端失败→"导入失败，请重试"。
- 附件为 OSS 预签名 URL，**隔久导入可能失效**（已知限制，本期不处理，保留 name 展示）。

## 测试计划
- **后端**：`importSession` 用例——N 条 records 仅一次 `save`；返回非空主键 id；index 依次为 `askId+1..N`；user 记录 fileList、ai 记录 citations 保留、无 thoughts；overview 被覆盖；空 records 抛异常回滚。Swagger 手测 `POST /import`。
- **前端**：导出选中→文件名与 schema 正确、无 thoughts；导入回环→新会话出现、正文/引用/附件正确渲染、续聊/撤回/重试可用；非特性路径（发送/接收/历史/删除/切模式）无回归；各类非法文件给出中文错误；答疑显示入口、陪练不显示。

## 被否决的方案（Rejected Alternatives）
- **分享ID + 新建 `el_answer_share` 表**（原始需求）：用户改为本地 JSON 文件方案，更简单、无需新表与分享ID查询/生成，故否决。
- **前端循环 `addRecord` 做云端同步**：N 次请求、非原子，写一半断网残留半场会话；改用单次原子 `/import` 接口。
- **导入后仅用本地 JSON 直接渲染（不回后端拉取）**：本地记录缺后端生成的 `index`，会导致撤回/重试/删除失效；改为返回主键 id 后 `loadHistoryDetail(id)` 拿权威 index。
- **导入返回 askId + 新增按 askId 查询端点**：多一个端点；改为返回既有主键 id、复用现成 `getRecord(id)`/`loadHistoryDetail`。
- **抽独立 selection composable + MessageGroupCheckbox 组件（Plan A）**：对小特性属过度脚手架；仅保留 A 的纯 `conversationTransfer.js`，选择状态放 View + 展示型工具条。
- **Web Worker 异步解析 + 超大容量上限（Plan B）**：YAGNI；文件很小，同步解析 + 合理大小/条数上限即可。
- **完整保真（含 thoughts）**：按用户决策只留 正文+引用+附件，剔除 thoughts。

## 假设（已与用户确认）
- 仅答疑模式；陪练不做。
- 成对分组：用户消息 + 紧随 AI 回复；欢迎语/system 排除。
- 附件按原样存 `url+dashScopeFileId+name`；预签名 URL 过期为已知限制。
- 导入永远新建会话，不追加当前会话。
- 文件名 `share-<overview>.json`，overview 清洗、空则回退时间戳。
- 保真度：正文 + 引用 + 附件，不含思考。
